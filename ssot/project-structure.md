# 專案資料夾結構

> 正本。版本 v2，2026-09-19。這份結構本身是方法論的一環：它規定想法從發散到發布的每一段放在哪裡、為什麼要有那個位置。`AGENTS.md` 的四階段表是本檔的操作用複本。

## 一句話

想法從發散到發布走四段，每段一個固定位置；交付之後有三處回存，讓下一次更短。判斷一個東西該放哪裡，看它處在哪一段，不看它有多長。

## 四段

| 段 | 位置 | 放什麼 | 為什麼存在 | 誰動手 | 發布 |
|---|---|---|---|---|---|
| 發散 | 對話，以及 `工作紀錄.md` 的「待消化」區 | 亂聊出來、還沒決定收不收的想法，標明誰提出、日期、候選用法 | agent 提出的東西不能直接進正式文件；要有一個地方讓它先放著，人看過再決定 | agent 寫，人決定 | 否 |
| 整理 | `kb/` | 找到的資料的摘要，一個來源或一個主題一檔，四段：來源、重點、洞見、課程用途（候選）。分 `arguments/` 與 `tools/` | 別人的東西與自己的洞見要分得開、找得回來源；還沒決定用不用，所以不排結構 | agent 寫 | 否，但在 git |
| 收斂 | `drafts/` | 依題目從 kb 與待消化區抽出來排成結構的東西：課程地圖、教案、逐頁稿 | 結構會大改、會有棄案，需要一個可以反覆重排而不影響對外成品的地方 | agent 起草，人挑選 | 否 |
| 交付 | `lessons/`、`index.qmd`、`setup.qmd`、`tools.qmd`、`slides/` | 學員看得到的成品 | 對外的東西代表自己，要人審過才出去；發現問題退回 drafts 改結構，不在成品上硬修 | agent 寫，人審過才發布 | 是 |

## 三處回存

| 位置 | 放什麼 | 為什麼存在 |
|---|---|---|
| `ssot/` | 已定案、多處要引用的核心概念，一個概念一檔，定義與圖同檔，附版本紀錄 | 同一個概念散在教案、文章、投影片、工具索引各自改寫，就會出現多個版本；要有唯一正本，改動先改這裡再同步 |
| `AGENTS.md`、`skills/` | 定案後的工作方式與標準，每次對話都讀；`skills/` 一個主題一檔 | 用過確定有效的標準寫下來，下一次那一格就變短；這是專案累積能力的地方 |
| `工作紀錄.md` | 各次決定與理由、待消化區、已消化並整合 | 決定為什麼這樣做，人會忘、新對話不知道；寫下來下次才接得上 |

另有 `assets/`：教材圖片，因為要附來源與授權，所以獨立一處；`tmp/`：試跑與收斂前的版本，不進 git。

## 升格與回存規則

- 待消化 → kb：資料讀過、有來源、能寫出洞見，就成一檔。
- kb → drafts：使用者指定題目後才抽；drafts 每份註明取自哪些 kb 檔與待消化項。
- drafts → lessons 與 slides：只在使用者說「整合」或「發布」之後；agent 不自行升格。
- 反向也成立：成品發現問題，退回 drafts 改結構。
- 回存：概念定案進 ssot 並記版本；標準用過有效進 skills 或 AGENTS.md；決定與理由進工作紀錄。已發布週次用當時版本，不回改。

## 跨週素材索引與取用循環

`kb/index.md` 是人與 agent 在課程討論前先讀的快速入口，跨週列出素材主題、可能用途、狀態及來源連結。它屬於整理階段的導航，完整內容仍放在 KB 主題筆記或工作紀錄。

每週從索引選材進 draft，採用後更新去向；收斂時把超出範圍與新長出的想法補回來源筆記及索引。已採用只代表有使用位置，仍可重用；暫不採用須保留理由。每週 draft 不另維護完整素材庫，也不再以「某週移出素材」作共用入口。
