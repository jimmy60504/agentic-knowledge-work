## 本週目的

學員理解 AI 放大器需要領域知識與駕馭 agent 的能力相輔相成，並從自己想完成的工作，辨認目前需要補足的部分：知識與方向、具體操作，或另一個檢查角度。

用熟悉主題或既有簡報，練習請 agent 補充想法、完成一段操作與協助檢查，再由自己選擇和修改。從原有流程逐步嘗試，讓學員找到學習 agent 的方向；本週不要求建立完整專案流程。

## 課程流程

| 段落 | 內容 |
|---|---|
| 前半段 | 以這份簡報的修改過程開場：自己的七步、向 agent 提問、外部參考與差異、人的取捨；再說明交付責任、AI 放大器與學習切入點 |
| 實作一 | 用 AI 拓寬視野，選擇有用的補充，再收斂成重點 |
| 實作二 | 請 agent 快速排版，和原稿或第一版比較，做一次具體修改 |
| 收尾 | 分享值得留下的改善與下一次想試的工作 |

時間以兩段體驗為重，前半段只提供開始操作需要的理解。總時數與分鐘配置尚未定；必要時縮減頁數，保留親自選擇與修改的機會。

## 材料與成果

- 選熟悉主題或可以提供給工具的既有簡報；講師準備公開或虛構材料備援，學員不需額外準備作業。
- 舊稿另存副本。先保留原有重點，再保存收斂後內容與幾頁排版成果，供前後比較。
- 開始前說明訓練用途設定、雲端傳輸與 GitHub push；關閉訓練不等於不上雲，private repo 仍在雲端。設定細節依實際工具與帳號於備課時確認。
- 測試不用機密、個資與未公開公務資料。不要求 push、完整知識庫、逐階段落檔或課後作業。
- 產出以可編輯 PPTX 為主，準備預覽與成品備援，避免工具問題耗去整段體驗。

## 本週完成的判斷

學員有比較原有與 agent 協助後的內容，有親自選擇建議、檢查並修改成果，能指出值得保留與仍需改善之處。不要求一定採納 agent 建議，也不以整份簡報完成或視覺華麗程度評分。

## 完整講稿與操作

以下是目前第二週的完整講稿。前半段建立入口與安全邊界，後半段直接進入兩個體驗；兩段都保留在本檔，避免講稿與教案分散成不同版本。

### 前半段：從這份簡報的修改過程開始

#### 一、先看這份簡報怎麼修改

上次介紹了 agent 是什麼。這次想讓大家知道，可以從哪裡開始學。我先拿準備這份簡報時的一段討論給大家看。

我先寫了幾頁想講的內容，其中一頁是做簡報的流程。我原本列的是：

**訂主題 → 找資料 → 整理大綱 → 尋找素材 → 文案收斂 → 排版 → 最終確認**。

這是我先整理出來的版本。接著我問 agent：「你有一些其他的人整理出來的流程嗎？」它查了 Duarte、Garr Reynolds 和 TEDx 的資料，再把那些做法和我的流程放在一起比較。

講師展示：原七步、這句實際提問、三個來源名稱。來源連結保留在講者備註，見 `kb/presentation-process-before-and-after.md`。本例的查找與摘要由 agent 完成，不描述成講師已讀完三本書或親自完成全部查證。

#### 二、比較後，多了哪些考量

比較後，有幾個地方變得更明確。我原本寫「訂主題」，可以再問：給誰聽、希望他聽完理解什麼？我寫「文案收斂」，還可以分清楚：是在決定主要想說什麼，還是在縮短文字？最後的「確認」，也可以具體到真的講一次，檢查時間和順序。

| 我原本寫的 | Agent 比較後提出的補充 |
|---|---|
| 訂主題 | 明列對象與目的，作為取捨內容的依據 |
| 文案收斂 | 先釐清核心訊息，再處理文字與逐頁內容 |
| 最終確認 | 實際試講，再依時間、理解難點與回饋修改 |

Agent 也提出了一個重新組合的版本：

**確認對象與目的 → 蒐集資料、發展想法 → 收斂核心訊息 → 組織大綱與逐頁內容 → 製作圖文與排版 → 試講、檢查與修改**。

這是它綜合參考資料提出的建議。比較的用途，是讓我看清楚原來哪些事情沒有明列出來，再決定對這堂課有沒有幫助。原稿留著，才看得出它增加了什麼、改動了什麼。

講師備課：目前六步仍為候選。這一頁可以展示「提出了什麼」，不要預先說成已全部採納或已經試講驗證。三組差異不表示講師原先不會考慮受眾或試講，只比較原稿明列的內容。

#### 三、我也會把 agent 的建議改回課程需要的方向

這份講稿還有另一段修改。Agent 原本把用途整理成「學新事、減少重複工作、補足非強項」。我看了以後，覺得還需要把背後的關係講出來。

我想帶的是 AI 放大器：領域知識與駕馭 agent 的能力需要相輔相成。先看自己想完成什麼，再看缺的是做事情的方向、具體操作，還是需要另一個人幫忙檢查，學習目標才比較明確。

所以我補上這個想法，請 agent 再調整大綱與講稿。現在就把這個關係放在前面，後面才帶到學新東西、補短板、減少重複操作和找盲點的情境。

講師展示：原本三種用途 → 使用者補充「領域知識與駕馭 agent 能力相輔相成」→ 目前「從自身需要切入」的大綱。這是已發生的改稿，可以說明自己的理由；與上一頁六步候選的狀態分開。

#### 四、交付出去的東西是要負責的

用幾句話就產出一整份簡報，看起來很厲害。但產出的內容是不是你要講的、資料是否正確、聽眾能不能理解，仍然需要自己確認。最後交付出去的人，要能說明裡面的內容與取捨。

如果一次產生太多內容，自己還沒看完，就很難知道哪裡需要修改。可以從原有工作流程中挑一小段，先請 agent 試做，檢查合不合用，再決定要不要交給它更多工作。

例如原本就知道要講什麼，可以先請它整理版面或潤飾語句。每次只改一段，比較原稿與修改版，看看是否保留原意、是否真的更清楚。方向不適合就說明原因，重點被改掉就請它修回來。

講師帶法：回指剛才兩次修改，說明自己需要讀懂建議、決定哪些符合教學目的；這裡不再另開一份範例。

#### 五、AI 是放大器：領域知識與駕馭 agent 的能力

剛才這段備課，就是一個例子：我提供原本的做法與這堂課想教的觀念，agent 協助找參考、比較差異、整理講稿，再由我繼續看和改。

可以用「領域知識 × 駕馭 agent 的能力」來理解 AI 放大器。領域知識幫助我們知道這件事要往哪個方向做、什麼結果才算合用；駕馭 agent 的能力，則幫助我們提供材料、說明要求，並透過嘗試與回饋，把想法做出來。

這兩邊需要相輔相成。很懂自己的工作，但還不熟悉 agent，可以從熟悉流程中的一段開始練習交辦與修改。很熟悉工具，卻不了解正在處理的主題，就需要補充知識，才比較能判斷產出是否適用。

也不必等到完全學會才開始使用。想學新的事情，可以請 agent 協助閱讀、解釋與製作範例，自己再透過查閱、試用與比較累積理解。學到的知識讓要求更清楚，實作中的問題也會讓自己知道接下來要補什麼。

講師帶法：沿用投影片的乘號表達兩種能力互相配合，不將它解釋成計分公式。這裡的「Agent 能力」指人運用與駕馭 agent 的能力。

#### 六、從自己需要補足的地方開始

先看這次想完成什麼，再看自己缺的是哪一部分，就比較知道要怎麼學、請 agent 幫什麼忙。

**缺知識與方向。** 想學新東西，或還不知道該怎麼做，可以從一本書、一份資料或討論開始，請 agent 協助解釋、整理可能的做法，再做一個小範例來試。遇到不理解的地方繼續查閱與提問，讓自己逐漸知道為什麼要這樣做。

**缺把事情做出來的具體操作。** 已經知道要什麼，但不熟悉操作，可以請 agent 協助製作，再根據成果提出修改。例如懂得要表達的內容，卻不擅長排版與視覺設計，就先試著把這個短板補到工作需要的程度。原本會做、但需要反覆操作的工作，例如格式整理與語句潤飾，也可以從既有流程中挑出來試。

**需要有人一起檢查。** 已有想法或成果，可以請 agent 換一個角度閱讀，找出遺漏、表達不清楚或需要再確認的地方。它提出的疑問是供自己檢查的線索，最後仍要回到材料與工作目的，決定要不要修改。

同一件工作可能同時需要這幾種協助，也可能在實作後才發現真正缺的是另一部分。今天先選一個具體需要，試過之後再調整。

講師帶法：口頭收集「目前想完成什麼、哪一部分需要協助」。學新事、補足短板、減少重複操作與找人看盲點都可以，不要求學員固定選一類，也不另加問卷或回家作業。

#### 七、換你試一段自己的工作

現在換成大家自己的題目。可以用熟悉的主題或既有簡報，先留下原本想講的內容，再挑一個需要協助的地方。

就像我先列自己的流程，再問 agent 有沒有其他做法，你也可以先寫下想法，請它補充角度、提供參考或找盲點。接著選出值得留下的內容，安排幾頁的順序，再請它協助排版。

今天不要求走完全部流程。先做一小段，打開成果比較、提出修改，最後說得出自己留下什麼、為什麼留下，就有具體收穫。

講師帶法：回到原七步或經講師確認的修訂流程，指出兩段實作的位置。細部流程不必再講一次；案例中的查閱、比較與改稿可供學員選用，無須每個人都搜尋三套方法。

#### 開始實作前：先選好練習資料

今天請用公開材料、虛構內容，或確認適合提供給所用工具的材料。不要拿機密、個資或未公開的公務資料來測試。拿自己的舊簡報練習前，也要看過內頁、備註和附件；拿不準就改用講師提供的範例。

使用的工具若有「將內容用於模型訓練」設定，先依該工具與帳號的說明關閉。關閉訓練用途，不表示資料沒有傳到雲端，也不等於所有資料都可以提供給它。

另外，push 到 GitHub 就是把資料上傳到雲端，private repository 也一樣。本次體驗只需要在練習資料夾保存檔案，不要求 push。不要把「存在專案裡」當成不會外傳的保證。

講師備課：確認本次實際使用工具的資料控制選項與適用範圍，準備設定畫面；若帳號沒有相同開關，依官方說明解釋，不套用別家設定。這段只講本次練習必要的注意事項。

### 後半段：發想與收斂、快速排版

#### 課前準備與成果

- 講師準備本次備課的原七步、提問、比較結果與用途段落修改，作為內容示範；另備同一材料的排版前後版本與備援成品。尚未製作的視覺成果須另外準備，不描述為本次討論已完成。
- 學員選熟悉的主題，或確認適合交給工具的既有簡報。不要求課前製作或課後補作；沒帶材料就用講師範例。
- 舊簡報另存練習副本，保留原稿供比較。只有主題的人，先記下原有三到五個重點，作為比較基準。
- 在同一個練習資料夾保存材料與成果即可，不要求建立完整知識庫、`AGENTS.md`、逐階段 Markdown 或 GitHub repo。
- 目標：完成一份自己選過的重點清單，以及幾頁排版成果；能指出一個值得保留的改善和一個仍需修正之處。

#### 接到實作

講師口述：

剛才看過我如何拿原稿請 agent 補充，再依教學目的修改。現在換成自己的題目；沒有帶材料的人，就沿用講師範例。先說明這次想完成什麼、目前哪一部分需要協助，再留下原本想講的內容，待會才看得出 agent 補了什麼、自己改了什麼。

#### 實作一：讓 AI 拓寬視野，再自己收斂

##### 1. 先留下自己的起點

講師口述：

先用幾句話說明主題、聽眾和這次目的，再寫下你原本準備講的幾個重點。也試著說一句：「這次最希望聽眾記住的是＿＿。」還說不清楚也沒關係，可以在討論後修改。有舊簡報的人，可以直接用其中一小段，不必一次處理整份。

##### 2. 請 AI 補充可能的角度

參考說法，學員可自行改寫：

> 這是我熟悉的主題與原有內容，對象是＿＿，希望他們聽完能＿＿。先不要做投影片。請提出三個我可能漏掉、但值得考慮的角度，說明各自對聽眾有什麼幫助；資訊不足時可以先問我。

講師口述：

如果還不知道要怎麼開始，可以先請它給兩種講法，再指出哪裡適合、哪裡不適合。對一個具體版本提出意見，通常比較容易開始討論。

先看看它補了什麼。有些可能有用，有些可能太遠或只是換句話說。遇到沒聽過的事實，先標記待查，不要因為它講得完整就直接採用。

##### 3. 人選擇，再請 AI 整理

請學員選一項有用的補充，指出一項不採用的建議及原因；若都不適合，可以說明原因再請它重試，不要求一定採納。

> 保留＿＿，因為＿＿；刪除＿＿，因為＿＿。把我原本的內容和選中的補充整理成幾個重點，暫時不要新增事實，待查的地方另列。

講師巡視重點：有沒有出現新角度？學員能否說明自己的取捨？若只是不斷要更多建議，協助他先選一個方向，不延伸成完整思考框架課。

##### 4. 把重點排成聽眾能理解的順序

講師口述：

重點選好了，還要看先講哪個、後講哪個。想像聽眾第一次接觸這件事：他需要先知道什麼，才聽得懂下一段？不必套固定模板，先把這幾個重點排順。

> 依這次聽眾與目的，把選好的重點排成三到五頁的順序。每頁用一句話說明要傳達的重點，列出需要的材料，先不要排版，也不要補造資料。

把這幾句話連起來讀一次。若有重複、跳太快或少了解釋，就先調整內容。也可以請 agent 協助找出盲點：

> 請站在這次聽眾的角度，指出這份大綱最需要確認的兩個地方，說明你根據哪段內容提出疑問。先不要重寫，缺少資訊就標記出來。

再由自己判斷它的疑問是否成立，決定補充、修改或保留原稿。這份簡短順序可以直接留在對話或重點清單中，不另加一份作業。

##### 5. 看一次前後差異

對照原有重點與收斂後的內容，簡短回答：「多想到什麼？留下什麼？為什麼？」保存選好的版本，接到第二個實作。

#### 實作二：請 agent 快速排版，再比較增強之處

##### 1. 講師示範：把已決定的內容做成簡報

講師口述：

現在內容與順序已經選過了，我們請 agent 做成幾頁簡報。這一段可以試它的排版與視覺能力，看看哪些原本需要自己慢慢調整的工作，可以先交給它。

今天以可編輯的 PowerPoint 檔為目標，方便自己或同事接著修改。打開後也試著選取文字、改一個字；副檔名是 PPTX，不代表每頁內容都能分別編輯。若整頁只是一張圖片，就要確認這種形式是否符合後續修改需求。

示範同一內容的原版與 agent 版，指出具體改善，例如文字比較容易讀、重點比較明顯、版面比較一致。也指出一處不適合的設計或內容改動，當場要求修正。

##### 2. 學員操作：兩種起點，共用同一個練習

有舊簡報：挑三到五頁，用上一段選好的內容改善原稿；能直接修改就修改副本，工具無法直接編輯時，以相同內容重做這幾頁。

只有熟悉主題：用第一個實作的重點做成三到五頁。比較基準是自己的原有內容與第一版成果，不必事先另做簡報。

參考說法：

> 請用這份我已選好的內容與頁面順序，製作／改善三到五頁可編輯的 PowerPoint 簡報，給＿＿閱讀或聆聽。請讓重點清楚、文字易讀、版面一致。保留既有事實、數字和主張；缺資料的地方列出來，不要自行補造。另存新檔，保留原稿。

不強制特定風格、配圖或生圖。想試漂亮版面的人可以補一個風格方向，仍以內容能否清楚表達來決定採用。

##### 3. 打開成果，做一次具體修改

講師口述：

先打開檔案看，不要只看 agent 說它已經完成。找一頁你覺得還能改善的地方，直接說明問題，例如字太小、重點不明顯，或圖雖然漂亮卻和內容無關。

參考說法：

> 第二頁的重點不夠明顯，請讓＿＿更突出，減少次要文字。保留原本的數字與意思，另存修改版。

也可以請 agent 依這次目的，指出一頁最需要改善的地方與理由，再自己打開檔案確認。若工具無法看到實際版面，它的意見只能作為內容檢查參考。

檢查時先看三件事：這頁要傳達的重點看得出來嗎？文字和圖是否有助於理解？原本的事實、數字與意思有沒有改變？現場遇到問題，再示範刪除重複文字、放大主要訊息或調整排列。

如果問題是內容不對或先後順序不清楚，就回到重點清單修改，再請 agent 更新投影片。保留原稿與選好的內容，才能分辨問題出在哪一步。

學員至少比較一次修改前後，自己決定哪一版更合用。工具若不能輸出 PPTX，先完成一頁可預覽的版面，配合講師備援檔理解差異，不把整段課變成安裝與除錯。

##### 4. 對照成果：哪些值得留下

| 比較面向 | 課堂觀察 |
|---|---|
| 想法 | 有沒有補到原本忽略的角度？哪些建議被自己刪除？ |
| 表達 | 原有重點是否更容易理解？有沒有被改掉意思？ |
| 排版 | 哪個地方比較清楚或好看？哪個地方仍需修改？ |
| 瑣事 | 哪一段工作可以交給 agent 先做？自己還需要檢查什麼？ |

不要求量化省時、不做免費與付費競賽，也不要求整份翻新。容許原版更好；能說明不採用的理由，也是本次比較的成果。

#### 收尾

講師口述：

就像開頭這份教材的例子，先留下自己的想法，才看得出 agent 補了什麼、自己又改了什麼。

今天從原有流程中挑了幾個地方：請 agent 補充想法、協助排版，也請它提供檢查意見。自己的領域知識用在取捨與確認；和 agent 來回交辦、比較與修改，則是在練習駕馭它的能力。

回頭看，今天從已有材料開始，經過整理與選擇，再做成可以給別人看的成果。這就是收集、整理、蒸餾、表達的一次小練習；第四週會再練習如何發想、整理材料，以及檢查摘要有沒有漏掉重要意思。

請簡短分享一個你會留下的改善，以及下一次想完成的事情：接下來需要補知識、練習請 agent 做出成果，還是需要另一個檢查角度？檔案留在自己的練習資料夾，今天的練習到這裡完成。

講師現場收集後續需求，不加回家作業。第四週再用這次經驗深入討論發想、提問與收斂。
