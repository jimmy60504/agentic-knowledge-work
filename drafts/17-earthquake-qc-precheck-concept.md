# 送出前初步 QC：初步構想與訪談問題

> 2026-09-29 第一版。供 2026-09-30 訪談使用：先提出一版構想作為討論對象，再依訪談結果修正。構想由 agent 依使用者說明起草，尚未經使用者與維護端確認。
> 取自：[現況整理](16-earthquake-qc-current-state.md)（流程、檢查項目、處理方式分類）、[[cwa-earthquake-db-qc-training]]、使用者 2026-09-29 口頭說明。

## 要解決的問題

上游承辦為了達到件數，常有步驟未執行或僅抽選部分事件處理。維護端檢查出問題只能退件，雙方反覆往返。目標是讓大部分問題在上游送出之前就被發現或修正，維護端收到的資料只剩少數需要討論的事件。

## 初步構想

### 使用情境

上游承辦完成一日的定位之後、送交維護端之前，對當日目錄執行一次程式。程式修正能以規則處理的問題，嘗試重跑定位，並列出必須回到 UI 處理的事件。承辦處理完人工項目再送出，檢查報告隨資料一併交給維護端。

### 處理流程

```text
當日 P file
  → 1. 掃描：讀取 header 與相位，執行全部檢查
  → 2. 自動修正：時間進位、遠震欄位字元等規則明確的項目
  → 3. 自動重跑：誤差或規模異常者，以不同模型重新定位並比較
  → 4. 判定去向：入庫、不入庫、刪除、需詢問
  → 5. 產出報告：已修正、已重跑、待人工處理、去向統計
  → 承辦處理人工項目 → 重新執行 → 人工項目清零後送出
```

### 設計原則

- **只修改規則明確的欄位。** 程式修改 header 與重跑定位，不修改 picking；需要看波形的問題一律列為人工項目。
- **每一筆修改都留紀錄。** 保留原始檔，報告列出修改前後的內容，維護端可以據此抽查。
- **門檻集中在一份設定檔。** 重複事件秒差、殘差、誤差等數值目前各處不一致，由維護端訂定一次，上下游共用同一份。
- **沿用現有檢查邏輯。** 以 CheckPfile 的檢查項目為基礎，補上現行程式無法檢查的項目（權重、測站檔、GAP），不另起一套標準。

### 分階段導入

| 階段 | 範圍 | 目的 |
|---|---|---|
| 一 | 只掃描與產出報告，不修改任何檔案 | 以過去的退件資料驗證，確認程式抓得到維護端實際退件的問題 |
| 二 | 加入自動修正 | 時間進位等規則明確的項目不再退件 |
| 三 | 加入自動重跑 | 視定位程式能否命令列執行而定 |
| 四 | 設為送出條件 | 人工項目未清零不得送出，需上下游與主管同意 |

第一階段不修改資料，風險最低，也最容易取得雙方同意，適合作為明天提出的起點。

## 訪談問題

依對象分組；「必問」為決定構想能否成立的問題，其餘視時間補問。

### 維護端：退件現況

1. 【必問】最常退件的原因是哪些？能否依頻率排出前五項？
2. 【必問】是否有退件紀錄（信件、表單、清單）可以提供，作為第一階段驗證的資料？
3. 一日大約收到多少事件、退件多少？一次退件到重新送回需要多久？
4. 目前哪一個檢查步驟最花時間？
5. 哪些問題即使上游做了，維護端仍一定要重看？

### 維護端：規則與權限

6. 【必問】重複事件的秒差門檻以哪一個為準（投影片 1 秒、紙本 2 秒、Samp.exe 3 秒）？
7. 殘差門檻是 3 秒一律適用，或 P 波 3 秒、S 波 5 秒？
8. ERH、ERZ 大於 2 時，是否一律改用 1D 模型重跑？
9. 【必問】哪些 header 修正可以由程式直接修改，哪些必須由人確認？
10. 有感遠震由誰決定是否入庫？
11. 紙本檢查清單的來源與維護者為何？是否有更新的版本？

### 技術可行性

12. 【必問】定位程式（HYPO）能否以命令列批次執行？可以切換哪些速度模型？
13. 【必問】P file 格式是否有規格文件？各欄位的位置與意義由誰說明？
14. CheckPfile、CheckPfileII 的原始碼在哪裡？目前由誰維護？
15. 上游承辦的電腦能否安裝或執行新程式（Python、執行檔）？有無網路磁碟權限限制？
16. HYPO3D.sta 等測站檔的正本在哪裡？新站加入的流程為何？

### 上游承辦（若能同時訪談）

17. 【必問】一日的處理流程為何？哪些步驟最常省略，原因是什麼？
18. 件數如何計算？退件是否影響件數？
19. 如果送出前多一道檢查，能接受多少時間？
20. 報告以什麼形式呈現最方便（文字檔、表格、網頁）？

### 導入

21. 由誰決定是否把檢查設為送出條件？
22. 是否能選一位承辦、一個月的資料先行試用？

## 訪談時可以索取的材料

- 退件紀錄或退件原因清單
- 一日份的 P file 範例（含一筆正常、一筆被退件的事件）
- P file 格式說明、CheckPfile 原始碼
- 最新版的紙本檢查清單
