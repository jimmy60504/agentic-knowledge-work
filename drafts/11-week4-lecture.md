## 建議講述順序

1. 先從共同工作環境看見 agent 能參與哪些工作。
2. 把思考外部化，透過中間產物逐步對齊。
3. 用 A、B 與中間節點 C 拆解工作，接回三個迴圈。
4. 查找、閱讀與摘要各做什麼，人的洞見如何加入。
5. 指派角色、交代目的與標準，將明確規則交給程式。
6. 材料、草稿、決定與標準如何保存，讓下一次接得上。
7. 看一個完整小案例，再帶入後半工作坊的自己的任務。

這是目前的編輯建議，可從實際試講再刪併；下文為講述內容，不另外維護另一份候選講稿。

## 一、共同工作環境：文件櫃、工作台與加工工具

使用者提出「文件櫃、工作台、機器人、加工機器」的比喻。文件櫃保存可取用的材料，工作台放正在修改的草稿；agent 能依指派查找、討論、記錄與製作，讓人共同查看結果。前提是工具具備相應的存取與操作能力。

| 環境 | 在這門課的例子 | 為什麼需要它 |
|---|---|---|
| 文件櫃 | `kb/` 的來源、筆記、洞見 | 材料找得回，也能補充與更正 |
| 工作台 | `drafts/` 的論述、提案與逐頁稿 | 可以先看結構、討論與重排，還不用完成最後版面 |
| 機器人 | agent | 查閱材料、提出建議、記錄決定、起草與操作工具 |
| 加工機器 | 程式、既有軟體、執行環境或設備 | 依明確規則製作與重複執行 |
| 成品 | 文件、簡報、報表、程式或實體 | 交給實際使用者檢查是否合用 |

先用一件熟悉工作介紹每個位置的用途，等需要找回材料、重排草稿或保存決定時再指出檔案位置。避免一開始巡覽整個課程 repo，要求學員先理解所有資料夾。

人工、數位化與 Agent 化可以作為短入口：人親手做；人操作軟體或程式做；人與 agent 討論，由 agent 操作工具做。三種方式並存。有些問題靠資料整理、一般軟體或流程調整就能解決；agent 也可以協助數位化，不需要把它們說成嚴格先後階梯。

來源：使用者 09-18 討論；原 12 號稿「共同工作環境」「人工、數位化到 Agent 化」。

## 二、思考外部化：先有可以共同檢查的內容

人心裡的想法轉成文字、口述與畫面時，會經過選擇與組織。對方看到的是表達，無法直接取得完整意圖。協作因此需要一個可共同查看的中間產物：一段整理、有依據的文稿、比較表，或對問題的具體描述。

請 agent 先把目前理解整理出來，人才能指出哪裡漏掉、誤解或還沒決定。人的想法也會隨新材料與試做結果改變；回饋是在共同釐清，而不只是把模型拉回第一次說法。

保留使用者要求記下的表述：

> LLM 學過大量人類語言與互動模式。我們可以借用溝通、管理與教練的方法，把意圖、背景、分工與標準說清楚，提高它產生合適回應的機率。

這是本課程的方法論說法。互動像同事或教練，不代表模型具有人的動機或責任；是否對齊意圖與事實是否正確，也要分開檢查。「思考沒有直接訓練資料」等更深的解釋保留在備選，需進一步釐清，不先當作完整認知理論講授。

可用的短示範：先說零散想法，請 agent 寫成一段，再現場指出一個偏移，補充理由並重寫。讓學員看到修改前後的差異。

## 三、每次轉換重新對齊，找出必要的中間節點

使用者提出的拆解方式是：先看目前有什麼 A、希望得到什麼 B。若不能清楚交代或可靠完成 A 到 B 的轉換，就找中間節點 C，把工作拆成 A → C → B。

C 可以是資料、決定、規格、草稿或試作結果。它要補上一個具體缺口，讓下一步有依據，也讓人能檢查。加入多少層，取決於任務、人的理解與工具能力；同一層也可以反覆修改，不必把每輪對話都變成新流程。

| 目前卡住的地方 | 候選中間產物 | 人檢查什麼 |
|---|---|---|
| 想法直接變簡報，主張與順序還不清楚 | 結構化文稿 | 背景、目的、主張與依據是否成立 |
| 文稿轉成簡報，還不知道每頁的用途 | 逐頁稿或 ghost deck | 邏輯能否連讀、證據與口述放在哪裡 |
| 多份材料直接變報告，版本與數字有衝突 | 來源與差異比較表 | 哪份有效、哪裡待確認，能否往下寫 |

前兩列延續第二週，第三列是課程自擬的遷移例子，尚未試跑。

找 C 的來源也不只一種：問 AI、請 AI 搜尋、自己讀資料或請教他人、觀察現場與親自試做。新發現可能連 A、B 的定義都改變。先把 agent 的建議當候選，再用材料或試作確認。

### 接回三圈，保留已定概念

三圈定義與圖以 [ssot v3](../ssot/three-loops.md) 為準：形成論述、建立架構、調整風格；分別以文稿、逐頁稿、成品供人檢查。第二週發布版本第一圈仍稱「確認方向」，講課只需簡短交代改名理由。

使用者已定要講來歷：需求分析、建立架構與實作，幫助說明為什麼有不同產物。用一句話帶過方法來源即可，不另外做兩門課的平行對照。

每次轉換要重看用途與標準。成品出現內容問題時，回到適當的草稿層修正；不是每次都在版面上重做。提前檢查是為減少後續返工，不宣稱所有情況下退回前一層必然更貴。

「累積是否另成一圈」「回存要放在哪裡」「通用任務是否需要不同層數」仍是討論題。本稿先把累積與回存作為貫穿工作的方法，不自行改寫三圈正本。

## 四、查找、閱讀與蒸餾：讓材料參與思考

使用者指出，AI 可以依問題找材料，但人往往讀了原文，才形成原先沒想到的新問題。自己的經驗與關注，會改變讀者如何組合材料。找到來源、摘要原文與形成洞見，是可以分開檢查的工作。

| 內容類型 | 保存時說清楚什麼 |
|---|---|
| 原始材料與作者主張 | 來源在哪裡、原文支持什麼、有哪些條件 |
| 對作者意圖的推論 | 根據哪些線索推論、哪些部分不確定 |
| 自己的新洞見 | 加入了什麼經驗與判斷、與原文有何關聯 |
| Agent 的提案 | 哪些仍是候選，需要用什麼驗證 |

蒸餾是依用途取捨，不只是縮短字數。摘要可能漏掉研究方法、限制或關鍵例外；當結論要拿來支持決定、摘要與理解衝突，或想深入找新問題時，回讀相關原文。這與 [孫以瀚講座筆記](../kb/arguments/sun-ai-assisted-research-writing-lecture.md) 中對摘要與深讀的區分相呼應；只取此觀點，不帶入整套學倫或工具建議。

### 候選短練習：用自己的長文檢查摘要

先保留自己想表達的見解與支持段落，請 AI 閱讀並摘要，對照遺漏或偏移。接著請它指出段落依據，再補充問題引導重讀，保留各輪結果。

分清哪些觀點文本原本就支持、哪些是後來提示才加入。如果必須直接說出答案才能被抓到，也可回看自己的文章是否表達清楚。練習觀察特定材料上的解讀，不推論模型已讀到作者內在思考。這是使用者提出、agent 展開的候選，尚未試跑。

延伸候選是帶目的讀書：先理解相關方法、預測改動效果，再請 agent 做可比較範例，人實際觀察並說明取捨。它可補上判斷力如何累積，但不增加指定購書、課前閱讀或課後作業。

## 五、請教與交辦：用具體角色讓分工可見

請教時帶著自己的經驗和意見，讓 agent 提供不同方向與關鍵字；交辦時說明目的、希望完成的結果、重要限制與檢查標準，保留具體做法的選擇空間。Why、what、how 是提醒，不必變成固定填空提示。

| 此時需要的角色 | 可以請它做什麼 |
|---|---|
| 討論者 | 拓展選項、比較方向、指出還沒想清楚的部分 |
| 資料蒐集與整理者 | 查找來源、取用舊筆記、整理關聯與差異 |
| 記錄者 | 留下共識、決定理由、未定事項與下一步 |
| 審查者 | 找反例、缺乏依據的假設與讀者可能誤解的地方 |
| 起草者 | 把零散想法整理成可閱讀、可修改的草稿 |
| 工具製作者與操作員 | 建立或修改程式、操作工具、檢查實際輸出 |

這些是工作角色，不要求多開六個 agent，也不保證換角色稱呼就會提高品質。審查建議仍要對照依據。使用者提出用「派」來提醒自己做主，可作互動說法；其教學效果尚未驗證。

原 12 號稿的「先讀現有材料、提供意見、拓展想法或試做」可合成一個隨手工具箱：先看現在缺什麼，再派相應工作。練習自然來回，不要求學員背一組長指令。

## 六、由 Agent 探索與製作，讓程式重複執行明確規則

保留使用者的分工想法：

> 讓 agent 去處理模糊不確定的東西，然後把明確規則收斂成程式碼讓他可以重複執行。

有些工作需要理解材料、提出選項與試做；確定規則後，可用程式或既有工具執行。例子是先確認逐頁稿，再用程式製作 PPTX；內容或版面出現問題，回到草稿與製作規則修改。

程式化可能減少重複生成與不必要變動，但仍有編寫、維護與執行成本。重建也依賴輸入、程式版本與環境。Agent 可以直接操作既有軟體，不需要為每項任務另寫程式。

「加工機器」還能延伸到螢幕、互動畫面、3D 模型與設備；本課先用文件成果講清楚分工，實體設備保留為選講。驗收要看實際成品，不以程式沒有報錯就認定工作完成。

## 七、保存材料、決定與標準，讓下次能接續

這是原本第四週要深入的知識管理主題。課程 repo 可當實例，但先問一件工作需要保存什麼，再介紹位置。完整結構以 [專案結構正本](../ssot/project-structure.md) 為準。

| 過程中需要留下什麼 | 本課採用的位置 | 要解決的問題 |
|---|---|---|
| 還沒採用的想法與問題 | 對話、工作紀錄待消化區 | 不讓未定想法混入成品 |
| 材料、來源與自己的洞見 | `kb/` | 找得回依據，分清原文與延伸 |
| 為本次任務組合的內容 | `drafts/` | 有一份可以反覆收斂的工作稿 |
| 人確認可交付的內容 | 正式文件與成品 | 使用者能拿去使用 |
| 多份內容共用的已定概念 | `ssot/` | 避免相同概念各自改成不同版本 |
| 確認有效的做法與標準 | `AGENTS.md`、`skills/` | 下次能依同一標準工作 |
| 為什麼採用、放棄或修改 | `工作紀錄.md` | 換次討論後仍能理解取捨 |

這些位置是本課的示範，不要求每位學員一開始複製全部資料夾。需要重用或遇到混淆時再增加結構；檔案命名也不能保證任何工具都自動讀取，要確認實際查閱。

Agent 可協助找舊材料、提出關聯、保存修正，但來源、分類、有效版本與適用條件仍需確認。整理不是越多越好；要能從檔案回到工作，並更正過時或錯誤內容。版本紀錄、可回退與交接是深化候選，先讓人看見保存的用途。

與演講 IMG_8356 的連結：既有知識可重用，新材料先比較、人審查，例外再探索；失敗條件也能留下。這提供知識累積的方向，不保證存檔後會自動產生創新。

## 八、把完整流程做成可看懂的小示範

本節是待試跑的示範候選，沿用備課或熟悉報告，不再講整段備課歷史。

1. 交代這次成果給誰用、手上有什麼，以及目前缺什麼。
2. 加入一份新材料，請 agent 找出與既有筆記的關係，保留來源。
3. 人指出一個不適用的建議，說明取捨，再請它記下理由。
4. 從材料形成一小段 draft，檢查主張與證據；需要時補一個中間產物。
5. 將一個有效標準回存，再換一個新需求，展示如何取用先前材料與決定。

每一步畫面只呈現當下需要看的材料、變動與結果，並說明這對報告、研究或交接有什麼幫助。重點是看到前面投入如何在後續派上用場，而非只看到整齊的資料夾。這次整理演講照片成兩份稿，也可當備用實例，但仍須先說清楚學員可套用的情境。

接到 11 點工作坊時，讓學員選一件自己的工作，運用前半的流程拆解、角色分工與保存方法。價值、成本、風險、五欄盤點與實作條件的完整操作引導只放在後半稿。
