## 引言：課程目的與貫穿案例

本週下午的工作坊，學員各自選一件工作，判斷 Agent 可以接手哪一段、是否值得嘗試。上午的兩小時為此準備。要判斷一段工作能否交出去，必須先知道 Agent 接到指示之後，中間經過哪些步驟，才產生一份投影片、一封信或一張表。因此上午先說明這個過程，再看其他組織的用法，最後把地震業務翻成同樣的語意，檢查兩邊能否對應。

以下用一個場景貫穿全部內容。每年年初，要把去年規模 5 以上、深度 40 公里以內的地震挑出來，逐件計算預警第一報的時效、震央誤差與規模誤差，分陸上與海域統計，做成表與分布圖，放進年報。手上有地震目錄、各事件的預警報次紀錄、去年的表。做這件事的人要決定哪些事件納入、多報次的事件取哪一報、異常的數字怎麼解釋；最後表要能重算，年報段落要過審。這件事有明確的起點與終點，中間有幾處需要查證、判斷與交接。每一段內容都回到這件事的某一步。

本週不討論中心應導入何種系統，也不主張哪個科的工作可以自動化。目的是把 Agent 的工作方式攤開，讓學員自行判斷手上的業務是否有一段值得嘗試。

## 一、Agent 的運作機制

把報告交給 Agent，很快就能得到一份看起來相當完整的成果，容易讓人以為它無所不能。要判斷它能做到哪一步，必須先了解它的工作方式。

模型本身只產生文字。產生的可能是一段回答，也可能是一段動作描述：一行指令、一段程式碼，或一個符合工具規格的呼叫，寫明工具名稱與參數。模型沒有操作滑鼠的能力，也不會因為寫出「寄信」二字就完成寄送。

使事情實際發生的是執行框架。執行框架預先接好可用的工具與執行規則，例如終端機、程式、API、瀏覽器與滑鼠。模型提出一個工具呼叫，執行框架檢查權限，交給對應的程式執行，再把結果送回模型。模型讀到結果之後決定下一步：繼續操作、請人確認，或交付成果。整個過程是一個循環：人提出目標，模型提出動作，工具執行，結果返回，模型再提出下一個動作。

以最小的例子說明。請 Agent 建立一個 Markdown 檔並寫入討論內容，需要四步。模型先決定檔案的位置、名稱與內容，必要時先呼叫工具查看目錄現況。接著模型產生 Markdown 文字，並提出「在此路徑建立檔案」的工具呼叫；至此仍只是文字與參數。然後執行框架把呼叫交給檔案工具或終端機，底層程式實際寫入磁碟。最後工具回傳結果，模型再讀取一次檔案，確認存在、內容正確、位置無誤。

因此單獨的模型可以寫出 Markdown 的內容，卻無法僅靠生成文字在電腦中建立檔案。寫入與回讀是執行框架提供工具之後，由模型與工具往返完成。若只是在對話框中顯示一段 Markdown，最後一步是介面顯示文字，並未產生檔案。

製作投影片走的是同一條路。模型先寫逐頁稿，再寫一支程式，執行框架執行程式產出 PPTX，再開啟檔案檢查。寫程式只是其中一種路徑；有些工具直接提供建立簡報的功能，模型便不必先寫程式。能走到哪一步，取決於當時接入的工具與授予的權限。

回到年度成效統計。Agent 讀取地震目錄與各事件的預警報次紀錄，使用的是讀取工具。逐件計算報時差、震央距離差與規模差，是寫一段程式並執行。產出統計表與分布圖，是執行程式並寫入檔案。草擬年報段落，是產生內容。送交承辦同仁審核，是詢問核准與傳送。每一步都可拆成三件事：模型提出動作，工具執行動作，結果得到驗證。這三件事分開看待，是後續所有判斷的基礎。

## 二、Agent 的介入方式

了解運作方式之後，下一個問題是 Agent 可以站在流程的哪個位置。同一件年度成效統計，Agent 可以用六種方式參與。

| 接手方式 | Agent 接手到哪裡 | 年度成效統計的例子 | 最後留下什麼 |
|---|---|---|---|
| 人向 Agent 請教 | 人在正式流程之外發問，Agent 回答後退出 | 同仁詢問時效與誤差的定義及往年慣例，取得建議後自行計算 | 可審查的建議 |
| Agent 完成一次性交付 | 以工具查找、寫檔、驗證，交出檔案後退出 | 產出去年的統計表、分布圖與逐事件 CSV | 可審查的檔案 |
| Agent 建置工具後退出 | 建置時產生程式或規則，之後由一般程式執行 | 寫好篩選事件與計算誤差的腳本，之後每年重跑 | 程式；運行時沒有 Agent |
| 固定節點呼叫一次模型 | 既有程式把輸入送給模型取回結果，依固定路徑進行 | 腳本把各事件的報次紀錄文字送去擷取第一報時間與規模，再交原流程計算 | 欄位；模型參與但不是 Agent |
| 流程節點呼叫 Agent | 事件到達時 Agent 查資料、選工具、迭代，交給下一節點或人 | 每次規模 5 以上事件結束後，Agent 取報次與地震報告，計算差異補一列，標出異常交承辦 | 改變流程狀態的產物 |
| Agent 協調跨節點工作 | 依回饋選擇下一步，跨系統查找、建立待辦、等候核准並追蹤 | 從逐事件補列、年底彙整、產圖表、寫年報段落、送審到依意見修改，由 Agent 串接 | 系統狀態改變與持續追蹤 |

讀這張表時，先把案例的五步標出：讀取、計算、確認、產出、保存。第一種方式只涉及讀取與計算的建議，而且在流程之外。第三種方式把篩選與計算寫成程式，之後每年執行，運行時沒有 Agent。第五種方式讓 Agent 站在每次事件結束後的節點，完成讀取與計算，補一列並標出異常，確認由人負責。第六種方式從讀取一路做到保存，在定稿之前停下等候核准。

有三點需要說明。

第一，六種方式不是由低到高的能力等級。第三種在建置時接手的工作很多，運行時卻完全沒有 Agent；第一種看似最簡單，卻可能每天使用。哪一種合適，取決於該段工作的性質，與編號無關。

第二，接手範圍與寫入權限是兩件事。第五種的節點 Agent 可以設為只讀取資料、只建立草稿，或經人核准後才寫入年度表。交出多少步驟，與允許改動什麼，須分別決定。

第三，「最後留下什麼」分三組。可審查的內容或檔案是一組，前四種大多屬於此類。改變外部系統或人的工作狀態是一組，補進年度表、送出審核都屬於此類。持續運行的服務是第三組，例如每次事件後自動補列。後兩組須另外確認權限、錯誤處理、紀錄與回復方式，因為它們改變的對象在 Agent 之外。

另有一處容易混淆。第四種有模型參與，但模型只在固定位置完成一件事，不能選擇工具，也不能決定下一步，這種情況不必稱為 Agent。中心預警管線裡的 P 波拾取與震度預測模型就是這一種：模型在管線的固定位置做一件事，前後都是程式。第三種寫好的程式若在執行時再次呼叫模型，便有模型參與流程，但是否構成 Agent，仍要看它能否選擇步驟。分類針對當下這件工作的實際執行方式，不針對產品。

## 三、從 A 到 B

知道 Agent 能站在哪裡之後，接下來是站進去之後如何進行。這一段說明一個方法，核心只有一件事：中間節點是什麼、如何找到、找到之後由誰負責。

### 先有可以共同檢查的內容

人心中的想法，轉成文字、口述或畫面時，都經過選擇與組織。對方看到的是表達，不是完整的意圖。人與人之間如此，人與 Agent 之間亦然。因此協作需要一個可以共同查看的中間產物：一段整理、一份有依據的文稿、一張比較表，或對問題的具體描述。

做法是先請 Agent 把它目前的理解整理出來，人再指出哪裡遺漏、哪裡誤解、哪裡尚未決定。這裡有一個觀念：

> LLM 學過大量人類語言與互動模式。我們可以借用溝通、管理與教練的方法，把意圖、背景、分工與標準說清楚，提高它產生合適回應的機率。

互動方式像同事或教練，不代表模型具有人的動機或責任。是否對齊意圖，與事實是否正確，是兩件須分開檢查的事。人的想法也會隨新材料與試做結果改變；回饋是在共同釐清，不只是把模型拉回第一次的說法。

課堂可安排一個三分鐘的示範：先提出幾個零散的想法，請 Agent 寫成一段；當場指出一處偏移，補上理由，請它重寫。學員看到修改前後的差異，便能理解中間產物的用處。

### 找出中間節點

先看目前有什麼，稱為 A；希望得到什麼，稱為 B。若 A 到 B 的轉換無法說清楚，或無法可靠完成，就找一個中間節點 C，把工作拆成 A 到 C，再 C 到 B。

C 可以是資料、決定、規格、草稿或試作結果。它的條件是補上一個具體的缺口，讓下一步有依據，也讓人能檢查。加幾層取決於任務、人的理解與工具能力；同一層可以反覆修改，不必每一輪對話都成為新的一層。

三個例子。想法直接變成簡報，主張與順序尚不清楚，C 是一份結構化的文稿，人檢查背景、目的、主張與依據是否成立。文稿要轉成簡報，尚不知每頁的用途，C 是逐頁稿，人檢查邏輯能否連讀、證據與口述放在哪裡。這兩個是第二週的內容，當時的三個迴圈就是三個 C：文稿、逐頁稿、成品。第三個例子是本週的案例：事件清單直接變成年度統計表，多報次與異常事件尚未處理，C 是一張逐事件差異表，附納入與排除的註記，人檢查多報次取哪一報、哪些事件該排除、數字能否重算。沒有這張差異表，年度的數字便無法追溯。

找 C 的來源不只一種。詢問 AI、請 AI 搜尋、自行閱讀資料、請教同事、到現場觀察、親自試做，都可以。新發現有時會改變 A 與 B 的定義。Agent 的建議先當作候選，再以材料或試做確認。成品出現內容問題時，回到適當的草稿層修正，不在版面上重做。

### 找到 C 之後由誰負責

有了 C，才有分工的問題。三個原則。

第一，同一個 Agent 在一件工作中輪流扮演幾種角色：討論者拓展選項，整理者查找來源，記錄者留下決定與理由，審查者尋找反例，起草者撰寫可修改的草稿，操作員執行程式並檢查輸出。請教時帶著自己的意見提問，讓它提供不同方向；交辦時說明目的、預期結果、限制與檢查標準，做法由它選擇。這些是角色，不要求開啟六個 Agent，更換稱呼也不保證品質提高。

第二，模糊的交給 Agent，明確的交給程式。原話如下：

> 讓 agent 去處理模糊不確定的東西，然後把明確規則收斂成程式碼讓他可以重複執行。

需要理解材料、提出選項、試做的工作，交給 Agent 探索；規則一旦確定，便收斂為程式或既有工具，可以反覆執行、結果穩定。本課程自身的例子是先由 Agent 把逐頁稿討論定案，再以一支程式將逐頁稿產成 PPTX；內容有問題改逐頁稿，版面有問題改程式，不在成品上手工修改。在案例中，篩選事件與計算誤差的規則確定之後寫成腳本每年重跑，哪些事件納入、異常如何解釋仍由人判斷。程式也有編寫與維護的成本；Agent 也可以直接操作既有軟體，不必每件事都寫程式。

第三，人核准哪一步須事先講定。判定與高影響的處置由有權責的人決定，Agent 列出依據、選項與疑點。這一條在介入方式一節已出現，在此是分工的一部分，在工作單上是「誰驗收」一欄。

## 四、其他組織如何以 Agent 協助工作

自方法回到業務，先看其他組織的做法。

學員講義的動詞對照表，一列一個工作動詞，後四欄寫明其他組織如何以 Agent 處理這類工作、Agent 具體做了什麼、中間留下什麼、人驗收什麼。這張表不是產品功能清單，也不列廠商名稱。目前一般的 Agent 大多具備聊天入口、工具呼叫、排程與檔案讀寫，這些用法並非任何產品專屬。

整張表留待下午查閱。上午挑四種說明拆法。

**第一版初稿。** 對應的工作是分析與報導。Agent 蒐集素材、寫程式或分析、形成可檢查的檔案：草稿、程式、測試紀錄。完成證據是檔案能開、能跑、數值可重算。人設定標準、執行測試、接受或退回。這一種正是年度成效統計的對應做法：統計表、分布圖與年報段落都是第一版初稿，數字能否重算是完成證據，承辦同仁決定接受或退回。

**跨來源整理成研究底稿。** 對應的工作是整理與分析。Agent 跨來源檢索、整理相互矛盾的資料、附來源起草、存回筆記。完成證據是每個主張可回到來源。人定義問題、檢查證據、決定結論。在案例中，事件清單來自地震目錄、報次來自預警紀錄、規則來自去年的表，三個來源對不上的地方就是要整理的底稿。

**例行詢問的答覆。** 對應的工作是解釋與回答。Agent 查詢知識庫、依個案回答、收集脈絡，無法回答的摘要後轉交。完成證據是對方得到答覆，或已交到承辦人。人驗收的是知識庫內容是否正確、例外與敏感情境如何處理、答覆是否抽查。

**定期監看與條件提醒。** 對應的工作是守視。Agent 定期檢查佇列、專案或外部資訊，比對變化，有變化才通知。完成證據是提醒送達，且誤報與漏報可控。人訂定門檻與停止條件。

其餘六種只列名稱：文件抽成欄位、警報與事件初篩、跨工具流程推進、定期摘要、線上事務代辦、遠端推動程式修改。完整拆法在講義上。

四種說明之後，把操作收成十個動作動詞：讀取、查找、擷取、比對、計算、草擬、寫程式、執行寫入、通知交接、詢問核准、驗證。前六個留下可審查的檔案。執行寫入與通知交接改變外部狀態。詢問核准把決定交回人。驗證是回讀結果，確認確實完成。下午拆解自己的工作時，以這些詞填寫「Agent 具體操作」一欄。

最後一項提醒。工具呼叫成功只證明那一步，不能代表整項業務完成。統計表產出了，不代表數字經過確認。年報段落寫好，不代表已審核通過。送出審核，不代表承辦人已接手。每種業務動詞各有完成條件，拆解工作時須寫得出完成證據。

外部案例的普及程度與成效數字不在課堂說明。若學員問起，說明這些案例多為業者自述，調查顯示多數組織尚未在任何一項業務上規模化使用。參考案例是參考做法，不是參考平均效果。

## 五、地震業務翻成同樣的語意

其他組織的用法以通用語意寫成：守視、查核、解釋、整理。要與之配對，自己的業務也須翻成同樣的語意。

動詞對照表的前三欄即為此用。十個工作動詞：守視發現、查核判定、通報發布、回答解釋、提供資料、整理保存、分析研究、維護設備、維護系統、規劃管考。每個動詞之後寫明它在地震業務中實際是什麼，再寫相近的外部工作語意。守視發現相近於監控中心看告警。回答解釋相近於客服與科普。維護系統相近於 IT 維運。規劃管考相近於專案管理。

這張表依公開的職掌與年報歸納，不是 SOP，也不代表各科實際分工。授課時請學員檢視自己相關的幾列是否貼切、何處遺漏，當場修正。修正這張表本身就是課程要做的事：把自己的工作用能與其他組織比較的語意描述一遍。

第四欄「對應的用法樣式」是配對的結果。守視對應事件初篩與定期監看。回答解釋對應例行詢問答覆。整理保存對應文件抽欄位與研究底稿。分析研究對應研究底稿與第一版初稿。維護系統對應遠端程式修改。規劃管考對應定期摘要與跨工具流程推進。配對已做在表上，學員只需找到自己的動詞。對得上只表示有其他組織做過的做法可以參考；能否施行，仍取決於資料、權限與驗收人，那是工作坊要處理的問題。

把案例放回這張表。年度成效統計自整理保存開始（挑事件、算差異、回存規則），主體是分析研究（統計與年報段落），最後接到通報發布（年報送審與發布）。一件事跨了三個動詞，由不同的人負責。這就是「一段」與「整件」的差別：工作坊先攤開整件，再挑出一段。

## 六、收尾：以案例走一次，銜接工作坊

上午的內容收在一張表上。講義的工作單分上下兩區，上區攤開整件工作，下區拆解一段。以下用年度成效統計填寫下區。

| 欄 | 案例填法 | 來自哪一段 |
|---|---|---|
| 我的工作段 | 從地震目錄挑出去年合條件的事件，逐件算出差異，做成表與圖交年報承辦 | 引言 |
| 通用動詞 | 整理保存、分析研究，接到通報發布 | 第五段 |
| 相似用法 | 第一版初稿、跨來源整理成研究底稿 | 第四段 |
| Agent 具體操作 | 讀取目錄與報次紀錄、擷取第一報與報告參數、計算差異、比對去年規則、草擬表圖與年報段落、詢問核准納入與排除、驗證數字可重算 | 第四段動作詞彙、第一段機制 |
| 中間產物與完成證據 | 事件清單、逐事件差異表、納入排除清單；數字可重算，承辦接受，年報審核通過 | 第三段的 C |
| 誰驗收 | 承辦同仁決定納入排除與異常解釋；年報審核者定稿 | 第三段誰負責、第二段介入方式 |

兩點說明。第一，這張表填的是一段，不是整件業務。工作坊先以上區攤開整件工作，再挑一段填寫下區。第二，「誰驗收」與「完成證據」填不出來的段，通常就是不適合交出去的段。填不出來是一項判斷結果，不是失敗。

做完之後留下什麼，以一頁交代。材料與自己的洞見存入文件櫃，工作稿存入工作台，確認有效的標準寫入工作規則，採用與放棄的理由留下紀錄。保存時分清四種內容：原始材料的內容、對作者意圖的推論、自己加入的洞見、Agent 的提案是否仍為候選。摘要不等於讀過。完整的位置與做法在工作坊操作引導四展開，不要求學員一開始複製整套資料夾。

工作坊的進行方式如下。學員取得三張講義：動詞對照表、工作單、評估表。先選一件近期做過、正在進行，或想做卻未開始的工作。以工作單上區攤開現況。挑出一段，查對照表，填寫下區。比較三種做法：調整流程、使用一般程式或既有軟體、使用 Agent；規則固定、輸入整齊的段，先考慮前兩種。以評估表檢視收益、條件、成本、風險與累積。條件允許便當場試做一小段，條件不足則寫明要驗證什麼。最後留下一小段紀錄。

沒有題目的學員有備援題。時間與順序由學員自行安排，講師巡視，不投影同步的時間表。成果不須繳交，也不須上台。能說清楚一個用途的目的、可行條件、代價與驗證方法，即為本週的收穫；暫時決定不做，只要理由有依據，同樣算數。
