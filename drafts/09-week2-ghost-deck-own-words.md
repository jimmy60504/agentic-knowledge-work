原話來源：Codex 與 Claude 的 session 紀錄，2026-09-06 至 09-07 使用者本人的訊息，逐字摘出，只刪贅字、不改用詞；括號內是日期與時間。完整訊息存 `tmp/week2-own-words/`。標【無原話】的是 agent 補的銜接或安排，沒有使用者的句子可還原。

### 9｜這份投影片是怎麼做出來的，分五頁

一頁放不下五次變化，拆成五頁：總覽一頁，三圈各一頁，第三圈再多一頁講今天的原話重排。每頁一組改前改後的畫面。

## 示範與實作

### 10｜自己的流程，拆成每一步

兩份原始版本：手稿第 6 頁的七步「訂主題 → 找資料 → 整理大綱 → 尋找素材 → 文案收斂 → 排版 → 最終確認」（09-06 18:06），以及 09-06 23:07 的操作版十行。下面依目前教案的八步對應，每步先列你的句子，再標沒有原話的部分。找原則不是獨立一步，第三圈的每個面向（分頁、語氣、排版）各在開頭拿判準。

**第一步：初始化**

- 「先開一個空的專案，然後開始先講這個專案大致上要做什麼，然後說要建立 kb，並且叫 agents 把討論都寫進 kb 裡面，然後這個動作全部寫進 agents.md 裡面，這樣就會把專案初始化」（23:07）
- 「kb 是一個常見的處理方式，剩下的 draft 或其他資料夾都是依照專案需求，跟著 agent 互動建立出來的……如果本身就有一個自己熟悉的整理方式，那就叫 agent 先照抄也可以」（22:04）
- 無原話：打開檔案確認、太長就刪短、明確請 agent 讀取 AGENTS.md。這三條來自試跑。

**第二步：背景與材料**

- 「然後開始講專案背景，像是受眾，時間，簡報長度等等這些限制條件／然後開始拓展主題看要讓觀眾知道什麼」（23:07）
- 「用聊天的方式把背景講一講，然後問問看 agent 建議，最後落成 md 存起來」（22:07）
- 手稿：「找資料」
- 「如果先在論點那個地方就先搜集一些文獻跟圖片會不會更好？」（09-07 01:03）
- 無原話：每份實際開啟、附來源與日期、區分作者說明與待確認、30 分停止搜尋。這些來自試跑與圖文判準。

**第三步：先找出想講的方向**

- 「有了大方向叫 ai 拓展看看有沒有東西要調整／有的話就繼續聊天補齊」（23:07）
- 「人看過所有前面探索的資料，先想辦法不用 ai 寫一個大綱出來……但真的想不到的話就叫 ai 串串看也是可以的」（22:45）
- 「如果自己有自己的想法，那就是先以自己的為主……不能被牽著走要有自己的意見」（22:20）
- 「論點本身也會有一些棄案可以被整理出來」（23:13）
- 手稿：「整理大綱」
- 無原話：檢查點一。
