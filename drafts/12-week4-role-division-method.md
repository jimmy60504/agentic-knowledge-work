# 人與 Agent 的角色分工：一套做法（草稿）

> 2026-09-21 初稿，同日採用：4-1 第 14 到 17 頁依第六節改寫，畫面不放大表，只用一條流程線逐頁加標註。使用者提議把「從組織合作的角度找角色」寫成一套人與 Agent 分工的做法，先起草看形狀。書面語，供 4-1 第 14 到 17 頁改寫或工作坊講義取材。來源：[[agent-roles-in-use]]、公文流程與幕僚作業的通用說法、RACI、Mintzberg 管理者角色、Belbin 團隊角色。

## 一、出發點

組織裡的分工早就有一套語言：承辦、會辦、審核、決行、歸檔；幕僚與業務；誰負責、誰當責、誰被諮詢、誰被告知。把 Agent 放進這套語言裡，不必為它發明新的角色名稱，也比較容易看出哪些位置它能站、哪些不能。

一句定位：Agent 是幕僚，不是主管。幕僚作業的內容是備妥資料、列出選項、擬好草案、跑完例行程序，然後把東西交到做決定的人手上。這個定義涵蓋了想事情與做事情的所有角色，也劃出了它站不進去的地方。

## 二、做法：三步

### 步驟一：先畫責任線

用 RACI 四個字問一遍：這一段工作誰負責執行、誰當責、誰被諮詢、誰被告知。

| RACI | 意思 | Agent 能不能 |
|---|---|---|
| 負責執行 | 實際動手做 | 能，這是它多數時候的位置 |
| 當責 | 出事誰負責、誰簽字 | 不能，永遠是人 |
| 被諮詢 | 做之前問一下意見 | 能，對話裡的討論者與對手 |
| 被告知 | 做完通知一聲 | 能，通知交接那個動作；也可以反過來是它通知人 |

當責那一格畫定之後，其他三格才有得派。這條線對應公文流程的決行，數發部手冊 4.2.9 說機關對 AI 輔助工作的輸出承擔責任，講的就是這一格。

### 步驟二：沿著公文流程派角色

一件事在機關裡走的路大致固定：幕僚備料、會辦提意見、承辦擬稿、執行、審核、決行、歸檔、追蹤。每一站問：這一站人做什麼、Agent 當什麼角色、需要什麼權限、交出什麼。

| 組織裡的位置 | 人做什麼 | Agent 的角色 | 需要的權限 | 交出什麼 |
|---|---|---|---|---|
| 幕僚備料 | 定題目、給範圍 | 整理者 | 讀資料 | 對照表、清單、底稿 |
| 會辦 | 帶著自己的意見去問 | 討論者、對手 | 只讀 | 選項附利弊、反例與疑點 |
| 擬稿 | 定標準、給格式 | 起草者 | 寫檔 | 可修改的草稿、程式 |
| 執行 | 給指令、看結果 | 操作員 | 執行 | 執行結果與回讀確認 |
| 審核 | 定檢查項目 | 審查者 | 只讀 | 逐項檢查表 |
| 決行 | 決定、簽字 | 無 | 無 | 決定 |
| 歸檔 | 決定存哪裡、存什麼 | 記錄者 | 寫筆記 | 決定、理由、未解事項 |
| 追蹤 | 定核准點 | 協調者 | 分派、通知 | 進度、待核准清單 |

幾個規則：

- 一站一個角色，同一個 Agent 換站就換角色，換角色就是換一段指示或換一段乾淨的對話。不是要開八個 Agent。
- 權限跟著角色走。會辦與審核只讀，擬稿寫檔，執行可以跑程式，追蹤可以通知。給它的權限不要超過那一站需要的。
- 審核那一站可以查別人的東西，也可以查它自己在擬稿那站寫的東西，條件是換一段乾淨的對話，不要在同一段裡自己審自己。

### 步驟三：定交接點

每一站交出來的東西，人在哪裡看、看什麼，先寫下來。這就是 4-2 講的完成證據與中間節點：整理者交的對照表要能逐列查來源，起草者交的草稿要能改，操作員交的結果要能重跑比對，審查者交的檢查表要一項一項有結論。交接點寫不出來的那一站，通常就是還不適合交出去的一站。

決行前後各一個交接點最重要：決行前，審查者的檢查表與起草者的草稿要一起到人手上；決行後，記錄者把決定與理由存回去。這兩個點在流程指派 Agent 與 Agent 管理流程那兩種介入方式裡，就是核准點。

## 三、它站不進去的位置

把幾套組織角色框架攤開比對，對不上 Agent 的角色有規律：

| 框架 | 對不上的角色 | 共同點 |
|---|---|---|
| 公文流程 | 決行 | 責任 |
| RACI | 當責 | 責任 |
| Mintzberg 十角色 | 領導者、聯絡人、發言人的責任、談判者 | 關係、對外代表 |
| Belbin 九角色 | 推進者、凝聚者 | 動力、關係 |
| 會議角色 | 主席、決策人 | 責任 |

它接不了的是責任、關係與動機，不是能力。這比列一張「AI 不能做什麼」的清單清楚：只要一站的重點是「誰擔責」「誰對外」「誰帶動人」，那一站就留給人。

## 四、案例：年度預警成效統計走一遍

| 站 | 人 | Agent | 交出什麼 |
|---|---|---|---|
| 會辦 | 問深度門檻要不要改 | 討論者列改與不改的利弊；對手質疑改了今年和去年能不能比 | 選項與疑點 |
| 幕僚備料 | 指定三個來源 | 整理者把地震目錄、報次紀錄、去年的表對起來，列出對不上的事件 | 對照表 |
| 擬稿 | 定表的格式與段落的標準 | 起草者寫逐事件差異表與年報段落草稿 | 草稿 |
| 執行 | 給定規則 | 操作員跑統計腳本，回讀結果和去年比對 | 統計表與比對 |
| 審核 | 定檢查項目 | 審查者逐句對照段落與表，指出數字不一致與漏講的項目 | 檢查表 |
| 決行 | 承辦決定納入排除與異常解釋，審核者定稿 | 無 | 決定 |
| 歸檔 | 決定存哪裡 | 記錄者存規則、事件清單、採用與放棄的理由 | 紀錄 |
| 追蹤 | 定核准點 | 協調者在每次事件後補一列，異常時停下通知 | 進度 |

追蹤那一站是第五種介入方式，其餘七站都可以在對話與交辦裡完成。以現況來說，執行那一站先寫成腳本，是第三種，收益最實在。

## 五、與六種介入方式的關係

介入方式講 Agent 站在流程的哪裡，角色講它在那一站做哪一種事，兩條軸互不決定。同一個角色可以出現在不同的介入方式裡：審查者可以在對話裡當一雙眼睛，也可以是流程裡的一個節點。角色決定權限，權限就是介入方式那條軸講的信任，兩邊講的是同一件事。

## 六、放進投影片的形狀（候選）

4-1 第 14 到 17 頁現在是「另一個維度、想事情、做事情、管事情」。如果改成這套做法，四頁會變成：

| 頁 | 標題 | 畫面 |
|---|---|---|
| 14 | 角色：Agent 是幕僚 | 一句定位；圖：六格圖加直軸不變 |
| 15 | 先畫責任線 | RACI 四列表，當責那列標「人」 |
| 16 | 沿公文流程派角色 | 八站表，只投位置、角色、權限三欄 |
| 17 | 站不進去的位置 | 五個框架對不上的角色，共同點一欄 |

案例表放第 18 頁套回案例的筆記，或做第 19 頁。想事情、做事情、管事情三群的分法退到筆記，作為八站角色的歸類。網路上的角色來源退到 KB。

兩種寫法的差別：三群版本從 Agent 這邊看，講它能做哪些事；幕僚版本從組織這邊看，講它站在哪一站、誰擔責。對承辦人，後者比較容易對到自己的工作；對「這一站能不能交出去」的判斷，後者也多了責任線這個判準。
