# 第四週後半文稿：從自己的工作找出值得嘗試的 Agent 用途

> 依 [04 工作坊稿](04-week4-agent-value-workshop.md) 與 [06 學員講義](06-week4-student-handouts.md) 展開的文稿，2026-09-19。以書面語寫成，能獨立閱讀；可作為工作坊開始時的說明，也可作為學員自行進行時的引導文件。照片出處與製作備註只留在 04 稿。
> 分組、用餐、自願分享與成果保存位置尚未決定，本文不預設。

## 目的

上午的講課說明了 Agent 如何運作、可以站在流程的哪個位置、一段工作如何從 A 走到 B，以及其他組織的用法與地震業務的通用語意如何配對。下午由學員把這套方法用在自己的工作上：先理解一件工作的目的與現況，再探索不同做法，判斷收益是否值得付出新增的成本與風險。

學員熟悉自己的工作，講師較清楚 Agent 能參與哪些環節。工作坊把兩者放在一起。成果不是一份提案，而是一個說得清楚的判斷：這一段工作的目的是什麼、Agent 能接手哪裡、需要哪些條件、代價是什麼、如何驗證。暫時決定不做，只要理由有依據，同樣是有效的結果。

## 進行方式

時間為 11:00 至 14:00，學員自行安排節奏，不設全班同步的時段。四個步驟可以往返，不必依序完成。講師巡視，依各人進度協助。

學員取得三張講義。動詞對照表用來查：找到自己工作的動詞，看其他組織的做法、Agent 的具體操作與完成證據。工作單用來填：上區攤開整件工作，下區拆解一段。評估表用來評：檢視收益、條件、成本、風險與累積成果。

成果不須繳交，也不須上台報告。紀錄是供自己接續工作用的。

三張表不必自行逐格填寫，可以讓 agent 協助。先請它讀過三頁教材，包括文末的三張講義，再用討論的方式進行：先說一件工作，由它整理成工作單上區，人指出哪裡不對、哪裡漏了；挑出一段，由它查動詞對照表提出配對與具體操作，人補正；評估表由它先列出問題與已知的條件，人逐一回答。表格是討論的紀錄，目的是把想法做出來，不是交出一張填滿的表。

## 開始：選一件工作

先選一件近期做過、正在進行，或想做卻一直未開始的工作。不必先想出「AI 應用提案」，也不必一開始就填完整張表格。講師可從對話協助縮小範圍。

選定之後，先釐清三件事：成果給誰使用，拿來做什麼，怎樣才算做好。產出文件只是過程；價值要看它是否改善了後續的理解、決策或行動。

以上午的案例說明。測站斷訊之後的處理，成果是給維運承辦人的一張工單與一份判斷依據；用途是讓承辦人知道該查什麼、優先度為何；做好的標準是承辦人不必重新查證就能開始處理。

## 步驟一：攤開整件工作

以工作單上區攤開整件工作。五個欄位：包含哪些流程，用了哪些系統，還有哪些痛點，收了哪些數據，會有哪些可能。

流程一欄記從什麼事情開始、經過誰、最後交給誰。系統一欄記使用哪些工具，以及哪些地方靠人工搬運、輸入或重新整理。痛點一欄記哪裡等待、重做、出錯、缺資料或無法決定，並追問原因：為什麼發生，影響上下游哪裡，能否提早發現，目前有無預防機制、為何未發揮作用。數據一欄記目前有哪些材料、紀錄與版本，能否取得。可能一欄記哪些步驟可以改變，哪些以前太費工而沒有做的事。

可以用文字、卡片或流程圖，記下每一步的輸入、處理、輸出與交接。形式不拘，目的是讓自己與講師看見同一件工作。

講師可視情況追問問題的性質：是偶發還是反覆發生，背後是資訊流動、決策權還是工作習慣。不要求學員完成整個組織的診斷。

## 步驟二：拆解一段並配對

從上區挑出一段。一段的意思是有明確起點與終點、交給某個人的一小截工作，不是整件業務。測站斷訊的例子中，「告警之後查明是設備故障還是通訊中斷，交維運處理」是一段；「從告警到修復完成記回紀錄」是整件。

查動詞對照表，填寫工作單下區六欄。

第一欄寫這一段從哪裡開始、到哪裡結束、交給誰。第二欄把這一段翻成通用動詞：守視、查核、發布、解釋、提供、整理、分析、維護、管考之一或其組合。第三欄在對照表找相似的用法樣式；配對已做在表上，同一個動詞對應的樣式通常有一到兩種。第四欄以動作詞彙寫 Agent 的具體操作：讀取什麼、比對什麼、草擬什麼、寫入哪裡、通知誰。第五欄寫中間留下哪些可檢查的東西，以及做完的證據是什麼。第六欄寫哪一步由誰核准、誰決定處置。

第五欄與第六欄填不出來的段，通常不適合交出去。工具呼叫成功只證明那一步；寫不出完成證據，就無法判斷業務是否完成。填不出來是一項判斷結果，值得記下。

填完之後比較三種做法：調整流程、使用一般程式或既有軟體、使用 Agent。規則固定、輸入整齊的段，先考慮前兩種；固定計算與專業模擬不必改成語言模型。需要理解材料、處理例外、產生可審閱成果的段，才是 Agent 較有價值的位置。

再以上午的 A→C→B 檢查這一段：目前有什麼，希望得到什麼，中間缺哪一個可檢查的節點。指出人負責哪一個決定、Agent 接哪一段、工具做什麼。上午的六種介入方式可作對照：這一段適合請教、一次性交付、建置工具後退出、固定節點呼叫模型、節點 Agent，還是跨節點協調。

收益從三個方向看，三者可以並存。降低既有成本：同樣成果能否少花查找、搬運、製作與返工的時間。強化人的能力：能否比較更多證據、探索更多方案、提早發現問題、形成更好的判斷。讓新工作可行：哪些想做卻維護不起的工作，現在可以持續做。知識管理是第三種的例子：以往每次討論都須自行整理與回存，往往無力持續；有 Agent 協助之後，才開始有可累積的材料與脈絡。收益不只看當次省時，也看後續能否再利用。

講師在這一步協助補上學員未想到的做法；是否符合現場，由學員判斷。

## 步驟三：檢視條件、成本與風險

以評估表對拆出的這一段做一次評估。五列各是一個問題群，不是必填的試算表。

條件一列問五件事：資料在哪裡，能否在允許範圍內取得；欄位、單位、詞義與版本是否一致，缺漏如何處理；誰能讀、誰能改，哪些動作需要核准；現在到哪一步，下一步交給誰，例外誰處理；成品、修改、依據與未解決事項存在哪裡。條件可以在小範圍試作中逐步補足，不要求先整理全組織的資料。

新增成本一列問工具費、資料整理、交辦、查核、返工、協調與維護各要多少，以及產出變快之後審查者的負擔是否增加。產出者更快，可能使審查者更慢；要看成果被使用之前的整段流程，不只看產出那一步。

風險一列問錯誤被採用、誤操作、資料使用不當、過時資訊被反覆引用各由誰承擔，以及誰受益、誰增加工作、出錯誰處理。

累積成果一列問下次可用的資料、方法、標準與已知的失敗條件是什麼。

沒有基準或尚未實測的收益，先當作假設。不把廠商的百分比換成自己的效益預估。

## 步驟四：試做一段，留下結果

選一小段可檢查、可修改的工作試做。條件允許便當場進行；尚缺資料或權限時，寫明要驗證什麼、如何觀察。

可以比較原本做法與新做法的總時間、品質、返工與檢查負擔。未完成時留下卡點。工作坊不以產出完整系統為目標，也不安排課後的紀錄或實驗。

最後回答四個問題：這次試過什麼，採用或放棄什麼，理由為何，下次可以直接沿用哪些材料或標準。失敗的條件同樣值得保存；暫時的發現不直接寫成永久規則。

可由 Agent 協助整理成一小段紀錄，學員確認內容。保存時分清四種內容：原始材料的內容、對作者意圖的推論、自己加入的洞見、Agent 的提案是否仍為候選。紀錄的用途是讓自己下次接得上，不預設繳交。

## 備援題

沒有題目的學員可從以下擇一。材料為公開資料或學員自己的文件，不使用未經允許的署內資料。

- 以自己寫過的長文檢查 Agent 的摘要。先保留自己想表達的見解與支持段落，請 Agent 閱讀並摘要，對照遺漏或偏移；再請它指出段落依據，補充問題引導重讀，保留各輪結果。分清哪些觀點文本原本就支持、哪些是提示之後才加入；若必須直接說出答案才能被抓到，也可回頭檢視自己的文章是否表達清楚。工作中有「讀多份材料再整理」這一段的學員，可直接以此檢查 Agent 摘要漏了什麼，判斷那段能否交出去。
- 找回舊結論：從一批舊文件中找出某個決定的依據與版本。
- 比對文件版本：找出兩份版本的差異與衝突之處。
- 整理多份表格：把格式不一的表格整理成一致的欄位。
- 準備會議：從材料整理出議題、待決事項與背景。

## 講師的角色

巡視時先理解工作現場，再提出技術上的可能性；不把所有需求改寫成提示詞。學員不知如何開始時，協助縮小一段工作、找到中間產物，或提供可試的公開材料。學員已有結果時，追問依據、例外與取捨，不只看產出是否流暢。

時間與順序由學員依進度安排。四個步驟可以往返，不投影成全班必須同步完成的時間表。

## 收穫的判斷

學員能否說清楚一個用途的目的、可行條件、代價與驗證方法，是觀察工作坊是否有幫助的方式。暫時不採用某個方案，只要理由有依據，同樣有價值。不設強制的成品數、測驗或課後負擔。
