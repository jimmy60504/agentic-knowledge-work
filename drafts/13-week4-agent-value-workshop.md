## 為什麼第四週改成工作坊

使用者指出，一般人很難從抽象的 agent 介紹感受到用途。上次以備課過程示範，包含太多只有講師熟悉的想法與脈絡，學員未必能連到自己的需求。

另一方面，學員可能還沒看過更好的工作方法。直接問「想用 agent 做什麼」，容易只得到原本做法的小幅加速，或根本想不到用途。因此工作坊需要讓學員提供現場經驗，講師協助提出新的可能，再共同判斷是否值得採用。

使用者提出的核心問題是：工作價值原本從哪裡來？Agent 如何增加價值？會新增什麼成本與風險，又能帶來哪些收益？工作坊以這些問題串起討論。

## 一、先理解工作的目的與現況

一份報告的價值，取決於它能否幫助後續理解、決策或行動。工作坊先選一件具體工作，說清楚誰會使用成果、要達成什麼，以及怎樣才算做好。這是本課程的引導建議。

接著借用演講的五欄盤點，讓全組有共同的工作現況可以討論。

| 整理自 IMG_8312 的五欄 | 課程延伸提問 |
|---|---|
| 包含哪些流程 | 從哪裡開始、經過誰、產生什麼、交給誰？ |
| 用了哪些系統 | 現在使用哪些工具？哪裡還要人工搬運或重新輸入？ |
| 還有哪些痛點 | 哪裡等待、反覆修改、資訊缺漏或容易出錯？ |
| 收了哪些數據 | 已有什麼資料與紀錄？需要時拿得到嗎？ |
| 會有哪些可能 | 有哪些步驟可以改變？哪些以前太費工的事，現在可能做得起？ |

可先請學員口述一件最近發生的事情，再用卡片或文字共同整理。卡牌讓第一線經驗外部化的用意取自 IMG_8314；本課程不假定已取得原活動的完整卡牌規則。

## 二、找出反覆問題的原因

整理自 IMG_8313：先辨認流程缺口造成的錯誤與耗時，再追問原因、上下游影響，以及現有預防機制為何沒有發揮效果，最後才討論 AI 可以協助哪裡。

IMG_8397 的冰山圖提供另一組追問層次：眼前事件是否反覆出現？背後的決策與資訊流動如何運作？大家對改變有哪些既定想法？

課程自擬例子：報告一直重寫，可能是初稿品質不足，也可能是需求改變、使用了不同版本的數據，或沒有人能確認方向。不同原因需要不同處理方式。本次工作坊先釐清所選任務的主要原因，不要求完成整個組織診斷。

## 三、用三種收益探索新做法

IMG_8386 將價值分成自動化、強化、代理三階段。本課程借用其收益角度，改成三種可並存的選題方式；不採用「所有用途都必須依序經過三階段」的強主張。

| 收益方向 | 可以討論的問題 |
|---|---|
| 降低既有成本 | 同一件事能否減少查找、搬運、重複處理與返工？ |
| 強化人的能力 | 能否比較更多證據、提早發現問題，或探索更多方案？ |
| 讓新工作可行 | 有哪些以前想做，卻因執行或維護成本過高而沒有做的事？ |

提出候選方案時，同時考慮流程調整、一般數位工具與 agent 的分工。固定計算可以交給程式，領域模擬交給專業工具，需要確認用途與品質的環節由人判斷。工具串接的參考來自 IMG_8389、IMG_8365、IMG_8373；它們是設計示意，不是已查核的部署成效。

每一步都要問：輸入是什麼、產出交給誰、下一步能否直接使用、錯誤如何發現？Agent 的介入範圍可以先小到一個環節。

## 四、檢查做法是否具備執行條件

整理自補充 JPEG 投影片的五個基礎問題。右欄為課程延伸，並非投影片遮擋細字的轉錄。

| 五個基礎問題 | 用於候選方案的檢查 |
|---|---|
| 資料在哪裡？ | 任務需要哪些來源，能否在允許範圍內取得？ |
| 資料結構清楚嗎？ | 欄位、單位、版本與用詞是否一致？缺漏如何處理？ |
| 權限怎麼管理？ | 人與 agent 可以讀寫什麼？哪些動作要經過核准？ |
| 流程怎麼進行？ | 目前做到哪一步、下一步交給誰、例外由誰處理？ |
| 結果怎麼留下？ | 成品、變更、判斷依據與尚未解決的問題存在哪裡？ |

這組問題檢查執行條件，前一組五欄用來盤點工作與探索機會，兩者在不同時點使用。可以在試作過程中逐步補齊條件，不要求先整理完所有資料。

## 五、把收益、成本與風險放在一起看

IMG_8335 提醒利害關係人的投入、價值與期待可能不一致；IMG_8398 強調跨部門溝通與翻譯。課程可轉成三個問題：誰受益？誰多了工作？誰負責驗收與後續處理？

產出者省下時間，可能讓審查者收到更多需要檢查的內容。評估範圍因此要包含交接到成果被使用的過程。

| 面向 | 可觀察的內容 |
|---|---|
| 收益 | 人力時間、完成速度、品質、決策所需資訊，以及新增可行工作 |
| 新增成本 | 工具費用、資料整理、交辦、查核、返工、協調與維護 |
| 風險 | 錯誤被採用、資料或權限使用不當、誤操作、過時資訊持續被引用 |
| 累積成果 | 下次能再用的資料、方法、標準，以及已知不適用條件 |

以上為課程改編的評估面向。企業生命週期與 gateway 投影片提供持續運行的背景，不作為入門必須採購或部署的清單。效益百分比尚未查核，評估以所選工作的原本做法和實際試作結果比較。

## 六、把一次工作留下來，供下一次使用

整理自 IMG_8356：既有知識與標準支援可重複的工作，新材料先與現有知識比較、由人審查；無法套用既有規則的部分再進入探索與實驗。失敗經驗也可以成為後續專案的資源。

使用者最有感的知識管理案例可放在這裡。以前討論完還要自行整理、回存、連結舊資料，成本高而難以持續；agent 能協助維護，讓之後的工作接得上。收益既包括當次交付，也包括後續少重新查找、重複研究或猜測決策理由。

講師可展示一小段完整過程：加入新材料、找回相關筆記、人做取捨、保存理由，最後換一個需求取用先前累積。示範需先交代工作目的，讓學員知道哪一部分變得更容易。這是候選設計，不是已驗證的教學成效。

保存要能支援找回、查核與更新，才可能形成可用資產。課程收尾可問：「這次做完，要留下什麼，讓下一次更容易做好？」

## 七、09:00–14:00 工作坊的候選安排

借用 IMG_8374 的規劃、驗證、實施、擴展思路，這次先聚焦理解問題、設計方案與小範圍驗證。已確認合併兩週時數，於同一天 09:00–14:00 進行。以下為四個候選活動階段；午休、休息、分組及實作形式待定。

| 階段 | 活動方向 | 可留下的成果 |
|---|---|---|
| 1. 理解與選題 | 講師用短案例說明價值與三種收益；學員提出真實工作情境 | 一件有受益者與目的的工作 |
| 2. 盤點與原因分析 | 共同盤點五欄、追問原因與既有機制，選出值得改善的部分 | 工作現況圖與需要驗證的原因假設 |
| 3. 方案與可行性 | 講師補上可能做法；比較方案與分工，檢查五個基礎問題 | 候選做法、必要條件與成本風險 |
| 4. 驗證與回存 | 選一小段試作或設計驗證，回看結果與下一步 | 可觀察的驗證方式、取捨理由與可再用紀錄 |

課堂先讓學員討論，再協助整理成果，不要求一開始填完複雜模板。Agent 可協助記錄、提出候選與檢查遗漏；學員確認是否符合工作現場，講師協助辨認技術可行性。

候選成功標準：學員能說清楚一個用途為何值得驗證、有哪些條件與代價，以及如何觀察改善。判斷暫時不採用某方案，只要理由有依據，也可以是成果。
