> 2026-09-18 討論草稿，依整段對話重新整理。供閱讀與修改，尚未整合進正式教材，也未修改 ssot。

## 從共同工作環境開始理解

想像你有一個文件櫃、一張工作台，以及一個可以跟你一起工作的機器人。文件櫃保存材料，工作台放正在整理的草稿；你派機器人找資料、討論、記錄或起草，共同查看結果，再決定下一步。

工作台上的內容確認後，機器人可以把製作規則寫成程式，操作加工機器，產出簡報、報告、互動畫面，甚至連接設備製作實體。成品出現問題，就回到草稿或加工規則修正，再重新製作。

| 工作環境中的東西 | 對應 | 作用 |
|---|---|---|
| 文件櫃 | `kb/` | 保存、取用與回存資料、來源、筆記及洞見 |
| 工作台 | `drafts/` | 整理、組合與修改正在形成的內容 |
| 機器人 | agent | 依指派討論、查找、記錄、審查、起草與操作工具 |
| 加工機器 | 程式碼、執行環境與設備 | 按明確規則轉換、執行與製作 |
| 成品 | 簡報、報告、程式或實體 | 供實際使用、檢查與交付 |

使用者將 kb 的比喻從「倉庫」改成「文件櫃」，是希望表達材料就在旁邊、隨手可取用。程式碼則同時可能是加工工具與最終交付物，依任務而定。機器人的比喻以 agent 有相應文件存取與操作工具為前提。

## 從人工、數位化到 Agent 化

使用者提出，可用工作方式的演進作為講解入口：原本人直接做出結果，電腦出現後，人透過軟體或編寫程式產出結果；現在則由人指派 agent 建立、調整與操作程式及工具，製作結果。

| 工作方式 | 產出路徑 | 人主要做什麼 |
|---|---|---|
| 人工 | 人 → 結果 | 親手製作、操作與修改 |
| 數位化 | 人 → 軟體／程式 → 結果 | 操作軟體，將可明確描述的規則寫成程式 |
| Agent 化 | 人與 agent 討論 → 程式／工具 → 結果 | 說明意圖、指派工作、檢查與驗收 |

這是講解用的演進示意，三種方式仍會並存。Agent 化依賴可讀取的材料、可說明的流程與可操作的工具；攤開工作時，可能發現這些條件尚未具備，需要先補上數位化與流程釐清的工作。

### 靈感來源：先攤開流程，再判斷如何改善

使用者說明，本段討論受到最近觀看數發部選題演講的啟發：為輔導中小企業進行 AI 轉型，先攤開既有流程，會發現許多環節尚未數位化，需要先處理這些問題，才有機會接上 AI。這是使用者的觀看心得；演講題名、講者、日期與連結尚未提供，未查核或視為數發部正式主張。

使用者特別指出，有些問題在數位化過程中就能解決，未必需要進一步使用 AI。另一方面，AI 也可以協助整理流程、建立工具與編寫程式，加速數位化。數位化與 Agent 化可以交錯推進。

這讓工作流設計多了一個判斷：先釐清要解決什麼，再看資料整理、流程改善或一般程式是否已足夠；仍有模糊、需要探索或自然語言互動的部分，再評估 agent 如何參與。

| 攤開流程後發現的缺口 | 可以先處理什麼 |
|---|---|
| 材料尚未成為可讀取的資料 | 數位化、整理與建立存取方式 |
| 做法與標準未說清楚 | 記錄流程、釐清分工與完成條件 |
| 明確步驟仍在重複手動執行 | 用既有軟體或程式固定規則 |
| 需要解讀語言、探索與反覆釐清 | 指派 agent，透過中間產物對齊 |

表格是 agent 依討論補充的候選整理，不是演講原表。改善是否有效，仍要用原本的問題與實際結果判斷；流程中使用多少 AI 並非目的。

## 思考必須透過外部表達才能共同處理

使用者指出：

> 人的想法轉成外部可見的任何東西都會失真，包含轉成文字跟畫面等等，我們只能夠透過輸出的這些東西來推測，但真正的思考是沒有辦法被外部觀測的，這個東西就沒有訓練資料。

思考本身與思考的表達需要分開。文字、畫面、口述與工作紀錄都經過選擇與轉換；即使寫下自己的思考過程，也無法保證完整呈現。

就文字訓練資料而言，模型接觸的是人類思考留下的外部表達，無法直接取得某個人的完整思考與意圖。資料中可以有推理說明、工作紀錄與成品，這些仍是表達。此處保存的是方法論觀點，尚未形成完整的認知理論。

因此，協作要先把目前的想法外部化，形成可以共同查看的內容。大部分想法具體化的第一步，是將零散對話與想法整理成有背景、有目的、有結構的東西；可以是文稿、提案或需求說明。

## 每次轉換，都要重新對齊

使用者概括目前的方法：

> 所以我們這個方法就是拿著學習人類回話的生成器，用人預期的管理方式，讓模型產出中間產物來跟自己的思考對齊。

中間產物讓人有機會辨認「這跟我想的不一樣」，再補充背景、說明取捨或修改內容。這些修正成為下一輪生成的上下文，逐步減少模型需要猜測的部分。

每次轉換都會增加內容、重新組織與聚焦。討論變成文稿、文稿變成逐頁稿、逐頁稿變成簡報，各層的用途與限制不同，因此每次都要重新確認意思、範圍與標準。

人也會在擴展時學到新東西。新材料、不同觀點與試做結果，可能改變原本的理解與需求；對齊的目標會隨之調整。工作台也讓人釐清自己究竟想要什麼。

| 簡報案例中的轉換 | 重新對齊的內容 |
|---|---|
| 零散想法與材料 → 結構化文稿 | 背景、目的、主張、依據與新理解 |
| 文稿 → ghost deck、逐頁稿 | 受眾、時間、邏輯順序，以及畫面與口述的分配 |
| 逐頁稿 → 簡報 | 語氣、畫面、媒介限制與實際使用效果 |

需要幾層迴圈，取決於想法到成品需要多少次轉換，以及人對工作流程的理解與模型能力。轉換層數與每層的修改輪數要分開；一層可以反覆修改多次，也可以在條件足夠清楚時合併部分轉換。

第二週的三個迴圈是簡報案例中的安排：形成論述、建立架構、調整風格；第二週已發布教材第一圈仍稱「確認方向」。這次討論把它概括成「各次轉換與重新對齊」，尚未改動正本。

## 用 A、B 與中間節點拆解工作流

使用者提出，創造工作流時要尋找的步驟，是人能用語言明確說明「如何從 A 得到 B」的轉換。如果目前想像的 A 無法直接得到 B，就找一個中間節點 C，把兩者串成 A → C → B。

A 是目前已有的材料或產物，B 是希望得到的下一個產物。拆解時先說明輸入、需要完成的轉換與結果的檢查方式；若無法說清楚，或一次轉換難以可靠完成，就加入 C，並分別確認 A → C 與 C → B 如何進行。仍有缺口時，繼續拆解。

例如從零散想法直接製作簡報，可能難以確認主張與順序，就先形成結構化文稿；如果文稿到簡報之間仍缺少各頁安排，再加入逐頁稿。每個中間節點都應補上一個具體缺口，讓下一步有足夠依據，也讓人能檢查。

這條規則把「理解原本的工作流程」變成可操作的問題：我目前有什麼、下一步要得到什麼、兩者之間缺什麼？能用語言說清楚，是指派與檢查的起點；是否真的可行，仍需試做確認。C 可以是新增資料、決定、規格或其他產物，依缺口選擇。

### 從哪裡找到中間節點 C

使用者指出，找 C 有幾個明確方向：問 AI、請 AI 找資料、自己查找資料，或從現實世界中發現事情。工作流的缺口可以透過對話、既有知識與實際觀察補上。

| 尋找方式 | 可以怎麼進行 |
|---|---|
| 問 AI | 說明目前的 A、想得到的 B 與卡住的地方，請它提出可能的中間節點與理由 |
| 請 AI 找資料 | 查找別人如何完成類似轉換，整理方法、案例、適用條件與來源 |
| 自己查找資料 | 閱讀文件、書籍或案例，請教有經驗的人，辨認缺少的材料或方法 |
| 從現實世界發現 | 觀察實際工作、親自試做，從結果、限制與新發現辨認缺口 |

這些方式可以交替使用。新發現可能指出需要哪個 C，也可能讓人重新理解 A，或調整原本想得到的 B。AI 提出的 C 先作為候選，再確認 A → C 與 C → B 是否成立；找到說法之後，仍需要材料、觀察或試做支持。

查找得到的資料與洞見回存文件櫃，採用的節點與轉換安排放在工作台上繼續加工。這也把角色工具箱接回工作流：需要建議時派討論者，需要依據時派資料蒐集者，需要檢查時派審查者；實際觀察與操作則依情境由人與可用工具完成。

### 搜尋取得材料，閱讀可能形成新的洞見

使用者進一步區分請 AI 查找與自己查找。AI 可能還不知道人真正想找什麼，只依表面要求搜尋；這能帶來沒看過的材料，但人的新想法往往是在閱讀原始資料後突然形成，並非一開始就知道要搜尋的答案。

許多關聯沒有直接寫在文字表面。AI 可以提出文字背後的連結，但搜尋結果本身不保證呈現讀者關心的問題。讀者帶著自己的經驗與探索方向，可能把文本中的線索重新組合成新觀點，甚至是作者沒有想到的觀點；使用者以「洞見」描述這種形成過程。

因此，找到材料、摘要作者的主張、推論作者的意圖，以及形成讀者的新洞見，需要分開辨認。讀者形成的洞見可以有價值，也要說明來自哪些線索、加入了哪些自己的判斷，避免把它寫成作者原本的意思。此處描述的是不同工作，不預先斷定 AI 永遠無法形成有用的新連結。

AI 查找可以擴展材料範圍；人閱讀後產生的新問題，再轉成下一輪搜尋或討論的方向。這也說明，派 agent 搜尋之後仍需要自己讀材料，並把閱讀後改變的探索意圖重新告訴它。

### 用自己的長文測試 AI 是否抓到意圖

使用者提出一個候選練習：拿自己寫過的較長文章，看 AI 如何總結，是否包含自己想表達的見解；再改變提示，請它重讀，觀察能否找出原本的意圖。

1. **先保留自己的參照。** 寫下文章最想表達的見解、哪些段落支持它，以及哪些意思可能沒有明寫，暫不提供給 AI。這一步是 agent 為方便比較所補充。
2. **看第一次摘要。** 請 AI 閱讀並總結，對照自己想表達的見解，辨認它抓到、漏掉或偏移的部分。
3. **逐步引導重讀。** 先請它找核心主張、段落間的關係與支持位置；再提供自己關心的問題或指出遺漏，請它重新解讀。保留各輪提示與結果。
4. **檢查答案如何形成。** 分清楚哪些見解由文本支持、哪些需要推論、哪些是在提示後才補入。確認它是否仍能指出依據，而非只是重述使用者給出的答案。
5. **回看自己的表達。** 若需要直接說出見解才能被抓到，也可能代表文章沒有把意圖表達清楚。比較不同解讀，可以同時檢查模型的閱讀與自己的文章。

這個練習觀察的是 AI 在特定文本與提示下如何重建意圖，不能直接證明它讀到作者內在的思考。作者自己保留的參照也可能是事後整理的表達；仍可用來比較摘要與原本想傳達的內容之間的落差。

它把本方法縮小成一次可觀察的循環：文章作為外部表達，摘要作為中間產物，人指出落差，再用新的語言線索引導模型重讀。練習目前只有設計，尚未實際執行。

## 用語言引導生成的機率

本次使用者明確要求保存的表述：

> LLM 學過大量人類語言與互動模式。我們可以借用溝通、管理與教練的方法，把意圖、背景、分工與標準說清楚，提高它產生合適回應的機率。

使用者強調，模型是機率生成系統。引導式語言改變的是不同回應出現的機率；管理與溝通方法提供可用的互動結構，例如建立背景、追問、比較、交辦與回饋。

不能因為模型回應得像同事或教練，就推定它具有人的動機、感受與責任感。借用這些方法，是希望引導可觀察的回應與行為；是否有效仍要看實際成果，對齊意圖與查核事實也要分開。

本方法主要適用於以自然語言互動的 LLM 與 LLM 型 agent，包含具備多模態能力的模型。其他類型的 AI，需要依其能力另行設計互動方式。

## 把 agent 的工作拆成可指派的角色

使用者認為，agent 在流程中參與太多角色，全部包成同一個名稱，會讓一般人難以想像能怎麼運用。把角色與任務說清楚，就能看見每次合作是在做什麼。

| agent 此時的角色 | 可以派它做什麼 | 開口例子 |
|---|---|---|
| 討論者 | 提供觀點、拓展與比較方向 | 「我想改成 why、what、how，你覺得呢？」 |
| 資料蒐集與整理者 | 查找資料、整理來源，取用與回存文件櫃 | 「先看第二週現有的方法，整理重點。」 |
| 記錄者 | 保存共識、理由與未定事項 | 「把目前的想法記下來，未定的分開列。」 |
| 審查者 | 提問、找盲點、檢查依據 | 「幫我看哪些假設還沒有講清楚。」 |
| 起草者 | 把零散想法整理成結構化草稿 | 「整理一個 draft，讓我有東西可以看。」 |
| 工具製作者與操作員 | 編寫或修改程式，操作工具並檢查製作結果 | 「依逐頁稿產出簡報，匯出畫面後檢查。」 |

這些是任務中的角色，同一個 agent 可以切換，也可以按需要分工。表格是本次討論的工具箱候選，沒有固定使用順序。

使用者提出，以「派」來理解 agent，可能讓人更意識到自己要做主。指派前想清楚需要它幫哪一段，指派後檢查結果、決定是否採用；這個心理效果仍可在教學中觀察。

Why、what、how 可以作為指派時的提醒：為什麼需要協助、希望完成什麼、有哪些限制與檢查標準。具體做法可以請 agent 提案，再由人決定，無須一開始規定所有操作細節。

## agent 處理不確定，程式碼固定明確規則

使用者提出的分工：

> 讓 agent 去處理模糊不確定的東西，然後把明確規則收斂成程式碼讓他可以重複執行。

agent 協助探索、理解自然語言、提出方案與試做。方向與規則確認後，將能固定的部分寫成程式，讓加工機器重複執行；遇到新情境或規則不適用，再回到工作台重新討論。

每次都由模型重新生成整份成果，可能消耗較多資源，也可能產生不必要的變動。將已確認的輸入與製作規則交給程式，可以減少重複生成，提高穩定性與重建能力。實際節省多少依工作而定；重現性也需要固定輸入、程式版本與環境，處理隨機值、時間及外部資料等變動因素。

例如先確認逐頁稿，再由 agent 編寫或使用 Python 程式製作 PPTX。機器人負責建立與操作加工工具，程式負責按規則執行。agent 也可以直接生成文字或操作既有軟體，並非所有成果都必須另外編寫程式。

## 人在工作台上修正，agent 操作加工機器

使用者希望把實體化與製作迭代交給 agent 和加工機器，減少人的逐項操作。人主要檢查成果，將修改回到意圖、草稿、標準或加工規則，再引導 agent 重新製作。

以簡報字太小為例，人可以指出具體問題與閱讀要求，agent 修改排版程式、重建並檢查。要避免的是只手動修改成品、沒有回存源頭，導致下次重新製作又出現同樣問題。具體的回饋仍有價值，也可能是修正规則的重要線索。

程式碼也能經由軟體與設備連接現實世界。使用者舉例，文字可以顯示到螢幕，3D 模型可以經加工指令控制列印設備，逐層製作實體。因此成品可以是文件、畫面或實體；都要確認實際結果是否符合用途。

## 為什麼回到管理與溝通方法

理解工作之後，才能拆出角色與任務、交代目的與標準，並決定如何回饋與驗收。這解釋了使用者最初為什麼想找管理書：從人類既有的分工與協作方法中，找出能幫自己指派 agent 的具體做法。

閱讀時可以問：這個方法幫我把哪一段工作交代得更清楚？再轉成可用的指派方式，以結果確認是否有效。討論中的《教練：價值兆元的管理課》是聯想來源之一，本方法並非直接取自該書。

材料存回文件櫃，確認過的草稿留在工作台，決定與理由寫入工作紀錄；用過有效的標準存入 skills 與 AGENTS.md。這些留下來，下一次協作就能接續。

## 目前的主線與待釐清處

講解入口可以先用「人工 → 數位化 → Agent 化」，說明為什麼要攤開流程、補上數位化條件，以及哪些問題可能用一般工具就能解決。再接到共同工作環境與下列主線：

1. 思考透過外部表達，才能共同處理，但表達存在落差。
2. 用中間產物看見落差，每次轉換都重新對齊，也在擴展中學習；若 A 無法直接到 B，就加入能串起兩者的 C。
3. LLM 的回應受語言與上下文引導，可以借用管理方法說明意圖。
4. 把工作拆成具體角色，讓使用者能指派、檢查與決定。
5. agent 處理模糊與不確定，將明確規則固定成程式。
6. 由加工工具製作成果，人回到源頭修正並驗收。

文件櫃、工作台、機器人與加工機器，是讓這條主線具體可想像的入口。後面的底層說明，用來解釋為什麼需要這種安排。

尚需釐清的部分：

- 「思考沒有直接訓練資料」與「機率生成器」要補概念與研究依據，避免過度簡化模型能力。
- 哪些管理方法轉用後有效，需要實際測試；「派」是否提高使用者主導意識，也需觀察。
- 哪些規則值得程式化，要考慮編寫、維護與重複執行的成本。
- 語言、圖片等不能保證完整傳遞經驗。要區分表達缺口、輸入缺口與模型能力限制；需要實際觀察與操作的部分仍要留下。
- 工具箱的角色分類與 why、what、how 如何配合，以及何時同步到三圈正本，尚未定案。

## 本次討論提及的參考

- [Language Models are Few-Shot Learners](https://arxiv.org/abs/2005.14165)：支持提示中的示例能影響模型任務表現；不直接證實整套管理方法的有效性。
- [Helpful assistant or fruitful facilitator? Investigating how personas affect language model behavior](https://pmc.ncbi.nlm.nih.gov/articles/PMC12208479/)：角色提示對行為與表現的影響；不能只因指定角色就推定品質提升。
- [《教練：價值兆元的管理課》出版社介紹](https://books.cw.com.tw/book/373)：使用者讀過的書，討論中用來聯想傾聽、提問與共同原則；本草稿不是該書摘要，也未宣稱本方法直接來自該書。
