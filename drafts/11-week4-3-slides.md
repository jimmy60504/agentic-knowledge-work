### 4｜Agent 協助的位置

**畫面**

- 主訊息：五個步驟皆可由 Agent 先做一版，人指出錯誤與遺漏。
1. 請 Agent 讀三頁教材、三張講義與 story 圖文法
2. 口述一件工作，由它寫成活動句與文字檔，產出第一版現況圖
3. 請它讀圖，逐一活動回答三個問題，提出候選；採用者畫成第二版
4. 選一段，由它查對照表提出配對與具體操作；評估表由它先列問題與已知條件
5. 紀錄由它整理，人確認內容

**筆記**

圖的任務：無
版型：清單

三張表與兩張圖不必自己逐格完成，可以由 Agent 先做一版。先請它讀三頁教材，包括文末的三張講義與 story 圖文法；再以討論的方式進行。口述一件工作，由它寫成活動句與文字檔，產出第一版現況圖，各位指出何處不符、何處遺漏，至通順為止。請它讀圖，逐一活動回答三個問題，提出候選，各位決定採用者，畫成第二版。挑出一段，由它查動詞對照表提出配對與具體操作，各位補正；評估表由它先列出問題與已知條件，各位逐一回答。表格與圖是討論的紀錄，目的是把想法做出來，不是交出一張填滿的表。

### 5｜選一件工作

**畫面**

- 主訊息：選一件近期完成、正在進行或有意進行的工作；先釐清使用者、用途、完成標準。
- 不必先想出「AI 應用提案」，也不必一開始就完成整張表
- 成果的使用者是誰、用途為何、完成的標準為何
- 研究想法測試：使用者是研究者自己與審閱者；用途是判斷想法是否成立；標準是比較表可重現

**筆記**

圖的任務：無
版型：清單

先選一件近期完成、正在進行，或有意進行而尚未開始的工作。不必先想出「AI 應用提案」，也不必一開始就完成整張表；範圍過大時講師可從對話協助縮小。

選定之後先釐清三件事：成果的使用者是誰，用途為何，如何才算完成。產出文件只是過程，價值要看它是否改善後續的理解、決策或行動。以上午的案例說明：研究想法測試的成果是給研究者自己與審閱者的比較表與結論；用途是判斷想法是否成立、是否值得繼續；完成的標準是比較表可重現，換人以同樣的參數與資料能得出同樣的表。

**原話與來源**

- 「應該說我現在的出發點比較像是要先讓學員有想像，這樣他們會比較能馬上有靈感覺得什麼東西可以用」（09-19 13:58）

### 6｜步驟一：畫第一版現況圖

**畫面**

- 主訊息：與 Agent 畫第一版現況圖：實際完成的一次，不加 Agent，不畫應然。
- 口述一次：自何事開始、經過何人與何系統、交出何物、交予何人
- Agent 列出演員、工作物件、活動句；逐句確認，自 1 號讀至最後，至通順為止
- 圖上另以註記標出：等待、重做、出錯、缺資料、無法決定之處；現有的材料、紀錄與版本
- 文字檔與圖存入自己的 repo；此圖即工作單上區
- 圖下：
1. 研究者 寫下 研究問題
2. 研究者 依研究問題向 文獻資料庫 檢索出 論文清單
3. 研究者 閱讀論文清單並與同事討論後選定 方法與評估指標
4. 研究者 向 資料管理者 申請並整理成 整理後資料
5. 研究者 依方法與評估指標撰寫 程式碼
6. 計算環境 以整理後資料執行 程式碼，產出 結果圖表
7. 研究者 對照現行方法整理 結果圖表，製成 與現行方法的比較表
8. 研究者 檢視比較表後調整 程式碼
9. 研究者 依 比較表 歸納出 結論
10. 研究者 依 結論 撰寫 報告
11. 審閱者 審閱 報告，寫出 審閱意見

**筆記**

圖的任務：研究流程的第一版現況圖作為例子，不加記號；圖檔 `slides/story/research-idea-class.svg`
版型：案例

工作單上區以第一版現況圖代表，步驟與上午第 5 至 7 頁的現場操作相同：口述、列句、產圖、讀一遍、退回一句、重產，題目換成自己的工作。口述實際完成的一次：自何事開始、經過何人與何系統、交出何物、交予何人；Agent 列出演員、工作物件與活動句，各位逐句確認，圖產出後自 1 號讀至最後，不通順之處回到句子修改。

原本上區的五欄，在圖上各有位置。流程與系統即圖上的演員與活動，系統畫成演員，人工搬運、輸入、重新整理之處會以活動出現。痛點以註記標在活動旁：何處等待、重做、出錯、缺資料或無法決定，並追問原因、影響上下游何處、能否提早發現。數據以工作物件表示：現有的材料、紀錄與版本，能否取得。可能留到步驟二。目的是讓自己與講師看見同一件工作；可以追問問題的性質：偶發或反覆，屬於資訊流動、決策權或工作習慣，但不要求做完整個組織的診斷。

- 「做出第一版是現況，然後再跟 agent 開始討論評估看看 agent 介入的可能性」（09-22）
- 「第五欄 會有哪些可能」（09-19 15:27，使用者辨讀照片補的欄名）
- 「這兩張是當時去聽演講，他們有個工作坊的架構，你看一下有沒有可以參考的」（09-19 15:27）

### 7｜步驟二：討論介入，畫第二版

**畫面**

- 主訊息：請 Agent 讀現況圖，逐一活動回答三個問題；採用的候選畫成第二版。
- 先自行標出三種活動：無法銜接的、每次相同的、由人決定的
- 給 Agent 的材料：現況圖的文字檔、六種介入方式、動作詞彙
- Agent 提出候選，人以三個問題退回：執行何種動作、留下何種產物、人在何處驗收
- 第二版：Agent 作為演員畫入圖中；第一版保留，兩版並列，差異即介入的範圍
- 圖下：
1. 研究者 寫下 研究問題，交給 Agent
2. Agent 依研究問題向 文獻資料庫 檢索出 附來源的論文清單
3. 研究者 閱讀論文清單並與同事討論後選定 方法與評估指標（核准點）
5. Agent 依方法與評估指標草擬 程式碼
6. Agent 以整理後資料於 計算環境 執行程式並填寫 逐次實驗紀錄表
7. Agent 依 紀錄表 製成 比較表
8. 研究者 檢查紀錄表與比較表後核准或退回 比較表
9. 研究者 依 比較表 歸納出 結論（核准點）
10. Agent 依 結論 草擬 報告草稿
11. 研究者 修改 報告草稿，送交 審閱者

**筆記**

圖的任務：研究流程的第二版作為例子，Agent 為演員，選定方法與歸納結論為核准點；圖檔 `slides/story/w42-v2-agent.svg`
版型：案例

先自行在第一版上標出三種活動：無法銜接的，上一個物件交到下一個活動無法繼續；每次相同的，輸入整齊、規則固定、執行多次；由人決定的，選定方法、歸納結論、定稿。再把圖交給 Agent，給它現況圖的文字檔、六種介入方式的說明與動作詞彙，以日常語句詢問：這是我目前的工作流程，哪幾個活動你可以接手，各留下何物供我檢查。Agent 一般會全數接手，以三個問題逐一退回，三題皆能回答的活動才列為候選。

採用的候選畫成第二版：Agent 成為圖上的一個演員，箭頭上的動詞用動作詞彙的十個詞，交出的物件寫明；由人決定的活動標為核准點。第一版不予覆蓋，兩版並列，差異即介入的範圍，也是步驟四評估的對象。

**原話與來源**

- 「再跟 agent 開始討論評估看看 agent 介入的可能性」（09-22）
- 來源：[[domain-storytelling]]；[[agent-use-patterns]]

### 8｜步驟三：拆一段

**畫面**

- 主訊息：從第二版挑一段，查動詞對照表，填工作單下區六欄。
- 一段：起點與終點明確、交付對象特定的相鄰幾個活動
- 六欄：工作段、通用動詞、相似用法、Agent 具體操作、中間產物與完成證據、誰驗收
- 完成證據與誰驗收無法填寫的段，通常不適合交付；無法填寫是一項判斷結果
- 比較三種做法：調整流程、一般程式或既有軟體、Agent；規則固定者先考慮前兩種

**筆記**

圖的任務：無
版型：清單

從第二版挑出一段。一段是指起點與終點明確、交付對象特定的相鄰幾個活動，不是整件。以研究想法測試為例，「依方法與評估指標撰寫程式，以整理後資料執行，製成與現行方法的比較表」是一段；「自寫下研究問題至收到審閱意見」是整件。

查動詞對照表，填工作單下區六欄：工作段、通用動詞、相似用法、Agent 具體操作、中間產物與完成證據、誰驗收。第五欄與第六欄無法填寫的段，通常不適合交付；工具呼叫成功只證明該步驟完成，寫不出完成證據便無法判斷業務是否完成。無法填寫是一項判斷結果，值得記下。

填完比較三種做法：調整流程、一般程式或既有軟體、Agent。規則固定、輸入整齊的段先考慮前兩種，固定計算與專業模擬不必改為語言模型；需要理解材料、處理例外、產生可審閱成果的段，才是 Agent 較有價值的位置。再以上午的 A、C、B 檢查這一段缺少哪一個可檢查的節點，指出人負責哪個決定、Agent 接哪一段、工具做什麼；六種介入方式可供對照，這一段適合對話、交辦、製作工具、結構化判斷、流程指派 Agent，或 Agent 管理流程。

收益自三個方向檢視，可以並存：降低既有成本，同樣成果能否減少查找、搬運、製作與返工的時間；強化人的能力，能否比較更多證據、探索更多方案、提早發現問題；讓新工作可行，哪些想做卻無力維護的工作現在可以持續進行，知識管理即屬此類。講師在這一步補充未想到的做法，是否符合現場由各位判斷。

**原話與來源**

- 「有時候問題可能也不需要到 ai，就在數位化過程就先被解決了」（09-18 14:37）

### 9｜步驟四：評估

**畫面**

- 主訊息：評估之前先確認收益屬實：若無 Agent，這件事是否仍會進行。
| 面向 | 問題 |
|---|---|
| 收益 | 節省時間、判斷品質提升、新工作可行 |
| 條件 | 資料位置、結構是否清楚、權限、流程進度、結果存放位置 |
| 新增成本 | 工具、整理、交辦、查核、返工、維護；審查者負擔是否增加 |
| 風險 | 錯誤被採用、誤操作、資料使用不當、過時資訊；承擔者 |
| 累積成果 | 下次可用的資料、方法、標準、已知失敗條件 |

- 非 ROI 試算表；未實測的收益視為假設

**筆記**

圖的任務：無，表格即畫面
版型：總覽

評估之前先問兩句，確認收益屬實：若無 Agent，這件事是否仍會進行？目前沒有 Agent，是如何完成的？兩句皆無法回答，代表這一段是為了使用而使用，並非有人受困，先不採用。數發部手冊 2.2「避免為導入 AI 而 AI」即是這一條。網路上分享的用例多數是為了示範，不能當作收益的依據。

以評估表對拆出的這一段做一次評估，五列各是一組問題，不是必填的試算表。條件問五件事：資料在何處、能否在允許範圍內取得；欄位、單位、詞義與版本是否一致；誰能讀、誰能改、哪些動作須核准；目前到哪一步、下一步交予誰、例外由誰處理；成品、修改、依據與未解決事項存於何處。條件可以在小範圍試作中逐步補足，不要求先整理全組織的資料。

新增成本問工具費、資料整理、交辦、查核、返工、協調與維護各需多少，以及產出加快之後審查者的負擔是否增加。產出者更快可能使審查者更慢，須檢視成果被使用之前的整段流程。風險問錯誤被採用、誤操作、資料使用不當、過時資訊被反覆引用各由誰承擔，以及誰受益、誰增加工作、出錯由誰處理。累積成果問下次可用的資料、方法、標準與已知的失敗條件。沒有基準或尚未實測的收益先視為假設，不把廠商的百分比換成自己的效益預估。

- 「好像為了玩 bot 硬要去做的一件事情……不需要說一定要大家就是要把所有東西都換成 agent 才夠跟得上時代，而是真的用了會發現不一樣才換」（09-21，起點測試）

### 10｜步驟五：試作與紀錄

**畫面**

- 主訊息：選一小段可檢查、可修改的工作試作，最後留下一段紀錄。
- 條件允許即當場試作；缺資料或權限則寫明要驗證什麼、如何觀察
- 紀錄回答四個問題：嘗試內容、採用或放棄的項目、理由、下次沿用的材料
- 材料與洞見存文件櫃、工作稿存工作台、確認有效的標準寫入工作規則；兩版圖的文字檔一併保存
- 回到工作之後的測試：試用一段時間後停止，觀察是否有人要求恢復

**筆記**

圖的任務：無
版型：清單

選一小段可檢查、可修改的工作試作。條件允許即當場進行；缺資料或權限則寫明要驗證什麼、如何觀察。可以比較原做法與新做法的總時間、品質、返工與檢查負擔；未完成即留下受阻之處，不以做出完整系統為目標，也不安排課後作業。

最後回答四個問題：這次嘗試了什麼，採用或放棄了什麼，理由為何，下次可以直接沿用哪些材料或標準。失敗的條件同樣值得保存，暫時的發現不直接寫成永久規則。可以由 Agent 整理成一小段紀錄，各位確認內容；保存時分清原始材料、對作者意圖的推論、自己的洞見、Agent 的提案。材料與洞見存文件櫃，工作稿存工作台，確認有效的標準寫入工作規則，採用與放棄的理由記下；兩版圖的文字檔一併保存，下次修改流程時自此改起。存放位置分開，下次才能找到。

回到工作之後還有一個成本最低的測試：試用一段時間後停止，觀察是否有人要求恢復。確有收益的用法停止後會有人反映；為了使用而使用的停止後無人注意。由上而下推行的用法，經過一段時間多半回到原狀；2026 年幾家大型企業把使用量納入考核又撤回，原因即在此。是否更換做法，依據是自己試出的差異，不是使用量，也不是他人的分享。
