## 主軸

幫學員整理一下目前自己的業務有沒有可以用 Agent 幫忙的地方。為了能分析，先講 Agent 怎麼動、能站在流程的哪裡、一段工作怎麼從 A 走到 B；再從三個角度看業務：別人怎麼用 Agent 幫工作、Agent 到底做了哪些具體操作、地震業務翻成能和其他場景比較的通用語意。三個角度是一組配對工具：別人的用法是用通用語意寫的，自己的業務翻成通用語意之後兩邊才對得上，對上以後再看那個用法裡 Agent 具體做了什麼，判斷自己這一段能不能照做。

前半給工具，後半教配對，工作坊學員對自己的工作做同樣的事。

## 一、Agent 的運作機制（15 分）

目的是建立對機器的正確想像，避免把「寫出指令」當成「做完了」。

模型主要產生文字形式的內容與動作描述，可能是一段指令、程式碼，或符合工具規格的結構化呼叫。它本身沒有手去按滑鼠，也不會只因為寫出「寄信」兩字就真的寄出。執行框架預先接好可用工具與執行規則：收到模型的工具呼叫後檢查權限，交給對應的程式執行，再把結果送回模型；模型依結果提出下一步。

```text
人的目標／事件
    ↓
模型讀取文字脈絡，產生回答或工具呼叫（名稱＋參數／指令）
    ↓
執行框架呼叫預先接好的工具：終端機、程式、API、瀏覽器、滑鼠等
    ↓
工具真的讀取、計算、點擊、寫入或傳送，回報結果／錯誤
    ↓
模型依回饋繼續操作、請人確認，或交付成果
```

**最小例子：建立一個 Markdown 檔。** 模型先決定檔案放哪裡、叫什麼、寫哪些內容，必要時先呼叫工具查目錄；產生 Markdown 文字並提出「建立這個路徑的檔案」的工具呼叫，這一步仍只是文字與參數；執行框架交給檔案工具或終端機，底層程式真的寫入位元組；工具回傳結果，模型再讀檔確認檔案存在、內容正確。單獨的模型可以寫出 Markdown 內容，無法僅靠生成文字在本機建立檔案。

投影片同理：模型先寫逐頁稿與程式，執行框架跑程式產出 PPTX，再開檔檢查。

**回到案例。** Agent 讀目錄與報次紀錄是讀取工具，算差異是寫程式並執行，產表與圖是執行程式寫檔，年報段落是草擬，送審是詢問核准與傳送。每一步都分成提出動作、執行動作、驗證結果三件事。

## 二、Agent 的介入方式（20 分）

目的是讓學員知道 Agent 可以站在自己流程的哪個位置，以及站進去之後留下什麼。依 [筆記](../kb/tools/agent-operation-output-business-map.md)「介入方式」一段。

| 接手方式 | Agent 接手到哪裡 | 年度成效統計的例子 | 最後留下什麼 |
|---|---|---|---|
| 人向 Agent 請教 | 人在正式流程之外發問，Agent 回答後退出 | 同仁問時效與誤差的定義及往年慣例，自行計算 | 可審查的建議 |
| Agent 完成一次性交付 | 用工具查找、寫檔、驗證，交出檔案後退出 | 產出去年的統計表、分布圖與逐事件 CSV | 可審查的檔案 |
| Agent 建置工具後退出 | 建置時產生程式或規則，之後由一般程式執行 | 寫好篩選事件與計算誤差的腳本，之後每年重跑 | 程式；運行時沒有 Agent |
| 固定節點呼叫一次模型 | 既有程式把輸入送給模型取回結果，照固定路徑走 | 腳本把報次紀錄文字送去擷取第一報時間與規模，再交原流程計算 | 欄位；模型參與但不是 Agent |
| 流程節點呼叫 Agent | 事件到達時 Agent 查資料、選工具、迭代，交給下一節點或人 | 每次規模 5 以上事件後，Agent 取報次與報告算差異補一列，標異常交承辦 | 改變流程狀態的產物 |
| Agent 協調跨節點工作 | 按回饋選擇下一步，跨系統查找、建待辦、等核准並追蹤 | 從逐事件補列、年底彙整、產圖表、寫段落、送審到修改由 Agent 串接 | 系統狀態改變與持續追蹤 |

講到這裡順手把案例的五步標出來：讀取、計算、確認、產出、保存。六種方式接手的是其中哪幾步，一目了然。

三個重點。第一，這不是按數字遞增的能力等級：建置時接手很多工作，也可能讓 Agent 在運行時完全退出。第二，接手範圍與寫入權限要分開看，節點 Agent 可以設成只讀、只建草稿、經人核准後才寫入。第三，「最後留下什麼」分三組：可審查的內容或檔案、改變外部系統或人的工作狀態、持續運行的服務；後兩組要另外確認權限、錯誤處理、紀錄與回復。

## 三、從 A 到 B（25 分）

目的是給學員一個拆工作的方法。核心只有一件事：中間節點 C 是什麼、怎麼找、找到之後誰做。

**思考外部化（5 分）。** 人心裡的想法轉成文字、口述與畫面時經過選擇與組織；對方看到的是表達，無法直接取得完整意圖。協作因此需要一個可共同查看的中間產物。先請 agent 把目前理解整理出來，人才能指出哪裡漏掉、誤解或還沒決定。人的想法也會隨新材料與試做結果改變；回饋是在共同釐清，不只是把模型拉回第一次說法。

保留使用者要求記下的表述：

> LLM 學過大量人類語言與互動模式。我們可以借用溝通、管理與教練的方法，把意圖、背景、分工與標準說清楚，提高它產生合適回應的機率。

互動像同事或教練，不代表模型具有人的動機或責任。可用的三分鐘短示範：先說零散想法，請 agent 寫成一段，現場指出一個偏移，補充理由並重寫。

**A→C→B（10 分）。** 先看目前有什麼 A、希望得到什麼 B。若不能清楚交代或可靠完成 A 到 B 的轉換，就找中間節點 C，把工作拆成 A → C → B。C 可以是資料、決定、規格、草稿或試作結果；它要補上一個具體缺口，讓下一步有依據，也讓人能檢查。加入多少層取決於任務、人的理解與工具能力；同一層可以反覆修改。

三個例子。想法直接變簡報而主張與順序還不清楚，C 是結構化文稿，人檢查背景、目的、主張與依據是否成立。文稿轉成簡報而不知每頁用途，C 是逐頁稿或 ghost deck，人檢查邏輯能否連讀、證據與口述放哪裡。事件清單直接變年度統計而多報次與異常事件還沒處理，C 是逐事件差異表附納入排除註記，人檢查取哪一報、哪些排除、數字能否重算。

前兩個是第二週，三圈就是三個 C：文稿、逐頁稿、成品，定義以 [ssot v3](../ssot/three-loops.md) 為準，一句帶過。第三個是本週案例：從事件清單到年度統計之間，缺的 C 是逐事件差異表。

找 C 的來源不只一種：問 AI、請 AI 搜尋、自己讀資料或請教他人、觀察現場與親自試做。先把 agent 的建議當候選，再用材料或試作確認。成品出現內容問題時，回到適當的草稿層修正，不是每次都在版面上重做。

**找到 C 之後誰做（10 分）。** 三個分工原則：

- 同一個 Agent 在一件工作裡輪流當討論者、整理者、記錄者、審查者、起草者、操作員。請教時帶著自己的意見去問，交辦時說明目的、要的結果、限制與檢查標準，做法讓它選。不要求開六個 Agent，也不保證換角色稱呼就會提高品質。
- 模糊的交 Agent，明確的交程式。保留使用者的話：「讓 agent 去處理模糊不確定的東西，然後把明確規則收斂成程式碼讓他可以重複執行。」課程自己的例子是先讓 Agent 把逐頁稿討論定，再用一支程式把逐頁稿產成 PPTX；內容有問題改逐頁稿，版面有問題改程式。案例上，篩選與計算的規則確定後寫成腳本每年重跑，哪些事件納入、異常怎麼解釋仍由人判斷。
- 人核准哪一步要先講好。判定與高影響處置由有權責的人決定；Agent 列依據、選項與疑點。

## 四、別人怎麼用 Agent 幫工作（20 分）

目的是給靈感，同時給判斷依據。依 [用法樣式筆記](../kb/tools/agent-use-patterns.md)；學員講義為 [動詞對照表](06-week4-student-handouts.md)，樣式與工作動詞的配對已做在表上。投影片不放整張表，只投其中三到四列的「對應的用法樣式、Agent 具體操作、中間產物與完成證據、人驗收什麼」四欄。不放來源，不點名產品。

講課挑四種樣式走完拆法：第一版初稿（就是案例）、跨來源整理成研究底稿、例行詢問的答覆、定期監看與條件提醒。其餘六種只列名稱，說明講義上有完整表可查。

講法是每種樣式先說它在做什麼事（通用動詞），再拆開看 Agent 具體做了哪些操作、中間留下什麼、完成證據是什麼、人驗收什麼。例如第一版初稿是分析加報導，操作是蒐集素材、寫程式或分析、形成可檢查的檔案，完成證據是檔案能開、能跑、數值可重算，人設定標準、接受或退回。這一種正好就是年度成效統計，講到這裡讓學員發現自己的案例在別人那裡有對應。

講完把操作收成十個動作動詞：讀取、查找、擷取、比對、計算、草擬、寫程式、執行寫入、通知交接、詢問核准、驗證。前六個留下可審查的檔案，執行寫入與通知交接改變外部狀態，詢問核准把決定交回人，驗證是回讀結果確認真的做了。這是後面拆自己工作時的詞彙，不另立一段。

最後一句提醒：工具呼叫成功只證明那一步，不能代表整項業務完成。統計表產出了不代表數字經過確認，年報段落寫好不代表已審核通過，送出審核不代表承辦已接手。拆工作時要寫得出完成證據。

外部案例的普及程度與成效數字不講；學員問起時說明案例為業者自述，多數組織尚未在單一功能規模化。

## 五、地震業務翻成同樣的語意（15 分）

目的是讓學員把自己的工作翻成能和第四段配對的通用動詞。依 [工作類型筆記](../kb/reference/cwa-earthquake-center/cwa-earthquake-center-work-types.md)。

十種工作動詞：守視發現、查核判定、通報發布、回答解釋、提供資料、整理保存、分析研究、維護設備、維護系統、規劃管考。投影片投 [動詞對照表](06-week4-student-handouts.md) 前三欄：動詞、在地震業務中實際是什麼、相近的外部工作語意。例如守視發現相近於監控中心看告警，回答解釋相近於客服與科普，維護系統相近於 IT 維運。說明這是公開職掌與年報的歸納，不是 SOP，請學員當場修正；修正本身就是互動。

接著打開對照表第四欄「對應的用法樣式」：守視對到事件初篩與定期監看；回答解釋對到例行詢問答覆；整理保存對到文件抽欄位與研究底稿；維護系統對到遠端程式修改；規劃管考對到定期摘要與跨工具流程推進。配對已做在表上，講課只點兩三列說明怎麼看；對得上只表示有別人做過的做法可參考，能不能做還要看資料、權限與驗收人。

把案例放回動詞表：年度成效統計跨了整理保存、分析研究、通報發布三個動詞，分別由不同人負責。這是第六段「一段」與「整件」的差別。

## 六、收尾與接工作坊（10 分）

**用案例走一次配對三步（6 分）。** 投影 [工作單](06-week4-student-handouts.md) 下區，講師用年度成效統計填：

| 欄 | 案例填法 | 來自哪一段 |
|---|---|---|
| 我的工作段 | 從地震目錄挑出去年合條件的事件，逐件算差異，做成表與圖交年報承辦 | 引子 |
| 通用動詞 | 整理保存、分析研究，接到通報發布 | 第五段 |

填完指出兩件事。一是下區填的是一段，不是整件業務；下午先用工作單上區攤開整件工作，再挑一段填下區。二是「誰驗收」與「完成證據」填不出來的，通常就是不適合交出去的段。

**做完留什麼（2 分）。** 一頁：材料與洞見存文件櫃，工作稿存工作台，確認有效的標準寫進工作規則，採用與放棄的理由記下來；存的時候分清原始材料、對作者意圖的推論、自己的洞見、Agent 的提案。完整位置以 [專案結構正本](../ssot/project-structure.md) 為準，不要求學員複製整套資料夾。工作坊操作引導四展開。

**接工作坊（2 分）。** 學員拿三張講義：動詞對照表、工作單、評估表。各選一件近期做過或想做的工作；工作單上區攤開現況；挑一段查對照表填下區；比較流程調整、一般程式、Agent 三種做法；用評估表看收益、條件、成本、風險、累積；條件允許就現場試一小段；最後留一小段紀錄。沒有題目的人有備援題。講師巡視，不投影同步時間表。成果不用繳交、不上台，能說清楚一個用途的目的、條件、代價與驗證方法就算有收穫。
