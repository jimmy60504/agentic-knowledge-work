先看四個公開實例，皆為業者自述的案例，不點產品名，重點在做法。第一個是保險公司的員工福利問答與軟體公司自家的 IT 服務台：員工反覆詢問同一套規定，Agent 查找知識庫、依個案回答，無法回答的摘要後轉交真人；人維護知識庫、處理例外、抽查答覆。第二個是投資機構的研究助理：資料分散於報告、新聞與資料庫，Agent 跨來源檢索、整理相互矛盾的資料、附來源起草底稿；人定義問題、檢查證據、決定結論。第三個是資安公司的警報分析：警報量大，人力難以逐件查閱脈絡，Agent 彙集事件紀錄、查找相似案例、初步分級、建議調查方向；人確認實際風險、修正分級規則。第四個是合約資料擷取：Agent 讀取 PDF、擷取欄位、標記非標準條款與原文位置後交財務審核；人審核例外、決定處置。

### 4｜拆解的原則

**畫面**

- 主訊息：任何用法皆可依三個問題拆解：Agent 執行何種動作、留下何種產物、人在何處驗收。
- 動作十個、產物四類、驗收點分事前與事後
- 三題皆能回答的段可寫入工作單；無法回答的那一題，即是尚不能交付的原因

**筆記**

圖的任務：三個問題並列成三格，每格之下標答案的範圍：十個動作、四類產物、事前與事後
版型：對比

四個實例看似四件不同的事，拆解之後結構相同。原則是三個問題。第一個問題，Agent 執行何種動作：查找、讀取、擷取、比對、計算、草擬，動作的種類有限。第二個問題，留下何種產物：一份答覆、一份底稿、一張事件卡、一張欄位表，產物決定人拿到手上能否檢查。第三個問題，人在何處驗收：事前設定標準、門檻、範圍，事後檢查、接受或退回。三個問題答完，一個用法即拆解完成。

這個原則的用處在後面。下午拆解自己的工作，不必逐一比對十種樣式，直接回答三個問題：這一段 Agent 執行何種動作、留下何種產物、自己在何處驗收。三題皆能回答，這一段即可寫入工作單；無法回答的那一題，就是這一段尚不能交付的原因。下一頁把第一個問題的動作整理成一組固定的詞。

**原話與來源**

- 「如果是一個一個示範去拆會不會有點太像是要每個都做一次的枯燥感，還是說有辦法找出一個大原則來講會比較好，然後大原則講完自己就比較能推出下面」（09-21）
- 「你有辦法從下到上完整說明一下 agent 的具體操作有哪些，然後整理出 agent 產出方式，再來到這些產出方式變成業務上的動詞的連接」（09-19 17:38）

### 5｜Agent 的動作詞彙

**畫面**

- 主訊息：Agent 的操作收成十個動詞，依留下的結果分四類。
| 留下的結果 | 動作 |
|---|---|
| 可審查的檔案 | 讀取、查找、擷取、比對、計算、草擬、寫程式 |
| 改變外部狀態 | 執行寫入、通知交接 |
| 決定交回人 | 詢問核准 |
| 確認已執行 | 驗證 |

**筆記**

圖的任務：無，表格即畫面
版型：總覽

四個實例中 Agent 的操作，整理為十個動作動詞：讀取、查找、擷取、比對、計算、草擬、寫程式、執行寫入、通知交接、詢問核准、驗證。依留下的結果分為四類。前七個留下可審查的檔案，四個實例的動作多數屬於這一類。執行寫入與通知交接改變外部狀態，例如轉交真人、建立工單，第一個實例的最後一步即屬此類。詢問核准把決定交回人，合約實例中非標準條款交財務審核即是。驗證是回讀結果，確認動作確實完成。

下午拆解自己的工作，「Agent 具體操作」一欄以這十個詞填寫。外部做法配對成功之後，自己的那一段要能以這十個詞描述，才算真正對接。

**原話與來源**

- 「你有辦法從下到上完整說明一下 agent 的具體操作有哪些，然後整理出 agent 產出方式，再來到這些產出方式變成業務上的動詞的連接」（09-19 17:38）

### 7｜對接：動詞與用法

**畫面**

- 主訊息：兩邊使用同一組詞，即可對接。
| 動詞 | 對應的用法 |
|---|---|
| 守視 | 事件初篩、定期監看 |
| 回答解釋 | 例行詢問答覆 |
| 整理保存 | 文件抽欄位、研究底稿 |
| 分析研究 | 研究底稿、第一版初稿 |
| 維護系統 | 遠端程式修改 |
| 規劃管考 | 定期摘要、跨工具流程推進 |

- 研究想法測試：分析研究，對應研究底稿與第一版初稿

**筆記**

圖的任務：無，表格即畫面
版型：總覽

兩邊使用同一組詞，即可對接。對照表第四欄「對應的用法樣式」是配對的結果：守視對應事件初篩與定期監看，回答解釋對應例行詢問答覆，整理保存對應文件抽欄位與研究底稿，分析研究對應研究底稿與第一版初稿，維護系統對應遠端程式修改，規劃管考對應定期摘要與跨工具流程推進。配對已完成於講義，各位只需查找自己的動詞。

以研究想法測試套用：主體是分析研究。找文獻對應研究底稿，論文清單每一條可回到來源；寫程式、跑資料、分析對應第一版初稿，結果圖表與結論初稿能否重現是完成證據。再以三個問題檢核一次：動作是查找、讀取、計算、草擬；產物是附來源的清單、可重跑的程式、結果圖表；驗收在事前選定方法與參數、事後由研究者判斷結果可信與否。

配對成功，只表示外部已有做法可供參考；能否執行，仍須視資料、權限與驗收人而定，那是下午的工作。配對完成、位置確定之後，還有一個實務問題：Agent 往往無法直接產出所需結果。下一段說明如何處理。

**原話與來源**

### 8｜Story 圖怎麼畫

**畫面**

- 主訊息：三個元素畫一張圖：演員、工作物件、編號活動。
- 演員：人、單位或系統；工作物件：文件、資料、對話等被傳遞的東西；活動：帶編號的箭頭，寫成動詞
- 一張圖講一個具體案例，從 1 號活動讀到最後，能念成一段話
- 顆粒度可調：粗的講整件事，細的講一段

**筆記**

圖的任務：以上半場第 3 頁的研究者圖為例，標出三個元素各是圖上的哪一種記號
版型：流程

上半場那張研究者的圖是這樣畫的：演員是研究者，工作物件是論文清單、主要方法、程式碼、結果圖表、分析結論、報告，活動是找文獻、選方法、寫程式、跑資料、分析、寫報告，各有編號。這種畫法叫 domain storytelling，元素只有三種，畫的時候一次講一句話：誰，做了什麼，交出什麼。從 1 號讀到最後，整張圖能念成一段話，念不順的地方就是圖畫錯或事情沒想清楚的地方。

一張圖只講一個具體案例，不畫所有分支；有分支就多畫一張。粗顆粒講整件事，細顆粒講其中一段。下午攤開自己的工作，就是畫一張粗的，再挑一段畫細的。畫圖可以請 Agent 幫忙：口述一遍，由它列出演員、物件、活動，各位改。

### 9｜從圖上找缺口

**畫面**

- 主訊息：畫完之後看兩件事：哪一步接不上，哪一步每次都一樣。
- 接不上的活動：物件說不清、判斷沒依據；這裡需要中間節點
- 每次都一樣的活動：規則固定、輸入整齊；這裡可以收成程式，或交給 Agent 反覆執行
- 由人決定的活動：選方法、下結論、定稿；留給人，標出核准點

**筆記**

圖的任務：同一張研究者圖，用三種記號標出接不上的活動、每次都一樣的活動、由人決定的活動
版型：流程

圖畫出來之後，看兩件事。第一，哪一步接不上：上一個活動交出的物件，下一個活動拿到手上做不下去。例如結果圖表直接變成結論，中間沒有交代參數與例外，這一步就接不上；接不上的地方需要一個中間節點，這是本段後面要講的 C。第二，哪一步每次都一樣：輸入整齊、規則固定、做過很多次，例如跑資料；這種活動可以收成程式，或交給 Agent 反覆執行，是上半場講的製作工具與流程指派。第三，由人決定的活動：選方法、下結論、定稿；這些不交出去，但要在圖上標成核准點，讓 Agent 做到這裡停下。

三種記號標完，一件工作可以交出去的段、要補中間節點的段、留給人的段就分開了。這比對照表更直接，因為是從自己的工作看出來的，不是從別人的用法對回來的。

**原話與來源**

### 12｜中間節點 C

**畫面**

- 主訊息：A 到 B 無法說清或做不可靠，即找 C。
- C 可為資料、決定、規格、草稿或試作結果，條件是人可檢查
- 找 C 的來源：詢問 AI、請 AI 搜尋、自行閱讀、請教同事、實地觀察、親手試作
- 需要幾層視任務、人的理解與工具能力而定；同一層可以反覆修改

**筆記**

圖的任務：A → C → B 三格橫排，C 加粗；讓人看出 C 是插在 A 與 B 之間、可以檢查的一站
版型：流程

B 定義為完成證據之後，常會發現 A 無法直接到達 B。先說明原因。人的想法轉為文字或畫面時經過選擇，對方看到的是表達，不是意圖；人與人如此，人與 Agent 亦然。因此協作需要一個可以共同檢視的中間產物：一段整理、一份有依據的文稿、一張比較表、一個具體的問題描述。LLM 學過大量人類語言與互動模式，可以借用溝通、管理與教練的方法，把意圖、背景、分工與標準說清楚，提高它產生合適回應的機率。互動形式像同事或教練，不代表它具有人的動機或責任。

再說明如何尋找。目前有何材料是 A，希望得到何種結果是 B。A 到 B 無法說清或做不可靠，即找一個中間節點 C，把工作拆為 A 到 C、C 到 B。C 可以是資料、決定、規格、草稿或試作結果，條件是補上一個具體缺口、讓下一步有依據、讓人能檢查。需要幾層視任務、人的理解與工具能力而定；同一層可以反覆修改。找 C 的來源不止一種：詢問 AI、請 AI 搜尋、自行閱讀、請教同事、實地觀察、親手試作。Agent 的建議先視為候選，再以材料或試作確認。成品出現內容問題，回到適當的草稿層修改，不在版面上重做。

時間允許時可放三分鐘示範：先說幾個零散想法，請 Agent 寫成一段，當場指出一處偏移，補上理由，請它重寫。時間不足則略過，以下一頁的例子替代。
