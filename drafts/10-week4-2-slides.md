**筆記**

上半場講的是 Agent 的用法：它怎麼動、六種介入方式。下半場回到業務，最後也講站進去之後一段工作怎麼接。三個角度是一組配對工具。別人的用法是用通用語意寫的：守視、查核、解釋、整理。自己的業務翻成同樣的語意之後，兩邊才對得上。對上以後再看那個用法裡 Agent 具體做了什麼，判斷自己這一段能不能照做。

| 人驗收 | 設定標準、執行測試、接受或退回 |

**筆記**

講義的動詞對照表，一列一個工作動詞，後四欄寫別人怎麼用 Agent 做這類事、Agent 具體做什麼、中間留下什麼、人驗收什麼。這張表不是產品功能清單，沒有廠商名稱；目前一般的 Agent 大多有聊天入口、工具呼叫、排程與檔案讀寫，這些用法不是哪個產品專屬。整張表下午再查，現在挑四種走一遍拆法，每種同一個版面：做的事、Agent 操作、完成證據、人驗收。

第一種，第一版初稿。做的事是分析與報導。Agent 蒐集素材、寫程式或分析、形成可檢查的檔案：草稿、程式、測試紀錄。完成證據是檔案能開、能跑、數值可重算。人設定標準、執行測試、接受或退回。這一種正是年度成效統計：統計表、分布圖、年報段落都是第一版初稿，數字能不能重算是完成證據，承辦決定接受或退回。各位的案例，別人已經有對應的做法。

### 9｜完成證據

**畫面**

- 統計表產出了，不代表數字經過確認
- 年報段落寫好，不代表已審核通過
- 送出審核，不代表承辦已接手

**筆記**

一句提醒：工具呼叫成功只證明那一步，不能代表整項業務完成。統計表產出了，不代表數字經過確認；年報段落寫好，不代表已審核通過；送出審核，不代表承辦已接手。每種業務動詞各有完成條件，拆工作的時候要寫得出完成證據是什麼。這是下午填表時「中間產物與完成證據」那一欄。

外部案例的普及程度與成效數字今天不講。有人問起，說明這些案例多為業者自述，調查顯示多數組織還沒在任何一項業務上規模化使用。看它們是看做法，不是看平均效果。

### 13｜中間節點 C

**畫面**

| 卡住的地方 | C | 人檢查什麼 |
|---|---|---|
| 想法直接變簡報，主張與順序不清 | 結構化文稿 | 背景、目的、主張與依據是否成立 |
| 文稿轉簡報，不知每頁用途 | 逐頁稿 | 邏輯能否連讀、證據與口述放哪裡 |
| 事件清單直接變年度統計，多報次與異常未處理 | 逐事件差異表，附納入排除註記 | 取哪一報、哪些排除、數字能否重算 |

- A 到 B 說不清楚或做不可靠，就找 C：A → C → B

**筆記**

先講為什麼需要 C。人心裡的想法轉成文字或畫面時經過選擇，對方看到的是表達，不是意圖；人與人如此，人與 Agent 也一樣。所以協作需要一個可以共同查看的中間產物：一段整理、一份有依據的文稿、一張比較表、一個具體的問題描述。LLM 學過大量人類語言與互動模式，我們可以借用溝通、管理與教練的方法，把意圖、背景、分工與標準說清楚，提高它產生合適回應的機率。互動像同事或教練，不代表它有人的動機或責任。三分鐘示範可以放這裡：先說幾個零散想法，請 Agent 寫成一段，當場指出一處偏移，補上理由，請它重寫。

再講怎麼找。目前有什麼是 A，希望得到什麼是 B。A 到 B 說不清楚或做不可靠，就找一個中間節點 C，把工作拆成 A 到 C、C 到 B。C 可以是資料、決定、規格、草稿或試作結果，條件是補上一個具體缺口、讓下一步有依據、讓人能檢查。要加幾層看任務、看人的理解、看工具能力；同一層可以反覆修改。找 C 的來源不只一種：問 AI、請 AI 搜尋、自己讀、請教同事、到現場、親手試。Agent 的建議先當候選，再用材料或試做確認。成品出了內容問題，回到適當的草稿層改，不在版面上重做。

三個例子。前兩個是第二週做過的：想法直接變簡報，C 是一份結構化的文稿；文稿轉成簡報，C 是逐頁稿。第二週講的三個迴圈就是三個 C，一句帶過。第三個是本週的案例：從事件清單直接變年度統計，多報次與異常事件還沒處理，C 是逐事件差異表附納入排除註記，人檢查取哪一報、哪些排除、數字能不能重算。沒有這張差異表，年度的數字追不回去。這就是下午工作單「中間產物與完成證據」那一欄。

### 14｜C 由誰做

**畫面**

- 引文頁內文：「讓 agent 去處理模糊不確定的東西，然後把明確規則收斂成程式碼讓他可以重複執行。」
- 人核准哪一步，先講定；同一個 Agent 輪流當討論者、整理者、記錄者、審查者、起草者、操作員

**筆記**

有了 C，才有分工的問題。第一，同一個 Agent 在一件工作裡輪流扮演幾種角色：討論者拓展選項，整理者查找來源，記錄者留下決定與理由，審查者找反例，起草者寫可修改的草稿，操作員跑程式並檢查輸出。請教的時候帶著自己的意見去問，讓它給不同方向；交辦的時候說目的、要的結果、限制與檢查標準，做法讓它選。這些是角色，不是要開六個 Agent，換個稱呼也不保證品質提高。用「派」這個字提醒自己做主，不是它給什麼就接受什麼。

第二，人核准哪一步要先講定。判定與高影響的處置由有權責的人決定，Agent 列依據、選項與疑點。這一條在上半場介入方式那幾頁出現過，下午填表時是「誰驗收」那一欄。

第三個分工原則，用原話說：讓 agent 去處理模糊不確定的東西，然後把明確規則收斂成程式碼讓他可以重複執行。需要理解材料、提選項、試做的工作，交給 Agent 探索；規則一旦確定，收成程式或既有工具，可以反覆執行、結果穩定。Agent 直接產成品太耗資源，而且不具重現性，隨機性不能保證每次一致，所以透過程式碼穩定它的輸出。

這門課自己的例子：先讓 Agent 把逐頁稿討論定，再用一支程式把逐頁稿產成 PPTX；內容有問題改逐頁稿，版面有問題改程式，不在成品上手工修。案例上，篩選事件與計算誤差的規則確定之後寫成腳本每年重跑，哪些事件納入、異常怎麼解釋仍由人判斷。程式也有編寫與維護的成本；Agent 也可以直接操作既有軟體，不必每件事都寫程式。

**原話與來源**

- 「一開始 agent 會扮演討論者，還有派出去搜集資料整理的，還有會議記錄者，跟審視想法提問的等等，那後面階段還有去操控加工機器的，沒有這個具體的語意，全部都被包成一個 agent，這樣一般人就很難想像到底可以怎麼運用」（09-18 13:52）
- 「看待 agent，就如他的名字，要思考在工作中該怎麼分工，就可以把目前的想法變成具體的角色去派給 agent 做事情，那用派的這個心裡暗示，使用者就會意識到要自己去做主來控制這些東西」（09-18 13:55）
- 「讓 agent 去處理模糊不確定的東西，然後把明確規則收斂成程式碼讓他可以重複執行」（09-18 13:46）
- 「agent 如果直接產生產物會太耗資源，且不具重現性，就是他的隨機性不能保證每次執行結果是一致的，所以會再透過程式碼去穩定他的輸出」（09-18 13:44）
- 來源：[[presentation-process-before-and-after]]；[[vibe-coding]]

### 15｜工作單：案例

**畫面**

| 欄 | 案例 |
|---|---|
| 我的工作段 | 從地震目錄挑出去年合條件事件，逐件算差異，做成表與圖交年報承辦 |
| 通用動詞 | 整理保存、分析研究，接到通報發布 |
| 相似用法 | 第一版初稿、跨來源整理成研究底稿 |
| Agent 具體操作 | 讀取目錄與報次紀錄、擷取參數、計算差異、比對去年規則、草擬表圖與段落、詢問核准納入排除、驗證可重算 |
| 中間產物與完成證據 | 事件清單、逐事件差異表、納入排除清單；數字可重算、承辦接受、年報審核通過 |
| 誰驗收 | 承辦同仁決定納入排除與異常解釋；年報審核者定稿 |

**筆記**

把上午的東西收在一張表上。講義的工作單分上下兩區，上區攤開整件工作，下區拆一段。現在用年度成效統計填下區，每一欄都在前面出現過：工作段是第 12 頁流程圖裡的一段；通用動詞來自第 10 頁；相似用法來自第 3、4 頁；Agent 具體操作用第 8 頁的動作詞彙；中間產物與完成證據是第 13 頁的 C 加第 9 頁；誰驗收是第 14 頁。

兩件事。第一，這張表填的是一段，不是整件業務；下午先用上區攤開整件，再挑一段填下區。第二，「誰驗收」與「完成證據」填不出來的段，通常就是不適合交出去的段。填不出來不是失敗，是判斷。

### 16｜工作坊的進行方式

**畫面**

- 三張講義：動詞對照表、工作單、評估表
- 選一件工作 → 上區攤開 → 挑一段填下區 → 比較三種做法 → 評估 → 試做一小段 → 留一段紀錄

**筆記**

做完留什麼，一句帶過：材料與洞見存文件櫃，工作稿存工作台，確認有效的標準寫進工作規則，採用與放棄的理由記下來；存的時候分清原始材料、對作者意圖的推論、自己的洞見、Agent 的提案。下午的操作引導四展開。

下午的做法。三張講義：動詞對照表、工作單、評估表。選一件近期做過或想做的工作；上區攤開現況；挑一段查對照表填下區；比較三種做法：調整流程、一般程式或既有軟體、Agent，規則固定的先考慮前兩種；用評估表看收益、條件、成本、風險、累積；條件允許就現場試一小段；最後留一小段紀錄。三張表可以請 Agent 協助填，先讓它讀過三頁教材，再用討論的方式做。沒有題目的人有備援題。不繳交、不上台；能說清楚一個用途的目的、條件、代價、驗證方法，就是今天的收穫。

**原話與來源**

- 「4-3 填表可以提示說可以用 agent 幫忙填，就不會說要自己填很麻煩，而且可以先教 agent 全部讀過一遍後用討論的把這個想法做出來」（09-20 11:03）
