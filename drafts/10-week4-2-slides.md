### 2｜下半場的路線

**畫面**

- 主訊息：下半場分四步：外部用法、地震業務的動詞、畫出現況、從現況討論介入。
- 外部用法：實例、拆解的原則、動作詞彙
- 地震業務的動詞：以同一組動詞描述，對接外部做法
- 畫出現況：以 story 圖畫出自己的工作，由 Agent 協助，第一版只畫現況
- 從現況討論介入：從圖上找缺口，與 Agent 討論介入的位置、完成證據與中間節點

**筆記**

圖的任務：無
版型：清單

上半場說明 Agent 的用法：運作機制、六種介入方式，每一種都以研究流程的 story 圖示範過一次。下半場回到各位的業務，分四步。第一步看外部用法：以網路上可查得的實例，拆解 Agent 的實際操作，歸納出一組動作詞彙。第二步以同一組動詞描述地震業務，兩邊用詞一致，即可對接：自己的哪一段工作，外部已有做法。動詞只能指出外部有做法，工作實際如何流動仍須畫出來，因此第三步介紹上半場那些圖是怎麼畫的：三個元素、一行一句的文法、如何請 Agent 畫、如何把圖修順，做出第一版的現況圖。第四步拿現況圖與 Agent 討論：哪些活動可以介入、完成證據為何、無法直接產出結果時如何找中間節點。這四步即是下午工作坊的順序。

先看四個公開實例，皆為業者自述的案例，不提產品名稱，重點在做法。第一個是保險公司的員工福利問答與軟體公司自家的 IT 服務台：員工反覆詢問同一套規定，Agent 查找知識庫、依個案回答，無法回答的摘要後轉交真人；人維護知識庫、處理例外、抽查答覆。第二個是投資機構的研究助理：資料分散於報告、新聞與資料庫，Agent 跨來源檢索、整理相互矛盾的資料、附來源起草底稿；人定義問題、檢查證據、決定結論。第三個是資安公司的警報分析：警報量大，人力難以逐件查閱脈絡，Agent 彙集事件紀錄、查找相似案例、初步分級、建議調查方向；人確認實際風險、修正分級規則。第四個是合約資料擷取：Agent 讀取 PDF、擷取欄位、標記非標準條款與原文位置後交財務審核；人審核例外、決定處置。

### 4｜拆解的原則

**畫面**

- 主訊息：任何用法皆可依三個問題拆解：Agent 執行何種動作、留下何種產物、人在何處驗收。
- 動作十個、產物四類、驗收點分事前與事後
- 三題皆能回答的段可寫入工作單；無法回答的那一題，即是尚不能交付的原因

**筆記**

圖的任務：三個問題並列成三格，每格之下標答案的範圍：十個動作、四類產物、事前與事後
版型：對比

四個實例看似四件不同的事，拆解之後結構相同。原則是三個問題。第一個問題，Agent 執行何種動作：查找、讀取、擷取、比對、計算、草擬，動作的種類有限。第二個問題，留下何種產物：一份答覆、一份底稿、一張事件卡、一張欄位表，產物決定人取得後能否檢查。第三個問題，人在何處驗收：事前設定標準、門檻、範圍，事後檢查、接受或退回。三個問題答完，一個用法即拆解完成。

這個原則會在第四段再用一次：以自己的現況圖與 Agent 討論時，對圖上每一個活動問這三個問題。三題皆能回答，這一段即可寫入工作單；無法回答的那一題，即是這一段尚不能交付的原因。下一頁把第一個問題的動作整理成一組固定的詞。

**原話與來源**

- 「如果是一個一個示範去拆會不會有點太像是要每個都做一次的枯燥感，還是說有辦法找出一個大原則來講會比較好，然後大原則講完自己就比較能推出下面」（09-21）
- 「你有辦法從下到上完整說明一下 agent 的具體操作有哪些，然後整理出 agent 產出方式，再來到這些產出方式變成業務上的動詞的連接」（09-19 17:38）

### 5｜Agent 的動作詞彙

**畫面**

- 主訊息：Agent 的操作收成十個動詞，依留下的結果分四類。
| 留下的結果 | 動作 |
|---|---|
| 可審查的檔案 | 讀取、查找、擷取、比對、計算、草擬、寫程式 |
| 改變外部狀態 | 執行寫入、通知交接 |
| 決定交回人 | 詢問核准 |
| 確認已執行 | 驗證 |

**筆記**

圖的任務：無，表格即畫面
版型：總覽

四個實例中 Agent 的操作，整理為十個動作動詞：讀取、查找、擷取、比對、計算、草擬、寫程式、執行寫入、通知交接、詢問核准、驗證。依留下的結果分為四類。前七個留下可審查的檔案，四個實例的動作多數屬於這一類。執行寫入與通知交接改變外部狀態，例如轉交真人、建立工單，第一個實例的最後一步即屬此類。詢問核准把決定交回人，合約實例中非標準條款交財務審核即是。驗證是回讀結果，確認動作確實完成。

這十個詞之後有兩個用處。畫 story 圖時，Agent 這個演員的箭頭上所寫的動詞即是這十個；填工作單時，「Agent 具體操作」一欄以這十個詞填寫。外部做法配對成功之後，自己的那一段要能以這十個詞描述，才算真正對接。

**原話與來源**

- 「你有辦法從下到上完整說明一下 agent 的具體操作有哪些，然後整理出 agent 產出方式，再來到這些產出方式變成業務上的動詞的連接」（09-19 17:38）
- 來源：[[agent-use-patterns]]

兩邊使用同一組詞，即可對接。對照表第四欄「對應的用法樣式」是配對的結果：守視對應事件初篩與定期監看，回答解釋對應例行詢問答覆，整理保存對應文件抽欄位與研究底稿，分析研究對應研究底稿與第一版初稿，維護系統對應遠端程式修改，規劃管考對應定期摘要與跨工具流程推進。配對已完成於講義，各位只需查找自己的動詞。

以研究想法測試套用：主體是分析研究。檢索文獻對應研究底稿，論文清單每一條可回到來源；撰寫程式、執行實驗、製成比較表對應第一版初稿，比較表能否重現是完成證據。再以三個問題檢核一次：動作是查找、讀取、計算、比對、草擬；產物是附來源的清單、可重跑的程式、比較表；驗收在事前選定方法與評估指標、事後由研究者判斷結果可信與否。

配對只表示外部已有做法可供參考。動詞是類比，只能說明這件工作屬於哪一類，無法說明這件工作在自己單位裡經過何人、交出何物、受阻於何處。要看出這些，須把工作畫出來。下一段說明上半場那些圖是怎麼畫的。

### 8｜Story 圖的三個元素

**畫面**

- 主訊息：一張 story 圖只有三個元素：演員、工作物件、編號活動。
- 演員：人、單位或系統；文獻資料庫、計算環境亦屬演員
- 工作物件：文件、資料、對話等在演員之間傳遞的物件
- 活動：帶編號的箭頭，寫成動詞；自 1 號讀至最後，整張圖可讀成一段敘述
- 一張圖描述一個具體案例，不畫分支；粗顆粒描述整件，細顆粒描述一段

**筆記**

圖的任務：以研究流程圖的前兩句為例，以註記標出演員（人、系統）、工作物件、編號活動；圖檔 `slides/story/w42-elements.svg`
版型：流程

上半場的研究流程圖依此畫成：演員有研究者、資料管理者、審閱者三個人，文獻資料庫、計算環境兩個系統；工作物件是研究問題、論文清單、方法與評估指標、整理後資料、程式碼、結果圖表、比較表、結論、報告、審閱意見；活動十一個，各有編號。這種畫法叫 domain storytelling，元素只有三種，畫的時候每次一句：何人、何動作、交出何物。自 1 號讀至最後，整張圖可讀成一段敘述；不通順之處即是圖畫錯或事情尚未想清楚之處。

兩個要點。第一，系統也是演員：資料庫、計算環境、既有的業務系統皆畫為演員，因為工作物件會交予它們、再由它們交出；只畫人，圖上便無法看出系統在何處接手。第二，一張圖只講一個具體案例，不畫所有分支；有分支就多畫一張。粗顆粒講整件事，細顆粒講其中一段。上半場六種介入方式各一張圖，就是同一件事的六段細圖。

**原話與來源**

- 「下半場開始拆解的時候會先講 story 圖怎麼畫，然後就可以從這個東西找出可能缺的東西，或是重新看到一些可以變成系統的東西」（09-22）
- 來源：[[domain-storytelling]]

### 9｜一行一句的文法

**畫面**

- 主訊息：畫圖之前先寫句子，一行一句：演員、動詞、工作物件。
| 句型 | 例句 |
|---|---|
| 演員 ＋ 動詞 ＋ 物件 | 研究者 寫下 研究問題 |
| 演員 ＋ 動詞 ＋ 物件 ＋ 動詞 ＋ 下一個物件 | 研究者 依 比較表 歸納出 結論 |
| 演員 ＋ 動詞 ＋ 物件 ＋ 介詞 ＋ 演員 | 研究者 撰寫 報告 送交 審閱者 |

- 動詞寫在箭頭上，受詞是箭頭指到的物件；不寫「得到」這類結果詞
- 物件須相互銜接：上一句交出的物件，是下一句的依據
- 演員交替之處即交接點，也是完成證據與驗收的位置

**筆記**

圖的任務：表格三列各對應一句，旁附三句畫成的圖；圖檔 `slides/story/w42-grammar.svg`
版型：總覽

圖是句子的畫法，先寫句子，再產圖。句子只有三種：演員以動詞產出物件；演員依上一個物件產出下一個物件；演員產出物件交予另一個演員。第一種是起點，第二種把物件串接，第三種是交替。上半場的圖自 1 號讀至 11 號，每一句皆為這三種之一。

三個規則。第一，動詞寫在箭頭上，受詞是箭頭指到的物件；「檢索文獻，得到論文清單」不成一句，「研究者 向 文獻資料庫 檢索出 論文清單」才是。第二，物件須相互銜接：論文清單是選定方法的依據，方法是撰寫程式的依據，句子裡寫出來，圖上才有連線；沒有連線的物件即是沒有後續的產物，本身即是一項發現。第三，演員交替之處即交接點：研究者把報告送交審閱者，審閱者以審閱意見交回；每一個交接點都是一份工作物件交出的位置，也是下午要寫完成證據與驗收的位置。

句子是 Agent 能寫、人能改的形式，這是下一頁的前提。

**原話與來源**

- 「我感覺沒有完整的文法結構？就是變成得到一堆東西而已？沒有受詞？」（09-22）
- 「原本論文清單裡面去選出主要方法，這個有要連起來嗎？因為感覺看圖覺得沒有關聯？」（09-22）
- 來源：[[domain-storytelling]]「寫故事給 agent 的規則」

### 10｜請 Agent 畫圖

**畫面**

- 主訊息：人口述一次實際完成的工作，Agent 寫成句子與文字檔，工具產圖；修改只改句子。
- 口述：實際完成的一次，自始至終，包括交付對象與交付物
- Agent 列出演員、工作物件與活動句，人逐句確認
- Agent 把句子寫成 PlantUML 文字檔，工具產出圖；本機安裝或線上服務皆可

```text
Person(researcher, 研究者)
System(litdb, 文獻資料庫)
Document(papers, 論文清單)
activity(_, researcher, 依研究問題向, litdb, 檢索出, papers)
```

- 修改不重畫：修改句子，重新產圖；文字檔存入自己的 repo

**筆記**

圖的任務：這一頁的流程本身畫成一張 story 圖：講師口述，Agent 列句、寫文字檔，工具產圖，講師通讀後回到句子修改；圖檔 `slides/story/w42-agent-draws.svg`
版型：流程

上半場所有的圖皆依此產生。講師把研究流程口述給 Agent：實際完成的一次，自提出問題至收到審閱意見；Agent 先列出演員、工作物件與活動句，講師逐句修改；確認之後 Agent 把句子寫成 PlantUML 的文字檔，用的是 DomainStory 函式庫，一行一個元素、一行一句活動，工具讀這個檔產出圖。畫面上的四行即是文字檔的形式：宣告演員與物件，再寫活動句，編號自動遞增。整張研究流程圖的文字檔只有二十多行，附在講義。

各位可依此進行。任何一個 agent 皆能撰寫這種文字檔，口述時不必使用它的語法，以日常語句說一次，缺漏之處 Agent 會追問。產圖有三條路：本機安裝 PlantUML；把文字檔貼到 PlantUML 的線上服務；或用 domain storytelling 官方的 Egon.io 手動畫。前兩條可以由 Agent 直接產圖，第三條圖由人畫，Agent 只出句子。

要點是修改不重畫。圖有錯，回到句子修改，重新產圖；文字檔存入自己的 repo，下次修改業務流程時自這個檔改起。這與這門課的做法相同：內容改文字，版面交給工具。

第一版的條件只有一個：照實。畫實際完成的一次，不畫理想的做法，也不畫 Agent。三種常見的偏差。第一，先把 Agent 畫入：如此無法看出現況，也無法看出介入前後的差異；Agent 留至第二版。第二，把執行不順的步驟省略或美化：例如申請資料等候兩週、比較表以人工整理，這些照實畫，因為那正是下一段要找的缺口。第三，把由人決定的活動省略：選定方法、歸納結論由人執行，仍須畫上，圖上才能看出哪些活動不交付。

### 13｜從圖上找缺口

**畫面**

- 主訊息：現況圖上找三種活動：無法銜接的、每次相同的、由人決定的。
- 無法銜接：上一個物件交到下一個活動無法繼續，物件定義不明、判斷缺乏依據；此處需要中間節點
- 每次相同：輸入整齊、規則固定、執行多次；可收斂為程式，或交給 Agent 反覆執行
- 由人決定：選定方法、歸納結論、定稿；保留給人，標為核准點

**筆記**

圖的任務：同一張研究流程圖，以三色箭頭與註記標出無法銜接的活動（紅，結果圖表到比較表）、每次相同的活動（藍，執行程式、調整程式）、由人決定的活動（綠，選定方法、歸納結論）；圖檔 `slides/story/w42-gaps.svg`
版型：流程

圖畫出之後，檢視三件事。第一，哪一步無法銜接：上一個活動交出的物件，下一個活動取得後無法繼續。例如結果圖表直接製成比較表，中間沒有交代每次實驗的參數與例外，比較表便無法回溯；無法銜接之處需要一個中間節點，即本段後面要講的 C。第二，哪一步每次相同：輸入整齊、規則固定、執行多次，例如執行程式、整理比較表；這種活動可以收斂為程式，或交給 Agent 反覆執行，即上半場講的製作工具與流程指派。第三，由人決定的活動：選定方法、歸納結論、定稿；這些不交付，但須在圖上標為核准點，讓 Agent 執行至此停止。

三種記號標完，一件工作可交付的段、須補中間節點的段、保留給人的段即已分開。這比對照表直接，因為是自己的工作看出來的，不是自他人的用法對應回來的。這一頁由人先看；下一頁把圖交給 Agent 共同檢視。

**原話與來源**

- 「從這個東西找出可能缺的東西，或是重新看到一些可以變成系統的東西」（09-22）

### 14｜與 Agent 討論介入

**畫面**

- 逐一活動回答：執行何種動作、留下何種產物、人在何處驗收；三題皆能回答者列為候選
- Agent 提出候選，人決定；Agent 傾向全數接手，以三個問題逐一退回

**筆記**

圖的任務：研究流程圖的第二版：加入「Agent」演員，接手檢索文獻、草擬程式、執行並填寫紀錄表、製成比較表、草擬報告；選定方法與歸納結論加核准點；與第 12 頁的第一版並列；圖檔 `slides/story/w42-v2-agent.svg`
版型：流程

第一版通順之後，交給 Agent 共同檢視。給它三項材料：現況圖的文字檔、上半場六種介入方式的說明、第 5 頁的動作詞彙；然後以日常語句詢問：這是我目前的工作流程，哪幾個活動你可以接手，各留下何物供我檢查。Agent 的回答一般會全數接手，此時以第 4 頁的三個問題逐一退回：這一個活動你執行何種動作、留下何種產物、我在何處驗收；三題皆能回答的活動才列為候選。六種介入方式即是 Agent 出現在圖上的六種方式：對話在活動旁不帶箭頭；交辦接收物件並交回檔案；製作工具出現在每次相同的活動；結構化判斷出現在物件轉物件之處，交回固定格式；流程指派與 Agent 管理流程則是 Agent 自身成為一條流程。上半場六張案例圖已各示範一次，各位下午的工作是將它們套用於自己的圖。

採用的候選畫成第二版：Agent 成為圖上的一個演員，箭頭上的動詞使用第 5 頁的十個詞，交出的物件寫明。第一版不予覆蓋，兩版並列，差異即介入的範圍，也是下午評估表評估的對象。以研究流程為例，第二版一般是 Agent 接手檢索文獻、撰寫程式、執行程式與製成比較表，選定方法與歸納結論由研究者核准。

下午的評估在第二版上進行：若無 Agent 這件事是否仍會進行、介入前後有無差異、成本與風險，皆列於 4-3 的評估表。這一頁止於候選與第二版。

### 16｜中間節點 C

**畫面**

- 主訊息：A 到 B 無法說清或做不可靠，即插入一個人可檢查的 C。
| 卡點 | C | 人檢查的項目 |
|---|---|---|
| 想法直接轉為簡報，主張與順序不清 | 結構化文稿 | 背景、目的、主張與依據是否成立 |
| 文稿轉為簡報，每頁用途不明 | 逐頁稿 | 邏輯能否連讀、證據與口述的位置 |
| 結果圖表直接製成比較表，參數與例外未交代 | 逐次實驗紀錄表，附參數、資料範圍與排除註記 | 參數是否一致、例外如何處理、比較表能否重現 |

- 尋找 C 的來源：詢問 AI、請 AI 搜尋、自行閱讀、請教同事、實地觀察、親手試作

**筆記**

圖的任務：結果圖表（A）、逐次實驗紀錄表（C）、比較表（B）一列橫排，Agent 填寫紀錄表、研究者檢查、Agent 依核准的紀錄表製表；讓人看出 C 是插在 A 與 B 之間、可以檢查的一站；圖檔 `slides/story/w42-a-c-b.svg`
版型：流程

B 定義為完成證據之後，常會發現 A 無法直接到達 B。先說明原因。人的想法轉為文字或畫面時經過選擇，對方看到的是表達，不是意圖；人與人如此，人與 Agent 亦然。因此協作需要一個可以共同檢視的中間產物：一段整理、一份有依據的文稿、一張比較表、一個具體的問題描述。LLM 學過大量人類語言與互動模式，可以借用溝通、管理與教練的方法，把意圖、背景、分工與標準說清楚，提高它產生合適回應的機率。互動形式像同事或教練，不代表它具有人的動機或責任。

再說明如何尋找。A 到 B 無法說清或做不可靠，即找一個中間節點 C，把工作拆為 A 到 C、C 到 B。C 可以是資料、決定、規格、草稿或試作結果，條件是補上一個具體缺口、讓下一步有依據、讓人能檢查。需要幾層視任務、人的理解與工具能力而定；同一層可以反覆修改。尋找 C 的來源不止一種：詢問 AI、請 AI 搜尋、自行閱讀、請教同事、實地觀察、親手試作。Agent 的建議先視為候選，再以材料或試作確認。成品出現內容問題，回到適當的草稿層修改，不在版面上重做。

三個例子。前兩個是第二週的做法：想法直接轉為簡報，C 是一份結構化的文稿；文稿轉為簡報，C 是逐頁稿。第二週的三個迴圈即是三個 C，簡短提及即可。第三個是本週的案例，也是第 13 頁標為無法銜接的那一步：結果圖表直接製成比較表，參數與例外尚未交代，C 是逐次實驗紀錄表附參數、資料範圍與排除註記，人檢查參數是否一致、例外如何處理、比較表能否重現。在圖上，C 是插在結果圖表與比較表之間的一個新工作物件；缺少它，結論即無法追溯。此即工作單「中間產物與完成證據」一欄的前半。

時間允許時可放三分鐘示範：先說幾個零散想法，請 Agent 寫成一段，當場指出一處偏移，補上理由，請它重寫。時間不足則略過。
