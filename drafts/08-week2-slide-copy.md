# 第二週投影片逐頁稿（第九版：由原話版 ghost deck 轉出）

來源：`09-week2-ghost-deck-own-words.md`。每頁三項：標題由該頁的原話書面化，一句以內、不帶逗號的長度；畫面是證據；備註是口述，能用原話就用原話。標【無原話】的頁，標題是 agent 依教案寫的。共 27 頁，前半段 16 頁、示範與練習 11 頁。

## 前半段

### 01｜先玩玩看 agent 吧

- 原話：「先玩玩看 agent 吧」「上次介紹了 agent 是什麼，這次讓大家有個方向怎麼學 agent」
- 畫面：深底標題頁，副標「Agent 時代的知識工作｜第二週」
- 備註：上次介紹了 agent 是什麼，這次讓大家有個方向怎麼學。前半段 30 分講怎麼合作，示範 30 分看一遍，練習 120 分自己做一份。

### 02｜研究專案的材料、想法與成果持續累積【無原話】

- 畫面：材料、想法、成果三個圖示連成循環，箭頭旁四個詞：查找、整理、試作、檢查
- 備註：開場是一個情境，課程主頁講的那個研究專案。agent 能幫哪一段，取決於你卡在哪裡。

### 03｜AI 是放大器：領域知識 × agent 能力

- 原話：「領域知識 x Agent 能力，我們需要兩邊都要有，才有辦法發揮」
- 畫面：左放大鏡照片；右兩則定義，中間乘號。領域知識：知道方法的因果關係，知道現在缺什麼、該怎麼跟 agent 講才會得到預期的結果。駕馭 agent 的能力：知道不同模型擅長什麼、能做到什麼程度，偏工具的熟悉度。
- 備註：兩個族群。學得快沒有包袱的，缺的是領域知識；經驗老到的，不用把原本工作流程打掉換新的，分析自己工作流裡重複機械式或目標明確的部分，用 agent 試試看，也可以去補過去一直想補但沒時間補的短板。

### 04｜從自己需要補足的地方開始

- 原話：手稿三個切入點「拿現有流程，把簡單重複的東西替換掉／將原本不知道的東西拓展出去／當作一個審查者，讓他來抓盲點」；後補「有想法但對工具不熟，像是 vibe coding」
- 畫面：二乘二卡片：缺知識與方向／有想法但不熟工具／簡單重複的雜工／需要人抓盲點，各一句做法
- 備註：同一件事可能同時需要幾種。選定之後，下一步是把需要向 agent 說清楚。

### 05｜聊天像請教導師

- 原話：「聊天的心態就是很像在請教一個不同領域的導師，你的領域一定自己比較懂，但是你可以從那個導師挖到很多你不知道的事情」「指派任務的話，要講比較明確的方向跟重要的限制條件……具體怎麼做不要規定的太細」
- 畫面：兩欄。請教：先以自己的想法為主，不能被牽著走；交辦：格式、範圍、長度講清楚，做法留給它。各一句 GDMS 例句。
- 備註：太籠統會沒跟自己對齊，太細節可能會錯過更好的方法。已有自己累積的工作流程，不用急著全部切換。最省事的交辦是只給一句話，示範開頭會先這樣做一次。

### 06｜交付出去的東西是要負責的

- 原話：「用幾句話完成什麼東西看起來很厲害，但那不是你要的東西／與其 AI 一次吐一堆看不完的東西／不如一點一點的把工作流程替換」
- 畫面：手稿三句直排；旁邊一張一句話生成的簡報縮圖
- 備註：對照組的反應：做得不錯，但拿去報就會卡，因為不知道第四種方法是什麼，被問就答不出來。漂亮這點可以吸收，後面第三圈會用到。

### 07｜內容要走三個迴圈

- 原話：「前半段是訂方向，後半段是確認內容，所以會看到兩個大的迴圈」「這個東西應該會變成第三個回圈，就是內容確定了我們要想辦法讓交付物對齊自己的喜好」
- 畫面：三圈全圖縮小，只看得出三塊與兩條回頭箭頭
- 備註：跟軟體工程對得上，需求探索、建立架構、寫 code。三段對三圈，接下來各看一圈。

### 08｜建立論點

- 原話：「人看過所有前面探索的資料，先想辦法不用 ai 寫一個大綱出來，這樣一方面人有先全部想過一遍，另一方面 ai 會順著這個方向先寫一版出來，這樣都可以減少認知債，但真的想不到的話就叫 ai 串串看也是可以的」
- 畫面：第一圈放大，其他淡化：探索 → 人先列綱 → agent 整理故事線；虛線回到探索
- 備註：有自己的想法就先以自己的為主，洞見從這裡插進去，成果才代表自己。後面才看到的東西可能推翻論點，就回去調整方向，但會隨著交付日期接近而鎖定。

### 09｜確認內容

- 原話：「一開始可以先叫 ai 打個草稿，這裡需要人大量的參與把原本 ai 說的話順成自己說的話，就是把真實的『肉』長出來，可以補一些文獻來源或圖片之類的」
- 畫面：第二圈放大：agent 起草 → 人充實查核 → 整體收斂；虛線回到起草；一條箭頭退回第一圈
- 備註：迭代回圈小一點，越快進到具體改起來越慢，內容盡量留在 md 上，甚至先在對話裡叫 agent 講一遍怎麼做，確定了再落檔。講稿像文章，投影片分口述跟畫面，節奏不一樣。

### 10｜確認表達

- 原話：「內容確定了我們要想辦法讓交付物對齊自己的喜好」「分頁找一次原則，排版找一次原則，就把這個東西融到每個步驟裡面」
- 畫面：第三圈放大：三個面向依序，分頁與順序、文字與語氣、版面與圖文；每個面向：拿判準 → agent 整份產出 → 人看整份；一條箭頭退回第二圈
- 備註：入口是判準。一直在改，就是要去找一個原則，叫 agent 先整理別人的做法，照著做，這就是補短板。自己有判斷力的面向直接拿規則檔，用過有效的補進 AGENTS.md，這一格就變短。AI 語氣也是這一圈的事。

### 11｜東西都要外部化存起來

- 原話：「整個資料夾結構是有機自己產生出來的，只有需要給 agent 這個概念要把東西都外部化存起來，那 kb 是一個常見的處理方式，剩下的 draft 或其他資料夾都是依照專案需求，跟著 agent 互動建立出來的」
- 畫面：三步一行：請 agent 寫成 md → 自己開啟確認 → 下次指定讀取；下方三個資料夾：kb 材料與來源、drafts 論點文章分頁與棄案、output 成品
- 備註：有自己熟悉的整理方式，叫 agent 先照抄也可以。實際產出的是 kb、draft 跟 ppt；論點整理到文章上，棄案在另一個 draft。

### 12｜這份投影片就是照那張圖做的

- 原話：「我整個投影片一開始的方向是什麼，然後找了資料以後方向變成現在這個樣子，然後我中間一直在來回修那個講稿，然後現在變投影片階段我剛剛測試了先叫 agent 找投影片原則，然後套用」
- 畫面：三圈全圖，三段各標日期：9 月 2 到 6 日、9 月 7 日、9 月 7 到 8 日
- 備註：接下來每圈一頁，看改前改後。

### 13｜建立論點：方向改了三次才定下來

- 原話：「我第二週想要做的比較像先給大家都體會到 agent 的好玩的地方」「客服的例子可以拿掉，不是很好講」「把 draft 裡面關於 NESA-SLIDE 拿掉」
- 畫面：左三個日期各一句方向（9 月 2 日文件專案化與模型能力；9 月 4 日公部門用 AI 的阻礙與規範；9 月 6 日先體驗 agent）；右移出的材料清單
- 備註：方向定了，材料進來又改細節。連迴圈圖本身也改了五次才定型。

### 14｜確認內容：講稿在兩輪試跑間來回修

- 原話：「你有沒有辦法模擬一下你是學員……如果中間卡住就要看教案怎麼修」「學員應該講話要更口語，更沒有結構一點」「時數是總共 60 分鐘……被 agent 膨脹了，現在要收斂一下」
- 畫面：左一則卡點：原句「以備課試跑確認可用的路徑製作可編輯 PPTX」，兩輪學員都看不懂，改成「先做一頁，確認這台機器真的做得出來」；右四個數字：2 輪、58 次發言、字數 8,200 到 7,300、60 分
- 備註：時數定下來，講稿才有尺可量。

### 15｜確認表達：逐錯修改六版沒有方向

- 原話：「太多硬要做的金句了……對於讀者就是個雜訊」「投影片就是要大家把注意力聚焦在少數重點上，不是把資訊攤開來展示」「真正重要的是概念本身怎麼串」
- 畫面：左第一版的一頁；右六版各修什麼：刪金句、精簡成書面文、一頁一個焦點、一頁一個概念、內文用條列或表格、實作頁要能跟著做
- 備註：每版解一個問題，每版又冒出新問題。

### 16｜確認表達：先找原則再用原話重排

- 原話：「你找一下一些做投影片的原則是什麼……要怎麼把論點變成一頁一頁的重點」「ghost deck 有辦法還原到我的原話而不是生成的字嗎」「用原話來調整 ghost deck 比較能看懂」
- 畫面：左原則表四列配套用後的同一頁；右一句對照：生成的「還沒有方法時請教，已知道要做什麼時交辦」對原句「聊天的心態就是很像在請教一個不同領域的導師」
- 備註：一次修一個錯，是每次只有一個判斷；先找原則，判斷變成一組。原則解決了分頁與版面，原話解決了語氣。練習第五到七步就是這三個面向。

## 示範與練習

### 17｜開始前先確認資料去哪裡

- 原話：「要把提供訓練關掉跟 push github 本身就是上雲，就叫他們測試的資料不要選機密的來試」
- 畫面：四張卡片：資料使用設定、repo 公開與否、PPTX 製作路徑、預覽方式；底部一行：把「幫我做一份向新進同仁介紹 GDMS 的簡報」貼給 agent 背景做
- 備註：示範只展開一條論點。接下來八頁，示範時看，練習時照做。

### 18｜第一步：開空專案

- 原話：「先開一個空的專案，然後開始先講這個專案大致上要做什麼，然後說要建立 kb，並且叫 agents 把討論都寫進 kb 裡面，然後這個動作全部寫進 agents.md 裡面，這樣就會把專案初始化」
- 畫面：步驟卡：做什麼／對 agent 說／確認什麼；右目錄圖
- 備註：有自己熟悉的整理方式就叫 agent 照抄。開啟檔案確認、太長就刪短、明確請它讀取，這三條來自試跑。

### 19｜第二步：講背景與限制

- 原話：「然後開始講專案背景，像是受眾，時間，簡報長度等等這些限制條件／然後開始拓展主題看要讓觀眾知道什麼」「用聊天的方式把背景講一講，然後問問看 agent 建議，最後落成 md 存起來」
- 畫面：步驟卡；右預設題方框：只用 GDMS 公開頁面
- 備註：每份實際開啟、附來源、30 分停止搜尋，來自試跑。任何一步卡住都可以再找一輪材料。

### 20｜第三步：先找出想講的方向

- 原話：「有了大方向叫 ai 拓展看看有沒有東西要調整／有的話就繼續聊天補齊」「先想辦法不用 ai 寫一個大綱出來」「論點本身也會有一些棄案可以被整理出來」
- 畫面：步驟卡；右立場修正的例子
- 備註：想不到時讓它先試串，自己逐段說認同或修改的理由。

### 21｜第四步：起草講稿

- 原話：「然後就會起個講稿的草稿」「把原本 ai 說的話順成自己說的話，就是把真實的肉長出來，可以補一些文獻來源或圖片」「文章本身可以作為輔助使用」
- 畫面：步驟卡；右查證對照表
- 備註：挑一句斷言查證是試跑後加的動作，學員不會主動做，第 50 分鐘全場再示範一次。

### 22｜第五步：找分頁原則

- 原話：「講稿更具體後做成投影片的分頁草稿」「投影片是分成口述跟畫面」「先把 ghost deck 寫好」「分頁找一次原則」
- 畫面：步驟卡；右這份投影片的 ghost deck 前幾行
- 備註：分頁方法找到好幾種，本課選綜合的一種。先讓 agent 自己找一輪再對照課程筆記。

### 23｜第六步：修改語氣

- 原話：「也可以把文字語氣這個東西變成一步，像是要盡量用原話，或是找消除 ai 語氣的整理之類的」「不是精簡成奇怪的金句，要是書面文」
- 畫面：步驟卡；右三份判準來源：維基 AI 寫作特徵清單、OpenAI 禁用詞與規則、Anthropic 的 mannered prose 定義
- 備註：請 agent 逐頁改寫並標出沒有原話依據的句子，自己讀一遍改掉不像自己的。看畫面最刺眼的口號句在這一步解決。

### 24｜第七步：找排版原則

- 原話：「分頁草稿確定後輸出 pptx 進入排版／排版就借用一下 ppt 的技巧」「迭代回圈小一點……才不會修太多美編排版，結果方向改變整個就丟掉了要返工」「他做得漂亮這點可以看怎麼達成」
- 畫面：步驟卡；右首次輸出與修改版並排
- 備註：第一次先做一頁驗路徑，之後整份產出。版面問題改規則重建，內容問題退回第五、六步。

### 25｜第八步：整個過一遍

- 原話：「最後就檢查交付」「最後人整個過一遍練習一下去微調，簡報就做完了」
- 畫面：步驟卡；右 agent 無法代做的三件事：親自點選文字確認可編輯、自己講一遍計時、講不順的地方回草稿改
- 備註：不用兩人一組，自己找時間真的講一遍，算是一個確認。開頭說的需求每項都在成品裡。

### 26｜練習：題目自選【無原話】

- 畫面：三欄：題目三條件、開始時兩件事、成品
- 備註：預設題同示範題。第 10 分鐘巡一輪，寫不出受眾與用途者改用預設題。

### 27｜回看：第一版和自己做的並排

- 原話：「如果只能帶走一件事……kb 會自己長出來，然後我們要收斂想法其實很快，因為 agent 會自己搜尋？那後面 ppt 製作就比較明顯，因為 agent 會自己去把簡報完成」（未定案）
- 畫面：兩疊並排，下方三問：補上了什麼、哪些是自己的判斷、哪些交給了 agent
- 備註：說不出理由的那頁，內容還不是自己的。三問是 agent 提案；核心訊息未定，上面那段是目前最接近的原話。
