## 前半段

### 01｜先玩玩看 agent 吧

- 目的：讓學員知道今天是動手玩，不是聽理論。
- 原話：「先玩玩看 agent 吧」「上次介紹了 agent 是什麼，這次讓大家有個方向怎麼學 agent」
- 畫面：深底標題頁，副標「Agent 時代的知識工作｜第二週」
- 備註：上次介紹了 agent 是什麼，這次讓大家有個方向怎麼學。前半段 30 分講怎麼合作，示範 30 分看一遍，練習 120 分自己做一份。

### 02｜AI 是放大器：領域知識 × agent 能力

- 目的：學員知道自己缺的是哪一邊，之後的協助選法從這裡來。
- 原話：「領域知識 x Agent 能力，我們需要兩邊都要有，才有辦法發揮」
- 畫面：左放大鏡照片；右兩則定義，中間乘號。領域知識：知道方法的因果關係，知道現在缺什麼、該怎麼跟 agent 講才會得到預期的結果。駕馭 agent 的能力：知道不同模型擅長什麼、能做到什麼程度，偏工具的熟悉度。
- 備註：兩個族群。學得快沒有包袱的，缺的是領域知識；經驗老到的，不用把原本工作流程打掉換新的，分析自己工作流裡重複機械式或目標明確的部分，用 agent 試試看，也可以去補過去一直想補但沒時間補的短板。

### 03｜把 AI 當同事

- 目的：知道開口有兩種方式，以及最省事的那種會出什麼問題。
- 原話：「可能改成把 AI 當同事」（09-08 本次對話）；「聊天的心態就是很像在請教一個不同領域的導師，你的領域一定自己比較懂，但是你可以從那個導師挖到很多你不知道的事情」「指派任務的話，要講比較明確的方向跟重要的限制條件……具體怎麼做不要規定的太細」
- 畫面：兩欄。左「請教」：像請教不同領域的同事，先以自己的想法為主，不能被牽著走；右「交辦」：講明確的方向跟重要的限制，格式、範圍、長度，具體怎麼做留給它。各一句 GDMS 例句。底部一行：最省事的交辦，是只給一句話、不給材料、不請教。
- 備註：太籠統會沒跟自己對齊，太細節可能會錯過更好的方法。已有自己累積的工作流程，不用急著全部切換。示範開頭會先做一次只給一句話的版本。

### 04｜從自己需要補足的地方開始

- 目的：學員選得出自己第一個要試的切入點。
- 原話：手稿三個切入點「拿現有流程，把簡單重複的東西替換掉／將原本不知道的東西拓展出去／當作一個審查者，讓他來抓盲點」；後補「有想法但對工具不熟，像是 vibe coding」
- 畫面：二乘二卡片：缺知識與方向／有想法但不熟工具／簡單重複的雜工／需要人抓盲點，各一句做法
- 備註：同一件事可能同時需要幾種。選定之後，下一步是把需要向 agent 說清楚。

### 05｜交付出去的東西是要負責的

- 目的：知道一句話生成的東西為什麼不能直接交出去。
- 原話：「用幾句話完成什麼東西看起來很厲害，但那不是你要的東西／與其 AI 一次吐一堆看不完的東西／不如一點一點的把工作流程替換」
- 畫面：左手稿三句直排；右一句話生成的對照組裡「漂亮但一堆字」的一頁，用第 4 頁「對話式 AI 直接生成」的方式卡：深藍版面、三塊說明文字塞滿，看起來完整，講的人卻答不出第四種方法是什麼。
- 備註：對照組的反應：做得不錯，但拿去報就會卡，被問就答不出來。漂亮這點可以吸收，後面第三圈會用到。

### 06｜東西都要外部化存起來

- 目的：知道東西要存成檔案，結構是長出來的，不用先設計。
- 原話：「整個資料夾結構是有機自己產生出來的，只有需要給 agent 這個概念要把東西都外部化存起來，那 kb 是一個常見的處理方式，剩下的 draft 或其他資料夾都是依照專案需求，跟著 agent 互動建立出來的」
- 畫面：這門課 repo 的整個資料夾結構，樹狀直排：AGENTS.md、工作紀錄.md、kb/（arguments、tools）、drafts/、skills/、assets/、slides/、lessons/、tmp/；每個資料夾右側一行說放什麼；用單色資料夾圖示
- 備註：有自己熟悉的整理方式，叫 agent 先照抄也可以。這個結構是這幾週跟 agent 互動長出來的，不是一開始設計的；kb 昨天才分成論點類與工具類。

### 07｜三個迴圈【段】

- 目的：知道接下來三圈一圈兩頁。
- 原話：「前半段是訂方向，後半段是確認內容，所以會看到兩個大的迴圈」「這個東西應該會變成第三個回圈」
- 畫面：深底，只有段名
- 備註：內容不是一次寫成的。先一張全圖，之後每圈兩頁：一頁講那一圈怎麼走，一頁用這份投影片當實例。

### 08｜內容要走三個迴圈

- 目的：看到整體只有三圈，每圈都有人的判斷。
- 原話：「這個東西應該會變成第三個回圈，就是內容確定了我們要想辦法讓交付物對齊自己的喜好」「跟原本軟體工程也是對得上的，就是需求探索，建立架構跟寫 code 的感覺」
- 畫面：mermaid 直式流程圖，三個群組由上而下：確認方向、確認內容、確認表達，群組內三格，實線往下、虛線回頭，每圈人的那一格紅框。
- 備註：跟軟體開發對得上，需求探索、建立架構、寫程式。三段對三圈，接下來各看一圈。

### 09｜確認方向

- 目的：知道第一圈人要先自己寫大綱。
- 原話：「人看過所有前面探索的資料，先想辦法不用 ai 寫一個大綱出來，這樣一方面人有先全部想過一遍，另一方面 ai 會順著這個方向先寫一版出來，這樣都可以減少認知債，但真的想不到的話就叫 ai 串串看也是可以的」
- 畫面：同一張直式圖，第一圈亮、其他淡化
- 備註：有自己的想法就先以自己的為主，洞見從這裡插進去，成果才代表自己。後面才看到的東西可能推翻論點，就回去調整方向，但會隨著交付日期接近而鎖定。

### 10｜確認方向：方向改了三次才定下來

- 目的：看到方向會改，改了不算失敗。
- 原話：「我第二週想要做的比較像先給大家都體會到 agent 的好玩的地方」「客服的例子可以拿掉，不是很好講」「把 draft 裡面關於 NESA-SLIDE 拿掉」
- 畫面：左三個日期各一句方向與移出的材料清單
- 備註：方向定了，材料進來又改細節。連迴圈圖本身也改了五次才定型。

### 11｜確認內容

- 目的：知道第二圈是把生成的字換成自己的觀點，而且留在 md 上改。
- 原話：「一開始可以先叫 ai 打個草稿，這裡需要人大量的參與把原本 ai 說的話順成自己說的話，就是把真實的『肉』長出來，可以補一些文獻來源或圖片之類的」
- 畫面：同一張直式圖，第二圈亮
- 備註：迭代回圈小一點，越快進到具體改起來越慢，內容盡量留在 md 上，甚至先在對話裡叫 agent 講一遍怎麼做，確定了再落檔。講稿像文章，投影片分口述跟畫面，節奏不一樣。

### 12｜確認內容：講稿裡補進去的想法

- 目的：看到「自己的觀點」具體是什麼，知道第二圈要補的是這種東西，不是改字。
- 原話：「我中間一直在來回修那個講稿」（09-07 本次對話）；補進去的想法各有原句，見畫面。
- 畫面：一欄清單，每項一句想法、一個日期，都是從討論裡補進講稿的：領域知識 × agent 能力，兩邊都要有（09-06）；兩個族群，各缺一邊（09-06）；聊天像請教導師，交辦要講明限制（09-06）；人先不用 AI 寫大綱，減少認知債（09-06）；迭代回圈小一點，內容留在 md（09-06）；產出物是 kb、draft、ppt（09-07）；第三個迴圈，讓交付物對齊自己的標準（09-08）。右側一句：這些段落 agent 原本沒有，是討論時補進去的。
- 備註：agent 沿論點展開的是通順的字，觀點是人插進去的。改語氣是另一回事，在第六步。

### 13｜確認表達

- 目的：知道第三圈先拿標準，依序分頁、語氣、版面。
- 原話：「內容確定了我們要想辦法讓交付物對齊自己的喜好」「分頁找一次原則，排版找一次原則，就把這個東西融到每個步驟裡面」
- 畫面：同一張直式圖，第三圈亮；圈旁標三個面向的順序：分頁與順序、文字與語氣、版面與圖文
- 備註：入口是標準。一直在改，就是要去找一個原則，叫 agent 先整理別人的做法，照著做，這就是補短板。自己有判斷力的面向直接拿規則檔，用過有效的補進 AGENTS.md，這一格就變短。AI 語氣也是這一圈的事。

### 14｜確認表達：分頁時實際做了什麼

- 目的：看到分頁這一步的具體動作，知道 ghost deck 怎麼用、為什麼要用原話。
- 原話：「先把 ghost deck 寫好」「用原話來調整 ghost deck 比較能看懂」「標題稍微精簡一點，不要有逗號的長度」「這頁其實不用」「五跟四反過來看看」（09-08 本次對話）
- 畫面：六個動作各一行，附實際例子：生成的標題看不懂，換成原話當底，「還沒有方法時請教」變「聊天像請教導師」；只讀標題連讀，刪頁，研究專案情境頁、時間表頁；換順序，把 AI 當同事前移、外部化接交付責任、迴圈與實例穿插；縮標題，「開空專案，建 kb 與 AGENTS.md」變「開空專案」；加段落頁；再看逐頁稿，決定每頁畫面與口述。
- 備註：現在正在做的就是這一圈，畫面是最後一步，內容問題都在前兩步解決。

### 17｜第一步：開空專案

- 目的：知道專案怎麼開始、討論存哪裡。
