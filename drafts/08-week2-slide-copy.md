來源：`09-week2-ghost-deck-own-words.md`。每頁四項：目的是這頁要讓學員知道的一件事，畫面照它選；標題由該頁的原話書面化，一句以內、不帶逗號的長度；畫面是證據；備註是口述，能用原話就用原話。標【無原話】的頁，標題是 agent 依教案寫的；標【段】的是段落標題頁。共 28 頁：前半段 15 頁、示範 10 頁、練習 3 頁。

## 前半段

### 01｜先玩玩看 agent 吧

- 目的：讓學員知道今天是動手玩，不是聽理論。
- 原話：「先玩玩看 agent 吧」「上次介紹了 agent 是什麼，這次讓大家有個方向怎麼學 agent」
- 畫面：深底標題頁，副標「Agent 時代的知識工作｜第二週」
- 備註：上次介紹了 agent 是什麼，這次讓大家有個方向怎麼學。前半段 30 分講怎麼合作，示範 30 分看一遍，練習 120 分自己做一份。

### 02｜AI 是放大器：領域知識 × agent 能力

- 目的：學員知道自己缺的是哪一邊，之後的協助選法從這裡來。
- 原話：「領域知識 x Agent 能力，我們需要兩邊都要有，才有辦法發揮」
- 畫面：左放大鏡照片；右兩則定義，中間乘號。領域知識：知道方法的因果關係，知道現在缺什麼、該怎麼跟 agent 講才會得到預期的結果。駕馭 agent 的能力：知道不同模型擅長什麼、能做到什麼程度，偏工具的熟悉度。
- 備註：兩個族群。學得快沒有包袱的，缺的是領域知識；經驗老到的，不用把原本工作流程打掉換新的，分析自己工作流裡重複機械式或目標明確的部分，用 agent 試試看，也可以去補過去一直想補但沒時間補的短板。

### 03｜把 AI 當同事

- 目的：知道開口有兩種方式，以及最省事的那種會出什麼問題。
- 原話：「可能改成把 AI 當同事」（09-08 本次對話）；「聊天的心態就是很像在請教一個不同領域的導師，你的領域一定自己比較懂，但是你可以從那個導師挖到很多你不知道的事情」「指派任務的話，要講比較明確的方向跟重要的限制條件……具體怎麼做不要規定的太細」
- 畫面：兩欄。左「請教」：像請教不同領域的同事，先以自己的想法為主，不能被牽著走；右「交辦」：講明確的方向跟重要的限制，格式、範圍、長度，具體怎麼做留給它。各一句 GDMS 例句。底部一行：最省事的交辦，是只給一句話、不給材料、不請教。
- 備註：太籠統會沒跟自己對齊，太細節可能會錯過更好的方法。已有自己累積的工作流程，不用急著全部切換。示範開頭會先做一次只給一句話的版本。

### 04｜從自己需要補足的地方開始

- 目的：學員選得出自己第一個要試的切入點。
- 原話：手稿三個切入點「拿現有流程，把簡單重複的東西替換掉／將原本不知道的東西拓展出去／當作一個審查者，讓他來抓盲點」；後補「有想法但對工具不熟，像是 vibe coding」
- 畫面：二乘二卡片：缺知識與方向／有想法但不熟工具／簡單重複的雜工／需要人抓盲點，各一句做法
- 備註：同一件事可能同時需要幾種。選定之後，下一步是把需要向 agent 說清楚。

### 05｜交付物代表自己

- 目的：知道交付物代表自己，一句話生成的東西為什麼還不能直接交出去。
- 原話：「用幾句話完成什麼東西看起來很厲害，但那不是你要的東西／與其 AI 一次吐一堆看不完的東西／不如一點一點的把工作流程替換」
- 畫面：左手稿三句直排；右一句話生成的對照組裡「漂亮但一堆字」的一頁，用第 4 頁「對話式 AI 直接生成」的方式卡：深藍版面、三塊說明文字塞滿，看起來完整，講的人卻答不出第四種方法是什麼。
- 備註：對照組的反應：做得不錯，但拿去報就會卡，被問就答不出來。漂亮這點可以吸收，後面第三圈會用到。

### 06｜東西都要外部化存起來

- 目的：知道東西要存成檔案，結構是長出來的，不用先設計。
- 原話：「整個資料夾結構是有機自己產生出來的，只有需要給 agent 這個概念要把東西都外部化存起來，那 kb 是一個常見的處理方式，剩下的 draft 或其他資料夾都是依照專案需求，跟著 agent 互動建立出來的」
- 畫面：這門課 repo 的整個資料夾結構，樹狀直排：AGENTS.md、工作紀錄.md、kb/（arguments、tools）、drafts/、skills/、assets/、slides/、lessons/、tmp/；每個資料夾右側一行說放什麼；用單色資料夾圖示
- 備註：有自己熟悉的整理方式，叫 agent 先照抄也可以。這個結構是這幾週跟 agent 互動長出來的，不是一開始設計的；kb 昨天才分成論點類與工具類。

### 07｜三個迴圈【段】

- 目的：知道接下來三圈一圈兩頁。
- 原話：「前半段是訂方向，後半段是建立架構，所以會看到兩個大的迴圈」「這個東西應該會變成第三個回圈」
- 畫面：深底，只有段名
- 備註：內容不是一次寫成的。先一張全圖，之後每圈兩頁：一頁講那一圈怎麼走，一頁用這份投影片當實例。

### 08｜內容要走三個迴圈

- 目的：看到整體只有三圈，每圈都有人的判斷。
- 原話：「這個東西應該會變成第三個回圈，就是內容確定了我們要想辦法讓交付物對齊自己的喜好」「跟原本軟體工程也是對得上的，就是需求探索，建立架構跟寫 code 的感覺」
- 畫面：mermaid 直式流程圖，三個群組由上而下：確認方向、建立架構、調整風格，群組內三格，實線往下、虛線回頭，每圈人的那一格紅框；圈與圈之間的箭頭標通過標準：文稿撐得住方向、逐頁稿連讀通過、試講過得去。圖上不畫 ghost deck，它是逐頁稿的前置。
- 備註：跟軟體開發對得上，需求探索、建立架構、寫程式。每一圈以自己的產物收尾，產物就是這一圈的檢驗：文稿測方向、逐頁稿測架構、成品測風格，測不過就退回。接下來各看一圈。

### 09｜確認方向

- 目的：知道第一圈是帶著問題探索材料，人補入洞見，agent 順著討論長成文稿，文稿讀過撐得住才算方向確認。
- 原話：「人看過所有前面探索的資料，先全部想過一遍，ai 會順著這個方向先寫一版出來，這樣都可以減少認知債，但真的想不到的話就叫 ai 串串看也是可以的」
- 畫面：同一張直式圖，第一圈亮、其他淡化；右側三行：概念，帶著問題探索材料，人補入洞見，agent 順著討論長成文稿；產出物，文稿；通過標準，文稿讀過撐得住方向，不必回頭改主軸
- 備註：有自己的想法就先以自己的為主，洞見在這一圈進去，成果才代表自己；不必先寫大綱，討論本身就會長成文稿。文稿讀起來撐不住，就回頭補充探索或改方向；後面才看到的資料也可能推翻論點，但會隨著交付日期接近而鎖定。

### 10｜確認方向：方向改了三次才定下來

- 目的：看到方向會改、洞見是怎麼進去的，以及文稿怎麼把撐不住的方向退回來。
- 原話：「我第二週想要做的比較像先給大家都體會到 agent 的好玩的地方」「客服的例子可以拿掉，不是很好講」「把 draft 裡面關於 NESA-SLIDE 拿掉」「把原本 ai 說的話順成自己說的話，就是把真實的『肉』長出來」
- 畫面：左欄「方向」三個日期各一句：文件專案化與模型能力、公部門用 AI 的阻礙與規範、先體驗 agent。中欄「補入的洞見」三條：迭代回圈小一點，內容留在 md；一直在改就是缺一個原則，先找原則再套用；第三個迴圈，讓交付物對齊自己的標準。右欄「文稿退回的」三條：客服例子不好講，拿掉；NESA 與三種形式的對照組整段移出；兩輪試跑看不懂的句子改寫。
- 備註：方向改了不算失敗。文稿是方向的檢驗：兩輪學員試跑都看不懂的句子，退回來改的是方向與說法；總時數定為 60 分之後，文稿才有尺可量。連迴圈圖本身也改了五次才定型。

### 11｜建立架構

- 目的：知道第二圈從逐頁稿開始，agent 先把文稿排成逐頁稿，人只讀標題連讀，調整邏輯順序，刪併由人取捨，都還在 md 上改。
- 原話：「文稿更具體後做成投影片的分頁草稿」「投影片是分成口述跟畫面」「先把 ghost deck 寫好」
- 畫面：同一張直式圖，第二圈亮；右側三行：概念，agent 把文稿排成逐頁稿，人連讀後調整邏輯順序，agent 提議刪併，人決定取捨；產出物，逐頁稿；通過標準，只讀標題連讀能講完故事
- 備註：逐頁稿的前置是只有標題的 ghost deck，一頁一句主張，連讀就看得出跳接。文稿像文章，投影片分口述跟畫面，節奏不一樣。越快進到具體改起來越慢，所以順序在 md 上調好再往下。

### 12｜建立架構：文稿排成逐頁稿

- 目的：看到 agent 排出的第一版逐頁稿為什麼看不懂，以及改用原話當底之後怎麼變成看得懂的。
- 原話：「你 ghost deck 有辦法還原到我的原話而不是生成的字嗎」「用原話來調整 ghost deck 比較能看懂」「標題稍微精簡一點，不要有逗號的長度」（09-08 本次對話）
- 畫面：左右兩欄同一段的標題各五行：左「生成的標題」，右「原話當底的標題」，例如「還沒有方法時請教」變「聊天像請教導師」、「開空專案，建 kb 與 AGENTS.md」變「開空專案」；下方一行：每頁標題附原話出處與日期，agent 補的標【無原話】。
- 備註：生成的標題句通順但認不出自己的思路，改了七版還不是要的感覺；換成原話當底才看得懂、才判斷得了順序。這個做法留在 skills 裡。

### 13｜建立架構：連讀後調整順序與刪併

- 目的：看到連讀之後改的都是邏輯順序與取捨，不是字。
- 原話：「五跟四反過來看看」「這個好像要一起上去，跟在流程後面」「這頁其實不用」「12 接到 06 後面」「建立論點跟投影片實例應該可以穿插」（09-08 本次對話）
- 畫面：左欄「調整順序」四條：先講迴圈再講實例；保存接在流程後面；把 AI 當同事前移，外部化接交付責任；迴圈與實例穿插，各接在對應的圈後面。右欄「刪併取捨」四條：刪研究專案情境頁；刪練習時間表頁；段落頁加了又減；歷程從五頁併成三頁。
- 備註：agent 提的是刪併建議，留哪頁、什麼順序是人決定的。連讀能講完故事，架構才算定。原本以為分頁在第三圈，改名建立架構之後才看清楚它是第二圈的起點。

### 14｜調整風格

- 目的：知道第三圈是 agent 先找風格規則寫成標準，依標準產出一版，人依自身品味檢視整份，不合就改標準再產；只有輸出成品之後才是調風格。
- 原話：「內容確定了我們要想辦法讓交付物對齊自己的喜好」「分頁找一次原則，排版找一次原則，就把這個東西融到每個步驟裡面」
- 畫面：同一張直式圖，第三圈亮；右側三行：概念，agent 尋找風格規則寫成標準，依標準產出一版，人依自身品味檢視整份；產出物，成品；通過標準，整份看像自己，試講過得去
- 備註：先語氣再版面，兩個面向做法相同。人依品味看哪裡不像自己，改的是標準不是那一頁；自己有判斷力的面向直接拿規則檔，用過有效的補進 AGENTS.md，下次這一格就變短。看成品發現的內容問題退回第二圈。

### 15｜調整風格：這份投影片從第一版排到現在

- 目的：看到風格靠標準整份重產，不靠一頁一頁手修。
- 原話：「我覺得他做得漂亮這點可以看怎麼達成，搞不好可以吸收一下」（09-07 05:19）；「字有點太多了」「判準改成標準好像比較通俗一點」「你可以幫我裡面的字也改成書面語嗎」（09-08 本次對話）
- 畫面：左邊同一頁的改前改後，第一版與現在這版；右邊三欄對三格：找到的標準，視覺設計規則一份、文案語氣規則一份、廠商語氣指引筆記；產出，每版整份重建；人檢視後改的標準，圖示統一用一套單色、文字改書面語與原話、流程圖改 mermaid 直式。
- 備註：每次都是整份重建，不在 PPTX 上手改；看畫面發現的內容問題退回前兩圈。

## 示範

### 16｜示範：向新進同仁介紹 GDMS【段】

- 目的：知道示範是講師走一遍，要記兩件事。
- 畫面：深底，只有段名；右下小字「示範 30 分」
- 備註：講師走一遍八步，只展開一條論點。學員記兩件事：自己會加哪個條件，最想先試哪一步。

### 17｜開始前先確認資料去哪裡

- 目的：動手前把資料風險與工具路徑講清楚。
- 原話：「要把提供訓練關掉跟 push github 本身就是上雲，就叫他們測試的資料不要選機密的來試」
- 畫面：四張卡片：資料使用設定、repo 公開與否、PPTX 製作路徑、預覽方式；底部一行：把「幫我做一份向新進同仁介紹 GDMS 的簡報」貼給 agent 背景做
- 備註：示範只展開一條論點。接下來八頁，示範時看，練習時照做。

### 18｜第一步：開空專案

- 目的：知道專案怎麼開始、討論存哪裡。
- 原話：「先開一個空的專案，然後開始先講這個專案大致上要做什麼，然後說要建立 kb，並且叫 agents 把討論都寫進 kb 裡面，然後這個動作全部寫進 agents.md 裡面，這樣就會把專案初始化」
- 畫面：步驟卡，左上角段落標改為「準備」：做什麼／對 agent 說／確認什麼；右目錄圖
- 備註：有自己熟悉的整理方式就叫 agent 照抄。開啟檔案確認、太長就刪短、明確請它讀取，這三條來自試跑。

### 19｜第二步：講背景與限制

- 目的：知道背景怎麼講、材料怎麼收。
- 原話：「然後開始講專案背景，像是受眾，時間，簡報長度等等這些限制條件／然後開始拓展主題看要讓觀眾知道什麼」「用聊天的方式把背景講一講，然後問問看 agent 建議，最後落成 md 存起來」
- 畫面：步驟卡，左上角段落標改為「確認方向」；右預設題方框：只用 GDMS 公開頁面
- 備註：每份實際開啟、附來源、30 分停止搜尋，來自試跑。任何一步卡住都可以再找一輪材料。

### 20｜第三步：先找出想講的方向

- 目的：知道先自己定方向，再讓 AI 拓展。
- 原話：「有了大方向叫 ai 拓展看看有沒有東西要調整／有的話就繼續聊天補齊」「先想辦法不用 ai 寫一個大綱出來」「論點本身也會有一些棄案可以被整理出來」
- 畫面：步驟卡，左上角段落標改為「確認方向」；右方向修正的例子
- 備註：想不到時讓它先試串，自己逐段說認同或修改的理由。

### 21｜第四步：起草文稿

- 目的：知道第四步是把大綱展開成文稿，讀過確認方向撐得住；接著調整邏輯順序就進入建立架構，並查證一句。
- 原話：「然後就會起個講稿的草稿」「把原本 ai 說的話順成自己說的話，就是把真實的肉長出來，可以補一些文獻來源或圖片」「文章本身可以作為輔助使用」
- 畫面：步驟卡，左上角段落標改為「確認方向」；右查證對照表
- 備註：挑一句斷言查證是試跑後加的動作，學員不會主動做，第 50 分鐘全場再示範一次。

### 22｜第五步：分成逐頁稿

- 目的：知道第五步是請 agent 把文稿分成逐頁稿，先用原話與 ghost deck 做第一版邏輯，連讀通過再定成逐頁稿。
- 原話：「文稿更具體後做成投影片的分頁草稿」「投影片是分成口述跟畫面」「先把 ghost deck 寫好」「用原話來調整 ghost deck 比較能看懂」
- 畫面：步驟卡，左上角段落標改為「建立架構」：做什麼，把文稿分成逐頁稿；對 agent 說，先用我的原話排一版只有標題的 ghost deck，每頁一句；確認什麼，只讀標題連讀能講完故事，順序與取捨改好再請它補每頁畫面與口述；右這份投影片的 ghost deck 前幾行
- 備註：第一版邏輯用原話當底，看得懂才判斷得了順序；連讀通過之後才變成確定的逐頁稿，之後的修改都在這份檔案上做。分頁的原則不必另外找，一頁一句主張、畫面是證據，直接寫進對 agent 說的話裡。

### 23｜第六步：修改語氣

- 目的：知道語氣要改、標準從哪來。
- 原話：「也可以把文字語氣這個東西變成一步，像是要盡量用原話，或是找消除 ai 語氣的整理之類的」「不是精簡成奇怪的金句，要是書面文」
- 畫面：步驟卡，左上角段落標改為「調整風格」；右語氣的標準來源：原話、自己的文案語氣規則、維基 AI 寫作特徵清單、OpenAI 禁用詞與 Anthropic 的 mannered prose
- 備註：請 agent 逐頁改寫並標出沒有原話依據的句子，自己讀一遍改掉不像自己的。看畫面最刺眼的口號句在這一步解決。

### 24｜第七步：找排版原則

- 目的：知道排版整份產出、問題分兩類處理。
- 原話：「分頁草稿確定後輸出 pptx 進入排版／排版就借用一下 ppt 的技巧」「迭代回圈小一點……才不會修太多美編排版，結果方向改變整個就丟掉了要返工」「他做得漂亮這點可以看怎麼達成」
- 畫面：步驟卡，左上角段落標改為「調整風格」；右首次輸出與修改版並排
- 備註：第一次先做一頁驗路徑，之後整份產出。版面問題改規則重建，內容問題退回第五、六步。

### 25｜第八步：整個過一遍

- 目的：知道最後要自己講一遍。
- 原話：「最後就檢查交付」「最後人整個過一遍練習一下去微調，簡報就做完了」
- 畫面：步驟卡，左上角段落標改為「確認」；右 agent 無法代做的兩件事：親自點選文字確認可編輯、自己講一遍計時
- 備註：不用兩人一組，自己找時間真的講一遍，算是一個確認。開頭說的需求每項都在成品裡。
