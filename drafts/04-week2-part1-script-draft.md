## 一、從自己熟悉的工作開始

大家平常都有自己的簡報做法，也知道內容要講給誰聽。今天可以挑一個熟悉的主題，或拿一份自己已經做過、可以用來練習的簡報，看看 agent 能在哪些地方幫上忙。

我們先試兩件事。第一件是發想：讓 AI 提供一些原本沒想到的角度，再由自己選擇。第二件是排版：把已經決定的內容交給 agent，快速做一版，再和原本的做法比較。

今天不用完成很長的簡報。選幾頁有代表性的內容，看到一個值得留下的改善，就已經有具體收穫。

講師帶法：展示同一份公開範例的原稿與修改版，指出一個內容上的補充和一個排版上的改善。先讓大家看到能試什麼，再開始說明。

## 二、可以從三種用途找自己的入口

第一種是學新事。有些事情一直想試，卻不知道怎麼開始，可以請 agent 解釋、做一個小範例，自己實際比較和修改。做出結果後，還要能說出改了什麼、為什麼這樣比較好。

第二種是減少熟悉工作的重複環節。內容和重點你已經知道，可以試著把整理格式、調整版面這些工作交出去，再用自己的經驗檢查。

第三種是補足非強項。可能你很懂要講的主題，但不擅長視覺設計，就先讓 agent 提供一版，試著把它修改到這次工作需要的程度。

同一個人可以有不同的用途。今天先挑自己最有感的一種，不需要一次全部練完。

講師帶法：請學員簡短選擇想改善的是「想法」「重複工作」或「不擅長的部分」，在課堂口頭收集，不另加問卷或回家作業。

## 三、agent 可以做到哪一步，人要參與哪裡

以前用聊天工具，常常是問一段、複製一段，再自己放進簡報。今天會試著請 agent 依照材料完成一段工作，包括產生檔案和修改版面。

你仍然可以中途介入。它提出的方向不適合，就說明原因；它把重點改掉，就請它修回來。你對主題的了解，會用在這些選擇與修改上。

例如它補了五個角度，不必全部採用。你可以說：「第二個對這次聽眾有用；第四個超出範圍；其他幾個我們原本就有。」這些回應才會讓成果逐漸符合你的需要。

講師帶法：用準備好的範例，示範採納一項、刪除一項並說明理由。把人的判斷放在操作裡，不另外展開整套驗收理論。

## 四、開始前，先選好練習資料

今天請用公開材料、虛構內容，或確認適合提供給所用工具的材料。不要拿機密、個資或未公開的公務資料來測試。拿自己的舊簡報練習前，也要看過內頁、備註和附件；拿不準就改用講師提供的範例。

使用的工具若有「將內容用於模型訓練」設定，先依該工具與帳號的說明關閉。關閉訓練用途，不表示資料沒有傳到雲端，也不等於所有資料都可以提供給它。

另外，push 到 GitHub 就是把資料上傳到雲端，private repository 也一樣。本次體驗只需要在練習資料夾保存檔案，不要求 push。不要把「存在專案裡」當成不會外傳的保證。

講師備課：確認本次實際使用工具的資料控制選項與適用範圍，準備設定畫面；若帳號沒有相同開關，依官方說明解釋，不套用別家設定。這段只講本次練習必要的注意事項。

## 五、用簡報的幾個步驟接到實作

做簡報通常會先想清楚對象與目的，再找材料、發想、選出重點，最後安排內容、排版和檢查。大家本來就會做這些事，今天只挑兩段來試。

第一段先讓 AI 幫忙拓寬視野，再由你決定留下什麼。第二段把選好的內容交給 agent 快速排版，看看和原本相比，哪些地方更清楚，哪些還需要修改。

請選一個熟悉的主題，或一份可供練習的舊簡報。我們先從你已經有的內容開始。
