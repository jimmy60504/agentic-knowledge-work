# 第七週 ghost deck：把檢查規則整理成有依據的規則庫

> 狀態：ghost deck 第一版（2026-10-20），供使用者排序與刪減。依 `skills/ghost-deck-from-own-words.md` 製作：標題以使用者原話為底，只刪贅字、不改用詞；agent 補的頁面標【無原話】。
> 原話來源：本課的備課對話與檢查端的開發對話（完整抽出見 `tmp/week7-user-messages.md`、`tmp/week7-user-messages-0102-0110.md`，不進 git）。日期為台灣時間，只標日期。依去識別化規定，系統、程式與文件名稱以［］內的一般說法取代。
> 內容依據：[第七週文稿](20-week7-draft.md)第一版（五段）。講述約 60 分鐘，排 41 頁（含 6 張段落頁）；之後為討論與交換意見。
> 畫面：「開發截圖」指講師保存的 10/19 截圖（見文稿「附：可用的截圖」，含真實資料與內部名稱，需以虛構資料重拍或遮蔽）；自繪圖標【待畫】。

## 概念串接

1. 上週做出原型，本週把原型背後的檢查規則認真整理出來；原型沒有丟棄，還改得動就先改。
2. 接到兩個題目：預檢與定位軟體的翻新。錯誤會流到檢查端，是因為定位軟體沒有阻擋，因此兩者是一個整體；兩份程式包共用一個資料夾；規則自成一塊，兩端各自調用。
3. 以訓練投影片為主體列出步驟；為了分階段替換、保持行為一致，用 Agent 回到原始碼與執行檔，查清每個步驟對定位結果檔做了什麼。
4. 整理成一張規則與來源的大表：大量 Agent 盤查、人決定去留、雙向溯源、依檢查對象分類，欄位看得出設計意圖；依流程排列與門檻圖看把關的嚴謹程度；每一格都能點開原文。
5. 證據鏈從原文接到結果：規則與程式分開、與舊程式逐筆比對、以測試守住。
6. 從原型到正式工具：環境與測試機、處理留下紀錄、包成可以安裝與更新的程式。
7. 結語：檢查節點本身不用 Agent，AI 的投入在開發端；AI 也會出錯，靠證據鏈抓出來。

## 結語

### 41. AI 在哪些環節協助

- 目的：整理 AI 與人的分工，以及檢查節點不用 Agent 的理由。
- 標題：節點沒有搞成 Agent，開發梳理規則時用了大量的 Agent
- 原話：「我們會選用一般程式規則而不是 agent rag 也是這樣比較穩定且成本低，而且輸入輸出都是可以預期的結構化資料，所以才沒有把節點搞成一個 agent，但是開發在梳理規則的時候用了超級大量的 agent 去盤查」（10/17）
- 畫面：AI 與人的分工表（盤查來源、查證、驗證、執行檢查、打包與發布）。
- 備註：AI 也會出錯：第一輪讀錯的條目、讀錯原始碼而少算一行、構想階段提出的沒有來源的規則，都是靠證據鏈抓出來的【此句無原話】。
