### 4｜模型只產生文字

- 產生的可能是回答，也可能是動作描述：一行指令、一段程式碼、一個工具呼叫
- 沒有手按滑鼠；寫出「寄信」不等於寄出
- 原話：「一開始先講說他就是用文字的方式，去控制可能像 harness 預先寫好的程式，terminal 或是滑鼠等等，去做到他想做的事情」（09-19 17:49）
- 口述：文稿第一段第一、二段。

### 5｜執行框架讓事情發生

```text
人的目標／事件
  ↓ 模型讀取脈絡，產生回答或工具呼叫
  ↓ 執行框架呼叫預先接好的工具：終端機、程式、API、瀏覽器、滑鼠
  ↓ 工具真的讀取、計算、點擊、寫入或傳送，回報結果
  ↓ 模型依回饋繼續、請人確認，或交付
```

- 原話：同第 4 頁「harness 預先寫好的程式」
- 口述：文稿第一段第三段。圖用直式流程。

### 6｜最小例子：建一個 Markdown 檔

1. 模型決定位置、名稱、內容，必要時先查目錄
2. 產生 Markdown 文字，提出「建立檔案」的呼叫。仍只是文字與參數
3. 執行框架交給檔案工具，程式寫入磁碟
4. 工具回傳，模型再讀一次確認

- 單獨的模型可以寫出內容，無法在電腦裡建立檔案
- 原話：「就連開一個 md 把討論寫進去應該都是 harness 做了一連串的動作才做得到，單純 llm 是做不出這個操作」（09-19 17:51）
- 口述：文稿第一段第四、五段。投影片同理：逐頁稿、程式、PPTX、開檔檢查。

### 7｜提出、執行、驗證是三件事

| 案例的一步 | 用的工具 |
|---|---|
| 讀目錄與報次紀錄 | 讀取 |
| 算報時差與誤差 | 寫程式並執行 |
| 產統計表與分布圖 | 執行程式、寫入檔案 |
| 年報段落 | 草擬 |
| 送交承辦審核 | 詢問核准、傳送 |

- 每一步都分成：模型提出動作、工具執行動作、結果得到驗證
- 原話：「我能產出投影片，實際上是寫了一個 python 然後叫 python 出投影片這種比較細的中間產物」（09-19 17:34）

### 8｜六種介入方式

| 接手方式 | Agent 接手到哪裡 | 年度成效統計 |
|---|---|---|
| 人向 Agent 請教 | 流程之外發問，回答後退出 | 問時效與誤差怎麼定義，自行計算 |
| 一次性交付 | 查找、寫檔、驗證，交出檔案後退出 | 產出去年的表、圖與逐事件 CSV |
| 建置工具後退出 | 建置時產生程式，之後由程式執行 | 寫好篩選與計算腳本，每年重跑 |
| 固定節點呼叫一次模型 | 程式送輸入取結果，照固定路徑 | 從報次紀錄擷取第一報參數，交原流程 |
| 流程節點呼叫 Agent | 事件到達時查資料、選工具，交下一節點或人 | 每次事件後算差異補一列，標異常交承辦 |
| 協調跨節點工作 | 依回饋選下一步，跨系統、等核准、追蹤 | 補列到送審修改由 Agent 串接 |

- 原話：「目前應該有幾種 agent 的用法，就是直接接入 agent 到節點上做一些處理，還有 agent 產出程式碼，然後 agent 就不介入後面的結果，還有 agent 只是給人建議，並沒有進到整個流程中」（09-19 17:58）
- 原話：「這個感覺比較像是 agent 接手介入程度的感覺」（09-19 18:01）
- 口述：文稿第二段表格。先講使用者原本的三種，再攤開成六種。

### 9｜同一件事，六種方式各接哪幾步

| | 讀取 | 計算 | 確認 | 產出 | 保存 |
|---|---|---|---|---|---|
| 請教 | 流程外 | 流程外 | 人 | 人 | 人 |
| 一次性交付 | Agent | Agent | 人 | Agent 表圖 | 人 |
| 建置工具後退出 | 程式 | 程式 | 人 | 程式 | 人 |
| 固定節點呼叫模型 | 程式＋模型一次 | 程式 | 人 | 程式 | 人 |
| 節點 Agent | Agent | Agent | 人 | Agent 補列 | 人 |
| 跨節點協調 | Agent | Agent | 人核准 | Agent | Agent |

- 原話：「有兩條界線值得保留：程式若在運行時又呼叫模型，就不算 Agent 寫完後完全退出；固定節點的一次模型呼叫，也不一定就是能自行選步驟、使用工具的 Agent」（09-19 18:00）
- 口述：文稿第二段表格後一段。本頁為課程延伸，格子內容是示意。

### 10｜看介入方式的三個提醒

- 不是由低到高的能力等級：建置時接手很多，運行時可以完全退出
- 接手範圍與寫入權限分開決定：只讀、只建草稿、核准後才寫入
- 最後留下什麼分三組：可審查的檔案、改變外部狀態、持續運行的服務
- 第四種的現成例子：預警管線裡的 P 波拾取與震度預測模型，在固定位置做一件事，前後都是程式
- 原話：「多一些可能性這樣」（09-19 18:00）
- 口述：文稿第二段「三點說明」與「容易混淆」段。

### 11｜先有可以共同檢查的東西

- 想法轉成文字或畫面時經過選擇；對方看到的是表達，不是意圖
- 協作需要一個可共同查看的中間產物：整理、文稿、比較表、問題描述
- 先請 Agent 整理它的理解，人指出遺漏、誤解、未決
- 原話：「人的想法轉成外部可見的任何東西都會失真，包含轉成文字跟畫面等等，我們只能夠透過輸出的這些東西來推測，但真正的思考是沒有辦法被外部觀測的」（09-18 12:35）
- 原話：「我們這個方法就是拿著學習人類回話的生成器，用人預期的管理方式，讓模型產出中間產物來跟自己的思考對齊」（09-18 12:37）
- 引文頁內文：「LLM 學過大量人類語言與互動模式。我們可以借用溝通、管理與教練的方法，把意圖、背景、分工與標準說清楚，提高它產生合適回應的機率。」（09-18 12:28，使用者要求記下）
- 口述：文稿第三段第一小節。三分鐘示範放這裡。

### 12｜從 A 到 B，找中間節點 C

- 目前有什麼是 A，希望得到什麼是 B
- A 到 B 說不清楚或做不可靠，就找 C：A → C → B
- C 是資料、決定、規格、草稿或試作結果；條件是補一個具體缺口、讓人能檢查
- 找 C 的來源：問 AI、請 AI 搜尋、自己讀、請教同事、到現場、親手試
- 原話：「我們在創造工作流要尋找的步驟，就是一個人類可以用語言很明確知道可以從 a 得到 b 的轉換，如果自己想像的 a 沒辦法直接得到 b 的話，我們就要找一個中間節點 c，可以把 a 跟 b 串起來」（09-18 14:16）
- 原話：「怎麼找到 C 就會有個明確的方向，就是問 ai、叫 ai 找資料、或是自己想辦法去找資料、或是從現實世界中發現一些事情」（09-18 14:19）
- 口述：文稿第三段第二小節。

### 13｜三個 C 的例子

| 卡住的地方 | C | 人檢查什麼 |
|---|---|---|
| 想法直接變簡報，主張與順序不清 | 結構化文稿 | 背景、目的、主張與依據是否成立 |
| 文稿轉簡報，不知每頁用途 | 逐頁稿 | 邏輯能否連讀、證據與口述放哪裡 |
| 事件清單直接變年度統計，多報次與異常未處理 | 逐事件差異表，附納入排除註記 | 取哪一報、哪些排除、數字能否重算 |

- 前兩個是第二週：三個迴圈就是三個 C
- 原話：「回圈有幾層就是看本身這個想法要變成最終產物之前需要經過多少轉換，那這個東西取決於人對於原本工作流程的理解與模型的能力」（09-18 13:28）
- 口述：文稿第三段「三個例子」段。三圈一句帶過。

### 14｜找到 C 之後由誰負責

- 同一個 Agent 輪流當：討論者、整理者、記錄者、審查者、起草者、操作員
- 請教時帶著自己的意見問；交辦時說目的、結果、限制、標準，做法讓它選
- 人核准哪一步要先講定：判定與高影響處置由有權責的人決定
- 原話：「一開始 agent 會扮演討論者，還有派出去搜集資料整理的，還有會議記錄者，跟審視想法提問的等等，那後面階段還有去操控加工機器的，沒有這個具體的語意，全部都被包成一個 agent，這樣一般人就很難想像到底可以怎麼運用」（09-18 13:52）
- 原話：「看待 agent，就如他的名字，要思考在工作中該怎麼分工，就可以把目前的想法變成具體的角色去派給 agent 做事情，那用派的這個心裡暗示，使用者就會意識到要自己去做主來控制這些東西」（09-18 13:55）
- 口述：文稿第三段第三小節第一、三原則。

### 15｜模糊的交 Agent，明確的交程式

- 需要理解材料、提選項、試做的，交 Agent 探索
- 規則確定後收成程式或既有工具：可重複、結果穩定
- 課程例子：Agent 討論定逐頁稿，程式產 PPTX；內容改逐頁稿，版面改程式
- 案例：篩選與計算規則寫成腳本每年重跑，納入與異常解釋仍由人判斷
- 引文頁內文：「讓 agent 去處理模糊不確定的東西，然後把明確規則收斂成程式碼讓他可以重複執行。」（09-18 13:46）
- 原話：「agent 如果直接產生產物會太耗資源，且不具重現性，就是他的隨機性不能保證每次執行結果是一致的，所以會再透過程式碼去穩定他的輸出」（09-18 13:44）
- 口述：文稿第三段第三小節第二原則。

### 16｜下半場：回到業務

- 上半場：Agent 怎麼動、站哪裡、一段工作怎麼拆
- 下半場：別人怎麼用，地震業務翻成同樣的語意，兩邊對不對得上
- 工作坊：拿自己的工作做同樣的事
- 原話：「前半段感覺有一個整體性」「後半你回去修一下那幾個 kb 的參考資料，我那時候的討論比較像是從三個角度去分析」（09-20 09:52、09:58）
- 口述：一句收尾，休息十分鐘。
