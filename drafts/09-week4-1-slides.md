### 4｜示範：拆解一件工作

- 副標：以測試一個研究想法為例

圖下說明：

1. 研究者寫下研究問題。
2. 研究者依研究問題查詢文獻資料庫，取得論文清單。
3. 研究者閱讀論文清單，並與同事討論後，選定方法與評估指標。
4. 研究者向資料管理者申請資料，取得整理後資料。
5. 研究者依方法與評估指標撰寫程式碼。
6. 計算環境以整理後資料執行程式碼，產出結果圖表。
7. 研究者將結果圖表與現行方法對照，製作比較表。
8. 研究者檢視比較表，依結果調整程式碼。
9. 研究者依比較表歸納結論。
10. 研究者依結論撰寫報告。
11. 審閱者審閱報告，寫出審閱意見。

### 9｜後台實際的一輪來回

- 主訊息：模型僅輸出文字；改變狀態的是 Harness 呼叫的程式。

模型輸出的文字：

```text
先建立這次的統計腳本。
```

```json
{"name": "write_file",
 "arguments": {
   "path": "analysis/eew_stats_2025.py",
   "content": "import pandas as pd\n..." }}
```

工具回傳的文字：

```json
{"tool":"write_file","status":"ok","bytes":1284}
```

右側角色鏈：

1. 模型（Agent）：產生訊息與 `tool_call`，此時只是文字與參數。
2. Harness（程式）：剖析呼叫、比對工具清單、檢查權限。
3. 檔案工具（程式）：寫入磁碟，這一步才改變電腦狀態。
4. 模型（Agent）：回讀檔案驗證，決定下一步或停止。

### 12｜對話

- 主訊息：Agent 只提供建議，流程不變，仍由人執行。

適用情境：

- 聊天介面即可，零建置、隨時可用。
- 適合定義未明、規則未定，或成品已有而需要另一個角度檢查。
- 例如詢問時效與誤差的定義與往年做法，拿到建議後自行計算。

代價與條件：

- 資料不必開放，但產出是建議而非成品。
- 對話不累積，回答的是通則。
- 諮詢 AI 之前先形成自己的觀點與機關立場。

流程圖：

- 承辦人流程：自行查找資料、自行判斷、自行產出。
- AI 對話位於流程外。承辦人提出問題，取得建議後自行處理。
- 來源：數發部手冊 4.2.17。

### 13｜Agent 的角色

- 主訊息：介入方式決定位置，角色決定在該位置承擔的工作。
- 說明：機關內原本就存在這樣的分工，設定 Agent 的角色時沿用同一套想法即可。例如由同事先行檢查再送出，對應的即為審查者。

協助思考：

- 討論者：提供方向與選項。
- 對手：提出反例與疑點。
- 模擬對象：模擬民眾或記者提問。

代為執行：

- 整理者：查找比對並整理成表。
- 起草者：撰寫可修改的草稿。
- 操作員：執行程式與軟體操作。

監督把關：

- 規劃者：拆解步驟與順序。
- 審查者：對照標準檢查產出。
- 協調者：分派工作並追蹤結案。

- 來源：整理自管家／思考夥伴／陪練三分法、多 Agent 系統文獻與 Claude Code 子代理文件，2026 年 9 月。

### 14｜① 對話

1. 研究者先寫下研究問題。
2. 研究者帶著研究問題，與對話 Agent 進行方法討論。
3. 對話 Agent 依討論內容整理方法選項與限制。
4. 研究者依方法選項與限制，選定方法與評估指標。

- 圖檔來源：`slides/story/research-agent-method-1.svg`

### 15｜交辦

- 主訊息：交出成品後，Agent 退出，不留在後續流程。

適用情境：

- 使用 Agent 產品。
- 適合需要一份可檢查的成品，僅做一次，或規則尚未確定而先看初版。
- 例如產出去年的統計表、分布圖與逐事件 CSV。

代價與條件：

- 得到實際檔案，接受或退回的責任線清楚。
- 重做結果不保證一致。
- 每年須重新交辦與檢查，一致性不由 Agent 保證。

流程圖：

- 承辦人流程：準備需求與資料、成品檔案、檢查與驗收、送出／歸檔。
- Agent 位於流程外。承辦人交辦需求與資料，Agent 將成品送入流程。

### 16｜② 交辦

1. 研究者說明檢索範圍與來源要求，形成文獻檢索任務，交給交辦 Agent。
2. 交辦 Agent 依任務查詢文獻資料庫，交出附來源的論文清單。
3. 研究者檢查論文來源與取捨，確認最後採用的論文清單。
4. Agent 交出可檢查的成果後退出，後續是否採用仍由研究者決定。

- 圖檔來源：`slides/story/research-agent-method-2.svg`

### 17｜製作工具

- 主訊息：建置時有 Agent，運行時只有程式。

適用情境：

- 以 Agent 寫程式，通稱 vibe coding。
- 適合規則固定、輸入整齊、按月或按年重新執行。
- 例如篩選事件與計算誤差的腳本，完成後每年重新執行。

代價與條件：

- 相同輸入得到相同輸出，可測試、可重複。
- 規則變動須修改程式，程式無錯不代表結果正確。
- 程式可不逐行閱讀，輸出必須查驗；規則寫進程式之前，人先確認規則本身。

流程圖：

- 每次作業：每次的資料、以工具處理、人確認結果。
- AI 僅產生一次工具。人說明規則與格式，AI 交付工具。

### 18｜③ 製作工具

1. 研究者依方法與評估指標，整理輸入、輸出及測試條件。
2. 研究者將這些條件交給程式建置 Agent。
3. 程式建置 Agent 建立程式碼與測試。
4. Agent 交付工具後退出，不參與後續運行。
5. 計算環境載入程式碼。
6. 計算環境以整理後資料執行程式，產出結果圖表。
7. 研究者查驗結果圖表是否符合方法與評估條件。

- 圖檔來源：`slides/story/research-agent-method-3.svg`

### 19｜結構化判斷

- 主訊息：答案的格式與範圍由程式先定，模型只在裡面選。

適用情境：

- 以 API 接決策模型，程式在固定節點送出問題。
- 模型回傳預先定義的選項、是非、評分或機率，不選工具、不決定下一步。
- 適合選項已知、規則明確、量大且需快速的判斷。

代價與條件：

- 快速、低成本、行為可控。
- 只能回答預先定義的問題。
- 判斷品質須先以已知答案驗證，判斷錯誤不會自行察覺。

流程圖：

- 承辦人流程：逐筆資料、AI 逐筆判斷、人工抽查例外、一致結果與紀錄。
- 人先定義選項與範例。標準寫進流程，AI 只能選擇某個答案。

### 20｜Jev：只做判斷的模型

- 主訊息：不生成文字，只回傳判斷與機率。
- 標記：補充資料。
- 流程：程式送出狀態與問題、Jev 判斷、回傳型別化答案與機率、程式照結果繼續。
- 說明：Jev 位於流程中的判斷節點，取得結果不需先請模型輸出文字。

產品概要：

- TypeSafe AI 九月發布，創辦人是前 OpenAI 研究員。
- 參與過 InstructGPT 與 RLHF，團隊研發約兩年。
- 只回傳三種型別，程式可直接使用。
- `boolean`：`true / false`
- `enum`：`"include" | "exclude" | "review"`
- `score`：`0.93`，代表 0–1 校準機率。

受關注原因與風險：

- 同樣的判斷，速度明顯較快、成本較低。
- 適合工具選擇、相關性過濾、任務驗收這類高頻判斷。
- 快與便宜的倍數多來自官方測試。
- 不會產生格式錯誤，不代表判斷正確，仍須以已知答案驗證。

- 來源：TypeSafe AI 發布說明、LangChain 技術部落格與媒體報導，2026 年 9 月。

### 21｜④ 結構化判斷

1. 研究者先定義論文相關性的類別與範例，寫入固定流程。
2. 固定流程讀取論文題名與摘要，送給結構化判斷模型。
3. 模型只能依預先定義的類別，回傳相關性標記與分數。
4. 模型不選擇工具，也不決定流程的下一步。
5. 研究者抽查標記結果，處理低信心或分類錯誤的例外。

- 圖檔來源：`slides/story/research-agent-method-4.svg`

### 22｜流程指派 Agent

- 主訊息：事件觸發後，一段工作交給 Agent 自行處理，產物交回流程。

適用情境：

- 以 API 接常駐 Agent，自架或託管。
- 適合需查多個來源、處理例外，下一步無法事先寫成固定路徑。
- 例如規模 5 以上事件後自動補列，異常者標記交承辦。

代價與條件：

- 無須人力守候，留下可檢查的檔案、紀錄或通知。
- 運行時有不確定性。
- 須交出資料與操作權限，並設置停止條件。

流程圖：

- 承辦人流程：觸發條件、Agent 取資料處理、Agent 產出結果、人放行／歸檔。
- Agent 依 SOP 連續執行，中途無須人力介入。

### 23｜兩個受關注的 Agent

- 主訊息：一個運行於雲端，一個運行於個人電腦。
- 標記：補充資料。

Grok Bot：雲端代理人，由使用者指派工作。

- xAI 二〇二六年八月推出，與 Cursor 一同發布。
- 每個任務配一台自己的雲端電腦與登入身分。
- 關閉裝置後，任務仍於背景執行。
- 成果直接產生於被操作的工具中，而非對話回覆。
- 等於本簡報的「流程指派 Agent」。
- Beta 需搭配高階付費方案，未提供免費版本。

OpenClaw：個人電腦上的執行代理。

- 開源個人助理，前身 Clawdbot 與 Moltbot。
- 作者 Peter Steinberger，一月改名後於社群快速擴散。
- 運行於個人電腦，串接 Telegram、Slack 等通訊軟體。
- 執行由本機負責，判斷仍由串接的模型處理；可讀寫檔案、執行指令、操作瀏覽器。
- 風險最高的一種，須授予系統層權限。
- 社群分享的技能包易受提示詞注入，機關資料不宜直接介接。

- 來源：xAI 公告與科技媒體報導、OpenClaw 官方與社群文件，二〇二六年。

### 24｜⑤ 流程指派 Agent

1. 研究流程收到新一批整理後資料。
2. 流程建立重跑任務與停止條件，指派給實驗節點 Agent。
3. 實驗節點 Agent 依任務選擇工具，呼叫計算環境。
4. 計算環境以新資料執行程式，產生執行紀錄與異常資訊。
5. 實驗節點 Agent 依執行紀錄，整理與現行方法的比較表。
6. 研究者檢查比較結果與異常，決定接受或退回。

- 圖檔來源：`slides/story/research-agent-method-5.svg`

### 25｜Agent 管理流程

- 主訊息：主 Agent 承接整件工作，於核准點暫停待確認。

適用情境：

- 以 API 接多 Agent 編排。
- 適合跨多個系統、途中有核准與交接、完成後需追蹤。
- 例如從補列、彙整、產圖、撰寫到送審修改，由 Agent 串接。

代價與條件：

- 整件工作有單一承接者，多段操作可追蹤。
- 錯誤可能跨系統擴散。
- 權限、操作紀錄、核准點與回復機制須先建立。

流程圖：

- 人：設定目標與規則、分派與彙整、最終核可。
- Agent：取資料、分析比對、產出報表。

### 26｜⑥ Agent 管理流程

1. 研究者設定研究任務、操作權限與停止條件，交給主 Agent。
2. 主 Agent 建立工作計畫與進度紀錄，並在執行過程中持續更新。
3. 主 Agent 查詢文獻資料庫，整理文獻結果。
4. 主 Agent 依文獻結果形成方法選項，交給研究者選擇。
5. 研究者核准方法後，主 Agent 呼叫計算環境，產出實驗比較表。
6. 主 Agent 依實驗比較表整理結論草稿，交給研究者確認。
7. 研究者確認結論後，主 Agent 撰寫報告草稿，交給審閱者。
8. 審閱者審查報告草稿，寫出審閱意見。
9. 主 Agent 在方法、結論與定稿之前暫停，等待研究者核准。
10. 主 Agent 負責串接與追蹤流程；方法選擇、結論及定稿仍由人負責。

- 圖檔來源：`slides/story/research-agent-method-6.svg`

- 主訊息：干預越深，信任、權限、成本與難度越高；現階段效益最明確的是交辦與製作工具。
