# 用使用者原話當 ghost deck 的底

給 agent 與後續協作者：要把講稿或 draft 排成投影片之前，先做這一步。

## 為什麼

agent 生成的標題句讀起來通順，但不是使用者的話，使用者看了認不出自己的思路，也看不出哪裡不對。改用使用者在討論中說過的原句當每頁標題的底，使用者一看就知道這頁在講什麼、要不要、順序對不對。2026-09-08 第二週投影片改版時確認：生成字的 ghost deck 改了七版仍覺得不是要的感覺，換成原話後才看得懂。

## 怎麼做

1. **抽原話。** 從 session 紀錄逐字抽出使用者本人的訊息：Claude 端在 `~/.claude/projects/<專案目錄>/*.jsonl`，同一工作區可能有多個專案目錄；Codex 端在 `~/.codex/sessions/` 與 `~/.codex/archived_sessions/`。只取 role 為 user、內容為文字的項目，排除工具回傳、系統提示與模擬學員的 subagent 對話。同一則訊息會出現在分叉的多個 session 檔，以前 150 字去重。
2. **只刪贅字，不改用詞。** 語助詞、重複可刪，名詞與句型保留；使用者的口語就照口語放，書面化是下一步的事。
3. **按目前大綱排。** 每一節底下列該節能用的原句，附日期時間，讓使用者可以搬動。同一概念前後說法不同時，兩個都列，標明先後與修正關係。
4. **標出沒有原話的地方。** agent 補的銜接、安排、檢查動作，一律標【無原話】，不用生成句冒充。這些若要留，請使用者用自己的話重講一次。
5. **由使用者排序與刪減之後**，再把留下的原句書面化成標題句，逐頁配證據與口述。

## 判準

- 每頁標題能回溯到一則有日期的使用者訊息，或明確標為無原話。
- 使用者看 ghost deck 時不需要 agent 解釋這頁是什麼意思。
- 原話與現行教案衝突時，先問使用者，不擅自以教案為準。

## 產出位置

- 抽出的完整訊息放 `tmp/`，不進 git。
- 依大綱整理的原話版 ghost deck 放 `drafts/`，例如 `drafts/09-week2-ghost-deck-own-words.md`。
