# Agent 常見用法樣式：別人怎麼用，Agent 具體做了什麼

整理日期：2026-09-19。這張表把外部組織案例與個人助理型 Agent 的社群用法合成**十種用法樣式**，每種用通用動詞寫，並拆開看 Agent 具體做了哪些操作、中間留下什麼、人驗收什麼。目的是讓地震業務翻成通用語意之後能與它配對，見 [[cwa-earthquake-center-work-types]]。

表格不分產品、不點名工具。目前一般的 Agent 產品多半具備聊天入口、工具呼叫、排程與檔案讀寫，這些樣式並非某一產品專屬；來源只在下方註明。

- [[openclaw-how-people-use-it]]：個人助理型 Agent 的官方日常用途與社群展示，每日摘要、研究回存、跨 App 代辦、遠端程式工作、監看提醒。展示個案偏向願意公開分享的使用者。

## 重點

### 十種用法樣式

| 用法樣式 | 通用動詞 | Agent 具體操作 | 中間產物與完成證據 | 人驗收什麼 |
|---|---|---|---|---|
| 例行詢問的答覆 | 解釋、回答 | 查知識庫、依個案回答、收集脈絡；無法解決時摘要並轉交 | 檢索結果、答覆草稿、轉交摘要。證據：對方得到答覆，或已交到承辦人 | 維護正確知識、處理例外與敏感情境、抽查答覆 |
| 跨來源整理成研究底稿 | 整理、分析 | 跨來源檢索、整理相互矛盾的資料、附來源起草、存回筆記 | 來源清單、差異、底稿、筆記條目。證據：每個主張可回到來源 | 定義問題、檢查證據、決定結論 |
| 文件抽成欄位 | 整理、提供資料 | 讀 PDF 或掃描件、抽取欄位、標記非標準條件與原文位置 | 欄位表、例外清單。證據：欄位可對回原文 | 檢查欄位與例外、決定解釋與處置 |
| 警報與事件初篩 | 守視、查核 | 彙集事件紀錄、查相似案例、初步分級、建議調查方向 | 事件卡、分級建議。證據：卡交到值班者手上 | 確認真正風險、處理重大事件、修正分級規則 |
| 跨工具流程推進 | 協調、通報 | 依流程查資料、填系統、建立工作項目、在核准點暫停 | 系統紀錄、工單編號。證據：系統狀態確實改變且可回復 | 訂權限、核准高影響動作、處理失敗 |
| 第一版初稿 | 分析、報導 | 蒐集素材、寫程式或分析、形成可檢查的檔案 | 草稿、程式、測試紀錄。證據：檔案能開、能跑、數值可重算 | 設定標準、執行測試、接受或退回 |
| 定期摘要 | 整理、通報 | 定時讀信箱、行事曆、待辦或資料來源，彙整重點，送出 | 排程紀錄、摘要、送達狀態。證據：定時送達且來源可查 | 收件、抽查、調整範圍 |
| 定期監看與條件提醒 | 守視 | 定期檢查佇列、專案或外部資訊，比對變化，有變化才通知 | 差異摘要、提醒、追蹤紀錄。證據：提醒送達，誤報與漏報可控 | 訂門檻、停止條件、處理提醒 |
| 線上事務代辦 | 提供資料、整理 | 開網頁、填欄位、提交表單、建立任務、更新紀錄、回讀結果 | 操作序列、提交結果或案件編號。證據：系統回傳成功紀錄 | 授權範圍、核對填入內容 |
| 遠端推動程式修改 | 維護系統 | 讀專案、修改程式、執行測試、回報 | patch、測試結果、PR 或部署紀錄。證據：測試通過、變更可審 | 審核變更、決定上線與回退 |

同一件工作可以串幾種樣式：先初篩事件，再推進流程建工單，再定期監看處理進度。銷售材料製作與家庭裝置控制等樣式與公務業務距離較遠，未列入。

### Agent 的動作詞彙

上表的操作可以收成十個動作動詞，供拆自己的工作時使用：**讀取、查找、擷取、比對、計算、草擬、寫程式、執行寫入、通知交接、詢問核准、驗證**。前六個留下可審查的檔案；執行寫入、通知交接改變外部系統或人的工作狀態；詢問核准是把決定交回人；驗證是回讀結果確認真的做了。

### 一句提醒

**工具呼叫成功只證明那一步，不能代表整項業務完成。** 建工單的 API 回傳編號，不代表故障已排除；通知送出，不代表對方已接手；草稿寫好，不代表已核准發布。每種業務動詞各有完成條件，拆工作時要寫得出「完成證據」是什麼。

### 與地震業務工作動詞的對照

配對已做在 [第四週學員講義](../../drafts/06-week4-student-handouts.md) 的動詞對照表上，一列一個工作動詞，附對應樣式、Agent 具體操作、完成證據與人驗收。對應關係：守視對事件初篩與定期監看；查核對事件初篩與研究底稿；發布對跨工具流程與定期摘要；解釋對例行詢問答覆與第一版初稿；提供資料對線上代辦與文件抽欄位；整理保存對文件抽欄位與研究底稿；分析研究對研究底稿與第一版初稿；維護設備對事件初篩與跨工具流程；維護系統對遠端程式修改與定期監看；規劃管考對定期摘要與跨工具流程。對得上只表示有別人做過的做法可參考。

### 缺口常長的樣子

從案例橫向看，Agent 被放進去的位置常是：量超過人能逐件處理的速度；資訊存在但分散、難以追溯；資料格式與系統交界需要人工搬運；工作可拆解卻常卡在初稿或交接。例外少但代價高的地方，必須留有升級、核准、回退與稽核路徑。規則固定、輸入整齊、普通程式能穩定處理的，先評估既有自動化。

## 洞見

- 外部案例較一致的切入點是把人接手前的準備工作做完整：查資料、整理脈絡、標記例外、產出可追溯底稿。這是對案例的綜合推論，不是調查證明的因果結論。
- 把未標示來源的初稿交給審查者，可能只是移轉負擔。看價值時要看交接後的人是否更容易查證與決定。
- 這些樣式是用來配對的，不是用來證明地震測報中心有相同缺口。翻成通用動詞後對得上，只表示有別人做過的做法可以參考；能不能做，還要看資料、權限與驗收人。
