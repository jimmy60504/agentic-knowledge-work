# Domain Storytelling：用演員、工作物件、編號活動畫流程

整理日期：2026-09-22。使用者提出整份第四週演講的流程圖可以改用 domain storytelling 來畫；4-1 第 3 頁「示範：拆解一件工作」在 PPTX 裡已經是這種畫法（演員「研究者」、六個工作物件、六個編號活動）。本筆記記下方法要點與課程用法，來源細節待查核補上。

## 來源

- Stefan Hofer、Henning Schwentner《Domain Storytelling: A Collaborative, Visual, and Agile Way to Build Domain-Driven Software》（Addison-Wesley，2021）；官方網站 domainstorytelling.org 有圖形語言說明與免費的 Egon.io 繪圖工具。以上為記憶所及，連結與版次待查核。

## 重點

- **圖形語言只有幾個元素**：演員（人、群體或系統）、工作物件（文件、資料、對話等被傳遞的東西）、活動（帶編號的箭頭，寫成動詞）、註記、群組。一張圖就是一個具體案例，從 1 號活動讀到最後一號，可以念成一段話：「研究者找文獻，得到論文清單；研究者依論文清單選方法……」。
- **一張圖講一個具體的故事**，不畫所有分支。有分支就多畫一張。這和課程「一段一張、A 到 B」的講法一致。
- **顆粒度可調**：粗顆粒講整件事，細顆粒講一段。4-2 的「一段與整件」正是粗細兩層。
- **原本用途是領域專家與開發者共同畫圖**，在工作坊裡邊問邊畫，圖是討論的紀錄。

## 洞見

- 課程第四週要學員拆自己的工作，domain storytelling 的三個元素剛好對上工作單：演員對上「誰做」與「誰驗收」，工作物件對上「材料、中間產物、完成證據」，編號活動對上「步驟」與「Agent 具體操作」。把 Agent 也畫成一個演員，六種介入方式就是 Agent 這個演員出現在圖上的哪一個編號旁邊、拿到哪些工作物件。
- 圖比表格適合講課，表格比圖適合填寫。講課用圖，工作單用表，兩者的欄位對應可以直接說。
- 用 Egon.io 之類的工具畫，圖可以匯出成檔案，改內容不用重畫；這與「內容改稿、版面改程式」的做法相容。

## 工具：PlantUML DomainStory 函式庫（2026-09-22 實測）

標準 PlantUML 內建，檔頭寫 `!include <DomainStory/domainStory>`；本機 `brew install plantuml`，`slides/story/render.py` 轉 SVG。語法範例檔 `slides/story/syntax-sample.puml`，以下每一項都實際產過圖。

### 語法總覽

**一、元素（先宣告，再寫活動）**

| 類 | 巨集 | 用途 |
|---|---|---|
| 演員 | `Person(別名, 標籤)` | 一個人 |
| 演員 | `Group(別名, 標籤)` | 一群人，例如值班小組 |
| 演員 | `System(別名, 標籤)` | 系統，例如資料庫、計算環境；系統也是演員 |
| 工作物件 | `Document(別名, 標籤)` | 文件、表、清單、程式碼、報告，最常用 |
| 工作物件 | `Folder(別名, 標籤)` | 案卷、資料夾 |
| 工作物件 | `Email(別名, 標籤)` | 信件、通知 |
| 工作物件 | `Call(別名, 標籤)` | 電話 |
| 工作物件 | `Conversation(別名, 標籤)` | 對話、討論 |
| 工作物件 | `Info(別名, 標籤)` | 狀態、資訊 |
| 邊界 | `Boundary(別名, 標籤) { … }` | 把幾個演員框在一個單位裡，例如測報中心 |

每個元素都可以再加 `$note="…"`（註記，前綴 `^ > v <` 指定位置）、`$shape`、`$scale`、`$color`、`$background`。

**二、活動：三種寫法**

1. 基本句，四個參數：`activity(編號, 演員, 動詞, 物件)`，畫成「演員 →動詞→ 物件」，讀作「承辦 撰寫 簽稿」。
2. 串接句，六個參數：`activity(編號, 演員, 動詞, 物件, 動詞或介詞, 下一個物件或演員)`，多畫一段「物件 → 下一個」。第二段的目標可以是物件（「研究者 依 論文清單 選定 主要方法」，物件之間才有連線）或演員（「承辦 撰寫 簽稿 呈給 主管」）。
3. 行內建立物件：物件不先宣告，寫成 `類型: 標籤`，例如 `activity(_, a, 查看, Conversation: 討論紀錄)`。

八個參數（再接介詞與演員）不支援，要交給第三方另寫一句。第七、八參數是箭頭樣式（`-->`、`-up->` 等），不是第三段。

**三、編號：七種寫法**

| 寫法 | 效果 |
|---|---|
| `_` 或 `+` | 自動遞增，最常用 |
| `\|` | 平行活動，與前一個同號 |
| `.` 或空字串 | 不顯示編號，計數不動 |
| `3` | 指定顯示 (3)，計數不動 |
| `=5` | 指定顯示 (5)，並把計數設到 5 |
| `>_`、`<_`、`v_`、`^_` | 在編號前加方向，指定這一段往右、左、下、上畫 |
| `~_` | 逆著預設方向畫 |

**四、版面與樣式**

- `!$Story_Layout = "landscape"`（或 `left-to-right`、`top-to-bottom`、`portrait`），寫在 `!include` 之前。單一演員時圖會成扇形，加入系統與第二個人之後自動橫排；一般 PlantUML 的 `left to right direction` 對這套函式庫無效。
- `Bob ---[hidden]-> Alice` 隱藏箭頭，只用來調位置；`together { … }` 把元素排在一起。
- 樣式變數寫在 `!include` 之前，例如 `!$Person_IconStyle = "stickman"`、`!$Actor_IconColor = "green"`、`!$Step_BackgroundColor`。中文字型用 `skinparam defaultFontName "PingFang TC"`。

### 寫故事給 agent 的規則

- 先寫成一行一句：演員 ＋ 動詞 ＋ 工作物件（＋ 介詞 ＋ 演員或下一個物件）。動詞寫在箭頭上，受詞是箭頭指到的物件，不寫「得到」這種結果詞。
- 系統畫成演員。演員換手的地方就是交接點，也是完成證據與驗收的位置。
- 一張圖一個具體案例，不畫分支；粗的講整件，細的講一段。
- 圖示只有九種，程式碼與圖表都用 `Document`，不夠用時在標籤說清楚。

## 課程用途（候選）

- 4-1 第 3 頁已採用；套回案例頁與 4-2 一段與整件頁可改成同一套畫法，讓流程圖在整份演講裡只有一種語言。
- 工作坊步驟一「攤開整件」可以直接請學員畫一張 domain story，再由 Agent 轉成工作單上區。
- 待決定：是否在講義加一頁圖例，教學員讀這種圖。
