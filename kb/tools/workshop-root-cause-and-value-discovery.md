## 洞見

以下為 agent 的教學分析，非講者原述：

- IMG_8312 補上前一步的工作現況盤點。三張照片可供課程借用的推進關係為：盤點流程／系統／痛點／資料並探索可能 → 分析根本原因與既有機制 → 提出改善方案。這是依照片內容做的串接解讀，並非已取得原工作坊完整教案。
- 對第四週可改寫為盤點一件具體工作的步驟、參與者、工具、輸入資料與交接產物，再找問題。流程圖讓全組看見同一份工作，降低對講師私人脈絡的依賴。
- 「用了哪些系統」與「收了哪些數據」可用來檢查實作條件：資料是否存在、是否能在允許範圍內取得、agent 是否能讀取或操作。這些是 agent 分析延伸，非原投影片逐字內容。
- 使用者確認第五欄為「會有哪些可能」後，可知原投影片已包含可能性探索，不能將此完全視為課程新增。課程可在現況盤點前補上工作目的與受益者，再將「原本想做但做不起的事」作為第五欄的延伸提問，並加入收益、成本、風險與驗證。

- 值得借用提問順序：具體問題 → 原因與上下游影響 → 既有機制為何失效 → AI 可能介入的位置。可以避免直接從工具跳到解方。
- 卡牌可讓工作經驗外部化、供全組比較；確切卡牌規則須另確認。課程可自行設計「一個真實工作事件一張卡」，不冒稱原活動規則。
- 原架構已包含可能性探索，可延伸提問：以前想做、但因持續成本太高而沒做的事。使用者的 agent 知識管理經驗可作候選例子。
- 增補價值與驗證：改善誰的處境、扣除交辦／查核／返工／維護成本後是否值得，以及錯誤如何發現與處理。這些內容在照片中未見，不能推論原工作坊完全沒有。
- 方案比較可包含流程調整、一般數位工具與 agent；沿用既有「人工 → 數位化 → Agent 化」討論，不預設每個問題都需 AI。
- 與 [[moda-public-sector-ai-playbook]] 的場景問題定義素材相連：以具體目標、範圍、可行動性與可觀察結果檢查題目。
