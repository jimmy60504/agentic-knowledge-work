## 洞見

以下為 agent 的教學分析，非講者原述：

- 值得借用提問順序：具體問題 → 原因與上下游影響 → 既有機制為何失效 → AI 可能介入的位置。可以避免直接從工具跳到解方。
- 卡牌可讓工作經驗外部化、供全組比較；確切卡牌規則須另確認。課程可自行設計「一個真實工作事件一張卡」，不冒稱原活動規則。
- 照片所呈現的框架偏向現有痛點，需要另加機會探索：以前想做、但因持續成本太高而沒做的事。使用者的 agent 知識管理經驗可作候選例子。
- 增補價值與驗證：改善誰的處境、扣除交辦／查核／返工／維護成本後是否值得，以及錯誤如何發現與處理。這些內容在照片中未見，不能推論原工作坊完全沒有。
- 方案比較可包含流程調整、一般數位工具與 agent；沿用既有「人工 → 數位化 → Agent 化」討論，不預設每個問題都需 AI。
- 與 [[moda-public-sector-ai-playbook]] 的場景問題定義素材相連：以具體目標、範圍、可行動性與可觀察結果檢查題目。
