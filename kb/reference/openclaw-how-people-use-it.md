## 重點

### 產品在工作流裡的位置

OpenClaw 是可自行運行的助理架構：用 WhatsApp、Telegram、Slack、Discord 等聊天管道交辦，在持續運作的 Gateway 中接上模型、工具、記憶與排程。它能把「人在手機發一句話」接到「另一台電腦讀資料、操作軟體、回報結果」。這是**入口與執行環境**，不是一種新的檔案格式或單一模型能力；接上什麼工具、授予什麼權限，才決定它能做哪些事。

### 為什麼它能做：看不見的中間產物

```text
人在聊天軟體交辦／排程到點／外部事件觸發
  → Gateway 把訊息、工作區脈絡、可用工具與規則交給模型
  → 模型產生下一步：文字草稿、程式碼，或具參數的工具呼叫
  → OpenClaw 按權限讓對應工具執行（程式、API、瀏覽器、訊息等）
  → 工具回傳檔案、狀態、錯誤或確認碼
  → 模型檢查結果，必要時修改中間產物再做一次
  → 交付成品或回報實際完成狀態
```

這是官方 Agent loop 與工具文件的**教學化簡圖**。OpenClaw 提供入口、會話、工具接線、排程與執行回饋；模型產生內容及工具參數；真正寫檔、呼叫 API 或按網頁的是被授權的工具。並不是「龍蝦直接把意念變成投影片」。中間產物可能是一個持久檔案，也可能只是短暫的 JSON 參數、操作序列或 API 請求。

| 人看到的結果 | 可能的中間產物 | 真正完成工作的工具／環境 | 要查的完成證據 |
|---|---|---|---|
| 一份投影片 | 大綱、逐頁稿、Python／JavaScript 腳本、樣式與圖片路徑 | Python 的簡報函式庫、JavaScript 套件或簡報應用 | PPTX 已產生，能開啟、能渲染，內容與版面經檢視；**寫程式只是其中一條路** |
| 寄出一封信 | 收件人、主旨、內文、附件與寄送工具參數 | Email API／郵件應用 | 寄件紀錄或回傳 ID；草稿與寄出分開 |
| 安排行程 | 時區、時間、參與者與事件欄位 | 行事曆 API／網頁操作 | 事件 ID、實際時間、邀請狀態 |
| 填妥線上表單 | 欄位資料、點擊／輸入步驟 | 瀏覽器工具 | 提交成功頁、案件編號或系統紀錄 |
| 每天收到摘要 | 排程設定、資料查詢、摘要草稿、收件管道 | 排程器、資料工具、訊息工具 | 排程執行紀錄、摘要來源、送達狀態 |
| 修好一段程式 | 修改計畫、patch／程式碼、測試命令 | 檔案工具、終端機、測試系統、Git | diff、測試結果、PR 或部署紀錄 |
| 控制智慧設備 | 設備識別、目標狀態、API 參數 | 家庭設備整合／控制 API | 設備回報的實際狀態；發出命令不等於動作完成 |

每種結果都可以由不同路徑達成：例如投影片可能由程式生成，也可能由網頁或簡報軟體操作；填表也可能走 API 而非瀏覽器。**底層工具、套件、帳號、權限與資料來源**是能否做到的條件。Skill 或 `AGENTS.md` 可以教 Agent 步驟與標準，但它們本身不新增操作權限；插件與整合才可能增加可呼叫的工具。

### 與 Agent 產出方式的關係

[[agent-output-modes]] 回答「Agent 最後交付什麼／改變什麼」；OpenClaw 案例顯示的是**如何觸發、如何連工具、如何長期接續**。例如「每天早上寄摘要」同時包含定時觸發、跨來源讀取、內容產出與訊息送達；「用手機修網站」同時包含遠端入口、程式產出、執行測試和回報。這些不是互斥的新產出類別。

一個工作可用五格描述：**觸發方式 → 可取得的資料與工具 → Agent 執行的步驟 → 實際產出／狀態改變 → 人如何驗收**。這比只問「龍蝦能不能做 X」更能看出必要條件。

## 洞見

- OpenClaw 社群最可借鑑的是**工作從聊天入口開始、在背景持續、最後回到人面前**的設計。它讓使用者不用守在同一台電腦前逐步操作；但結果仍需分辨「草稿」「工具已執行」「對方已收到」「人已核准」。
- 對同一個成果，記下**中間產物與執行器**比只記「Agent 做了」更有用：可重跑、查錯、分清人的判斷和程式動作，也能發現根本不需模型的固定步驟。
- 社群案例中的個人行政、遠端寫程式、監看與家庭裝置，對應的資料權限和失敗後果不同。選題時應先看資料與操作邊界，再決定能否形成持續工作流；不能因工具有整合就推定適合接入正式地震測報系統。
- 對地震測報中心的候選類比是：公開資訊的定期彙整、既有文件的研究底稿、測站維運資訊的待查清單、經人工確認後的交接提醒。這些只是**可訪談方向**，不是已查明的缺口，也不是 OpenClaw 已在氣象署使用的證據。

## 課程用途（候選）

- 用來回應「Agent 和龍蝦可以做什麼」：先講通用產出方式，再用 OpenClaw 展示訊息入口、工具連接、背景執行與持續回報如何組成一段工作。
- 工作坊可讓學員選一件低風險的真實工作，填五格流程，分辨「先做一次」與「長期自動跑」所需的資料、權限和驗收；是否進正式教材待使用者決定。
