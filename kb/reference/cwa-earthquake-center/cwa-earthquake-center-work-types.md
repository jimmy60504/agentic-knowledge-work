# 地震業務的工作類型：用動詞而非科別看流程

整理日期：2026-09-19。這是把地震測報中心公開職掌轉成可跨組織比較的**工作語意**，不是新的組織圖，也不代表每項工作只由表中科別執行。範圍限地震；海嘯、火山的獨立作業未列。實際步驟、責任、工具及困難點仍須向同仁確認。

## 重點

### 十種能與別的機關或企業對照的工作

| 工作動詞 | 在地震業務中實際是什麼 | 可見輸入 → 產物 | 相近的外部工作語意 | 官網明列的主要相關科別 |
|---|---|---|---|---|
| **守視、發現** | 全天候注意地震訊號、地震活動與作業狀態；辨認需要處理的事件 | 即時測站訊號、系統狀態 → 事件／異常線索 | 監控中心看告警、資安事件初篩 | 地震監測科；資料鏈由測報技術科支援 |
| **查核、判定** | 核對自動定位與測站資訊，依發布條件處理顯著／小區域有感地震及特殊情況 | 自動解算、波形、震度、作業要點 → 經確認的事件資料與發布決定 | 高時效的專業審核、風險分流 | 地震監測科；技術與資料支援須依實際流程確認 |
| **通報、發布、更新** | 將有感地震報告送到規定對象並公布網站；重大事件加強通報、留下時間和內容 | 經確認的地震資訊、通報名單 → 報告、通知、公布紀錄 | 事故通報、危機資訊發布、版本同步 | 地震監測科；對外聯繫涉及綜合規劃科 |
| **回答、解釋、宣導** | 回應民眾或機構的地震查詢；把地震知識、震度、速報及防護資訊說給不同受眾理解 | 已發布資訊、FAQ、科學說明 → 答覆、百問、宣導品或活動 | 客服、公共溝通、衛教／科普 | 綜合規劃科的為民服務與宣導；專業內容可能需其他科支援 |
| **提供資料、支援使用** | 提供地震資料查詢、申請與展示服務，協助外部使用者取得合適資料 | 地震目錄、測站與地球物理資料、申請需求 → 查詢結果、資料集、使用說明 | 資料服務台、API／資料產品支援 | 地震資料科、測報技術科、地球物理科；正式申購另涉本署服務科 |
| **整理、校對、保存** | 處理、備份與統計地震資料，更新資料庫索引，維持可查與可重用 | 原始／處理後資料、修訂資訊 → 索引、目錄、備份與統計底稿 | 資料治理、檔案管理、品質檢查 | 地震資料科；地球物理資料由地球物理科處理 |
| **分析、報導、研究** | 撰寫每月地震活動分析、季報、年報及特殊事件分析；研究觀測異常與測報技術 | 事件資料、地球物理觀測、歷史資料 → 圖表、解釋、報告、技術方法 | 研究分析、績效報告、事後檢討 | 地震資料科、地球物理科、測報技術科 |
| **維護設備與場站** | 採購、設置、管理、巡檢與修復儀器、站房、傳輸線路及基礎設備 | 測站清冊、狀態、故障與採購需求 → 可用測站、維修／財產紀錄 | 設備資產管理、現場維修 | 地震系統科 |
| **維護、改進資訊系統** | 建置與維運即時資料接收整合、測報、資料展示和資料庫系統，管理資訊安全並研發技術 | 測站資料、系統事件、使用需求 → 穩定服務、版本、技術改善 | IT 服務維運、資料工程、產品改版 | 測報技術科；地震監測科及地震資料科也各有業務系統維運 |
| **規劃、協調、管考** | 提報計畫和預算、管理委辦與合作、召開會議、聯繫防救災單位、辦理行政規則與檔案 | 政策目標、合作需求、執行成果 → 計畫、契約／會議紀錄、進度與考核資料 | 專案管理、跨單位協作、治理 | 綜合規劃科；各科提供專業成果 |

「對民眾解釋」並非只有客服電話：可能是查詢答覆、報告文字、地震百問、宣導活動；其時效、可用資料及核准方式不同。「管理」也至少分為**實體設備、資訊系統、資料、計畫與合作**四種，每種的責任與驗收標準不同。這些區分是依公開職掌作出的功能歸納，不代表已確認中心內部 SOP。

### 把同一事件畫成可討論的工作鏈

```text
測站訊號與系統狀態
  → 守視、發現
  → 自動解算與人工查核
  → 通報、發布、更新
  → 民眾／機構查詢與解釋
  → 資料整理、保存、統計
  → 月報／季報／年報與研究

設備、資訊系統維運支撐整條鏈；計畫、合作與管考提供資源及規則。
```

這只是**依公開資料重組的概念圖**。並非所有事件都走完每一格，研究和定期報告也可能橫跨多次事件；圖中「人工查核」與對外發布責任不能從流程圖轉交給 Agent。

## 洞見

- 與 [[external-agent-business-use-cases]] 對照時，先比較**工作機制**，例如「大量訊號分流」對照資安警報、「依已發布資料回答」對照客服、「維修紀錄串接」對照 IT 工單；不能因名稱相似就推定已有缺口。
- 最值得分開問的是**時效與風險**：秒級預警與有感地震正式發布，和月報、民眾答詢、設備維修的容錯與審核空間不同。即時測報核心需以既有專業系統與人員責任為前提，Agent 適用性須另行驗證。
- 找缺口時可在每一類追問四件事：最常見的輸入是什麼？產物交給誰？例外如何升級？查核與修訂紀錄在哪裡？這些問題比直接問「哪個科需要 Agent」更容易得到可觀察的流程。

## 課程用途（候選）

- 當作六科職掌與外部 Agent 案例之間的**翻譯表**，供學員先指出自己實際做的工作類型，再描述流程和阻力。
- 若做訪談或工作坊，可請同仁挑最近一次具體事件，填「觸發 → 查了什麼 → 做了什麼 → 交給誰 → 怎麼驗收 → 例外」；本表僅供選類，缺口須從真實例子確認。
