# 設計邏輯的容器：theme 管不准變的，skill 管該怎麼變的

延續 [[pptx-theme-design-token]] 的討論。

## 問題

雜誌式構圖（編輯網格、滿版圖、不對稱分割）是「構圖回應內容」，內容形狀無限多，
母片的版型枚舉不完 → 光靠母片做不出被設計過的簡報 → 需要 agent 逐頁客製。
但 agent 自由發揮 = 每頁像不同人做的。

## 分層解法

Web 的 design system 有三層：token（值）→ component（元件）→ usage guideline（規則）。
簡報世界的對應：

| 層 | 簡報側 | 管什麼 |
|---|---|---|
| token | theme（theme1.xml）＋母片 | 不准變的：色彩、字型、基本版型 |
| 規則層 | **skill（md 陳述設計邏輯）** | 該怎麼變的：構圖如何回應內容 |

規則層在 pptx 檔案格式裡沒有容身之處（一直活在設計師腦中／品牌手冊），
skill 剛好是它的容器：設計邏輯本來就是文字可陳述的知識。

規則例：一頁一訊息、標題最多兩行、數字用展示級字重、留白 ≥40%、圖表只用 accent1/2。

## 用 agent 抽 design system（CODE 循環套在設計知識上）

1. 收集：公認好看的 deck 數份，或品牌手冊 PDF。
2. 蒸餾：agent 逆向描述每頁構圖規則 → 抽共通原則。
3. 人審：哪些是原則、哪些是巧合（失真判斷，同讀 paper）。
4. 落成 skill：邏輯陳述＋可執行規範＋好壞範例。
5. 迭代：用 skill 產新簡報 → 對照範例 → 修 skill。
