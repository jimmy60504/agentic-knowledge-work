# 用銷售框架理解學員需求與持續參與

整理日期：2026-09-05。使用者希望先理解銷售流程框架，再討論工作流課程的方向與細節。使用者觀察：多數學員只是來看看，還沒覺得跟自己工作有關。以下課程建議由 agent 提出，尚未採用；具體任務的需求分布仍待課堂確認。

## 來源

- [Huthwaite：SPIN Selling questions](https://www.huthwaiteinternational.com/blog/spin-selling-questions)：現況、問題、影響、解決後的價值。
- [Christensen Institute：Jobs to Be Done](https://www.christenseninstitute.org/theory/jobs-to-be-done/)：人在特定情境下想取得的進展，包含功能、情緒與社會面向。
- [HubSpot：AIDA](https://blog.hubspot.com/marketing/aida-model)：注意、興趣、渴望、行動。
- 專案脈絡：`index.qmd`、`drafts/02-week2-presentation-lesson-plan.md`、`工作紀錄.md`，以及 [[what-makes-civil-servants-want-to-learn-ai]]。

## 重點

- JTBD 用來定義學員期待的工作改善；SPIN 用來問出具體需求；AIDA 用來安排開場與參與邀請。三者用途不同，不能把 AIDA 當需求調查。
- 課程的「成交」可理解為學員願意投入下一段注意力、動手試一次，再決定是否繼續參與。這是教學應用的類比，不是框架已證實能提升本課留存的結論。
- agent 建議的流程：辨認情境 → 找出卡點與影響 → 說明可取得的成果 → 示範證據 → 處理實際阻礙 → 課堂小試 → 依反應調整後續內容。

## 洞見

- 現有課程有明確的方法骨架；目前候選開場同時談政策、導入阻礙、工具差異與主管管理，個人工作上的好處可能出現太晚。
- 學員可能想少做重複修改、交付前更有把握、下次不必重講背景；這些是假設，應在課堂用最近一次實際工作驗證。
- 主辦者的導入與管理需求，和學員當天願意投入注意力的理由可能不同。「從私下用到公開用」是否適合當主軸，取決於實際阻礙，不能先當成全班共同需求。
- 「判斷力」可由具體修改示範帶出：大家指出一份 AI 初稿的缺點，修好，再把標準存下來供下一次使用。

## 課程用途（候選）

- 依使用者觀察，開場優先建立工作關聯：先展示熟悉任務的前後差異，再從學員的反應追問需求。先讓人看見可做什麼，避免一開始要求沒有使用經驗的人列出 AI 需求。
- 開場用一份熟悉的公開或模擬素材，展示初稿、人工判斷與修改成果；讓學員選擇最想改善的環節。
- 現場需求對話：最近一次做什麼、哪一步反覆重做、造成什麼影響、改好後有什麼價值。觀察具體案例與嘗試行為，不只收「有興趣」的票數。
- 每段採用「工作卡點 → 示範 → 小試 → 留下成果」；當場完成，不增加回家作業。
- 第二週候選入口：把現有資料整理成可修改的簡報初稿，練習修正重點與結構；第四週候選入口：資料很多時，找出有來源支持、自己也能說明的主張。
- 政策與環境限制在相關疑慮出現時回答；在學員使用資料前交代必要操作邊界。專案資料夾與紀錄不能單獨證明使用符合機關規定。
- 第五週後選題依需求常見程度、實際困擾、課堂可完成性與可遷移技巧綜合判斷，不預先排滿。
