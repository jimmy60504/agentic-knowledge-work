### 補充：五個基礎問題

補充照片的五欄可完整辨讀：

1. 資料在哪裡？
2. 資料結構清楚嗎？
3. 權限怎麼管理？
4. 流程怎麼進行？
5. 結果怎麼留下？

它將資料可取得性、結構與定義、權限、流程進度，以及結果與判斷紀錄放在同一張圖。原標題強調企業的基礎條件；本筆記只保留這個檢查角度，不將標題視為適用所有企業的實證結論。

### 按主題重組的來源觀點

1. **先決定何謂有價值，再選改變方向。** 8397 以冰山區分事件、反覆模式、組織結構與心智模型；8398 將識別價值與溝通翻譯列為重要能力。
2. **收益具有不同形式。** 8386 區分降低既有工作成本、強化人的能力、改變工作模式；8372 將用途連到交付、成本、品質、風險與知識等成果。
3. **完成工作需要連接既有工具與領域知識。** 8389 的訂單流程、8365 的研發模擬流程、8373 的開發工具鏈都呈現多環節協作；沒有證明更多 agent 必然更好。
4. **部署後還有長期工作。** 8370、8360 描述權限、資料、監控、版本與運行管理；8374 主張先驗證，再實施與擴展。
5. **參與者的期待會影響導入。** 8335 提醒關注主管、員工與供應者的投入和利益；8398 提出跨部門翻譯與協調能力。
6. **一次工作可以為下一次留下能力。** 8356 將既有知識使用、新知分類、人類審查與創新實驗連成知識演進的方向。

## 洞見

以下為 agent 依照片與本次課程討論提出的延伸，不是講者原句，也尚未由使用者定案。

### 價值可以分成當次成果與後續累積

當次價值是少花時間、改善品質、縮短回應、做出更好的決定；累積價值則是留下可再用的資料、方法、標準與失敗條件。維護與再利用的成本若降低，原本無力持續整理的個人或團隊才可能建立這些資產。

這能連到使用者最有感的知識管理：agent 不只在當下回答，也能協助找舊資料、分類、回存決策和更新規則。對課程可用的提問是：「做完這件事，下次能少重新摸索什麼？」但保存不等於資產化；還須可找回、有依據、適用範圍清楚、有人修正過時內容。新奇或分類不進去的資訊只是值得調查，不能直接認定為創新。

### 三種收益可供選題，不必當成人人必走的階梯

借用 8386 的分類，可問：能否把既有工作做得更省、把人的分析與判斷做得更好、讓原本做不起的工作變得可行？原圖的嚴格先後順序在照片中沒有證據支持。個人知識管理也可能同時包含自動整理與能力強化；agent 的使用不必等到所謂第三階才開始。

### 痛點的位置與原因可能不同

例：報告反覆重寫可能源於需求變動、決策權不清、版本與資料流動不良。加速初稿能改善一部分，但不能自動解決決策制度。冰山圖適合用來追問同一問題反覆出現的條件；本次工作坊不必要求完成整個組織診斷。

### 價值會受交接與驗收影響

由三張工具流程圖可延伸：一段工作的輸出要能被下一段使用，才可能改善整體成果。工作坊應關注每步的輸入、輸出、檢查、例外與負責人。工具鏈圖是設計線索，不是已驗證的效益；不能因標上 agent 就認定價格計算、模擬或每個固定步驟都需要 LLM。

### 收益與負擔可能落在不同人身上

產出者變快，可能使審查者負擔增加。省時、成本與風險須沿流程看，並追問誰需要改變做法、誰承擔出錯後果。對個人可行的工作方式，不一定能直接擴大到跨部門。

### 治理是成果持續可用的成本

企業架構圖提醒模型之外還有資料、權限、測試、記錄、監控、維護。課程只需先教自己任務範圍內如何檢查與處理例外，不把大型企業平台當作入門門檻。小範圍驗證可同時記錄產出品質、人力時間、返工次數、工具費用及失敗情況。

### 五個基礎問題把可行性與知識累積接在一起

補充照片可以接在工作坊提出候選用途之後，檢查需要的資料在哪裡、欄位與詞義是否一致、誰能讀寫或核准、流程目前到哪裡，以及結果和判斷依據存在哪裡。「誰能讀寫或核准」是課程延伸提問，不是被遮擋細字的轉錄。

前四題幫助釐清 agent 執行任務的條件，第五題也連到後續查核、交接與知識再利用。這支持使用者的知識管理經驗：保存的不只有成品，還包括做過什麼、根據什麼判斷、下一次可以如何接續。這些問題可隨小範圍實作逐步釐清，不必等到全組織資料整理完才開始。

### 可以用來討論的整體敘事

從目的與受益者出發，理解工作現況和反覆問題，探索節省成本、強化能力與新增工作三種可能；設計人、agent 和工具的分工，驗證總收益與新增成本風險，再把有效方法與失敗條件保存，供下一次使用。

此敘事是依多份投影片重組的課程候選，不能引用為單一講者的原始模型。與 [[workshop-root-cause-and-value-discovery]] 的流程／系統／痛點／數據／可能五欄互補，也可連到 [[moda-public-sector-ai-playbook]] 的具體問題定義。
